Cacti MCP — це плагін для Cacti, який дозволяє ШІ-клієнтам читати ваші дані Cacti через іменовані операції з фільтрацією за правами доступу, що називаються можливостями (abilities). Він надає їх двома способами безпосередньо із самого плагіна: через кінцеву точку MCP (`mcp.php`, Streamable HTTP) та HTTP API у стилі AIP (`api.php`). Cacti залишається відповідальним за авторизацію та виконання. Клієнт ніколи не робить прямих запитів до бази даних; він може викликати лише ту можливість, яку відкрив адміністратор і яку дозволяють права доступу (realms) Cacti власника токена.

Автори плагінів можуть реєструвати власні можливості лише для читання через хук `abilities_register`, і вони відображаються для клієнтів MCP як інструменти без написання протокольного коду.

**Статус: попередній випуск, версія 0.1.0.** Позначених тегом випусків ще немає.

Доступно вже зараз:

- Дев'ять вбудованих можливостей лише для читання, що охоплюють версії системи, пристрої, сайти, опитувачі (pollers), дерева графів, графіки, джерела даних та обмежений відредагований (redacted) хвіст журналу Cacti.
- Персональні токени доступу (`cmcp_pat_...`) як єдині облікові дані.
- Консоль Management > MCP: відкриття або приховування можливостей, створення та відкликання токенів, перегляд журналу аудиту.
- Management > My MCP Tokens: користувачі керують власними токенами, переглядають свою активність і бачать, якими інструментами можуть користуватися їхні токени.
- MCP поверх Streamable HTTP, версії протоколу `2026-07-28` та `2025-11-25`, лише інструменти.

Ще не доступно:

- Вхід через OAuth 2.1. Розміщені на зовнішніх серверах конектори, які не можуть надсилати персональний токен (наприклад, власні конектори ChatGPT та claude.ai), не зможуть підключитися, доки його не буде реалізовано. Це заплановано як План 2; цей план ще не написано.
- Можливості запису. Можна реєструвати лише можливості лише для читання.

Опис архітектури наведено у [специфікації проєктування кінцевої точки](../../superpowers/specs/2026-11-19-mcp-endpoint-design.md), а послідовність розробки — у [docs/plan.md](../../plan.md).

## Вбудовані можливості

| ID | Категорія | Аргументи | Необхідне право доступу (realm) Cacti |
| --- | --- | --- | --- |
| `cacti-get-system-info` | `system` | немає | 15 |
| `cacti-list-devices` | `inventory` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-get-device` | `inventory` | обов'язковий `name`, наприклад `devices/12` | 3 |
| `cacti-list-sites` | `inventory` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-list-pollers` | `system` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 15 |
| `cacti-list-trees` | `inventory` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 7 або 4 |
| `cacti-list-graphs` | `inventory` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 7 або 5 |
| `cacti-list-data-sources` | `inventory` | необов'язкові `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-get-clog` | `system` | необов'язкові `lines` (від 1 до 200, типово 50), `severity`, `search` | 19 або 18 |

Для кожного виклику також потрібне право доступу **MCP and Abilities API** для власника токена, область `abilities:read` (її має кожен персональний токен) і відкрита можливість. На вкладці Abilities у консолі показано основне право доступу, необхідне для кожної вбудованої можливості.

Усі шість можливостей `cacti-list-*` повертають сторінки розміром до 100 елементів (типово 50) і `nextPageToken`. Токен сторінки дійсний лише для тих самих значень `filter` і `orderBy`. `filter` це вираз AIP-160 із порівнянь (`=`, `!=`, `<`, `<=`, `>`, `>=`), об'єднаних через `AND`, наприклад `state = "DOWN" AND disabled = false`. `orderBy` приймає розділений комами список полів, придатних для сортування, після кожного з яких за бажанням можна вказати `asc` або `desc`.

| Можливість | Поля фільтрації | Поля сортування |
| --- | --- | --- |
| `cacti-list-devices` | `displayName`, `hostname`, `disabled`, `site`, `poller`, `deviceTemplate`, `externalId`, `state` (`UNKNOWN`, `DOWN`, `RECOVERING`, `UP`, `ERROR`) | `displayName`, `hostname`, `name` |
| `cacti-list-sites` | `displayName`, `city`, `state`, `country`, `timezone`, `alternateId` | `displayName`, `city`, `state`, `country`, `name` |
| `cacti-list-pollers` | `displayName`, `hostname`, `disabled`, `state` (`NEW`, `RUNNING`, `IDLE`, `UNKNOWN`, `DISABLED`, `RECOVERING`, `ERROR`) | `displayName`, `hostname`, `name` |
| `cacti-list-trees` | `displayName`, `enabled` | `displayName`, `name` |
| `cacti-list-graphs` | `title`, `device`, `graphTemplate`, `templateName` | `title`, `templateName`, `name` |
| `cacti-list-data-sources` | `displayName`, `device`, `dataTemplate`, `active` | `displayName`, `name` |

Обмеження області прав доступу та виключення секретних даних:

- `cacti-list-devices` і `cacti-get-device` виконують запити через функцію Cacti `get_allowed_devices()` та виключають рядки спільноти SNMP, парольні фрази й інші облікові дані.
- `cacti-list-trees` виконує запити через `get_allowed_trees()` (і фільтрує через `is_tree_allowed()`, коли вона доступна); `cacti-list-graphs` виконує запити через `get_allowed_graphs()` (і фільтрує через `is_graph_allowed()`, коли вона доступна).
- `cacti-list-data-sources` обмежує рядки пристроями, дозволеними викликачу через `get_allowed_devices()` (і `is_device_allowed()`, коли вона доступна), та повертає лише метадані без запитів до `data_input_data` і без розкриття секретних вхідних значень.
- `cacti-list-pollers` виключає облікові дані бази даних (`dbpass`, `dbuser`) та стовпці ключів і сертифікатів TLS (`dbsslkey`, `dbsslcert`, `dbsslca`).
- `cacti-get-clog` зчитує до останнього 1 МіБ налаштованого журналу Cacti (обрізаючи окремі рядки довжиною понад 2048 байтів), фільтрує за `severity` (`ALL`, `DEBUG`, `INFO`, `NOTICE`, `WARNING`, `ERROR`, `CRITICAL`, `ALERT`, `EMERGENCY`, `FATAL`, `STATS`, `POLLER`, `SYSTEM`; типово `ALL`) та регістронезалежним `search` (до 256 символів), і повертає `lines`, `count` та `truncated`. Кожен рядок очищається від персональних токенів, заголовків bearer/basic, паролів, секретів, рядків спільноти SNMP, ключів, `dbpass`, `dbsslkey` та облікових даних користувача в URL до виконання фільтрів `severity` і `search`, щоб `search` не міг слугувати оракулом для виявлення секретів. Очищення застосовує безпечну відмову з підстановкою `[redacted]`, а нечитабельний журнал повертає `FAILED_PRECONDITION` (`LOG_UNAVAILABLE`).

## Встановлення

Потрібні Cacti 1.2.31 або новішої версії, PHP 8.2 або новішої версії та основний опитувач (poller). Автентифікація Cacti має бути увімкнена; якщо вона вимкнена, плагін відмовляється виконувати автентифікацію.

Каталог плагіна повинен мати назву `mcp`, а не `plugin_mcp`. Коротке ім'я (slug) плагіна, назви прав доступу, домен перекладу та URL-адреси використовують `mcp`.

З копії вихідного коду:

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_mcp.git mcp
```

Доки немає випусків із тегами, ви можете натомість завантажити артефакт `mcp-plugin` з успішного [запуску CI](https://github.com/somethingwithproof/plugin_mcp/actions/workflows/ci.yml). Він містить `mcp.tar.gz` та `SHA256SUMS`. Перевірте контрольну суму, а потім розпакуйте `mcp.tar.gz` у каталог Cacti `plugins/`, щоб у результаті отримати `plugins/mcp/`. Автоматичні архіви вихідного коду GitHub використовують іншу назву каталогу верхнього рівня. В архіві відсутні `docs/` (включно зі знімками екрана нижче), `tests/` та `.github/`, тому посилання на `docs/` у README працюють на GitHub, але не у встановленій копії.

Далі:

1. У Plugin Management встановіть і увімкніть **Cacti MCP**. Адміністратор, який виконує встановлення, автоматично отримує право доступу **MCP Administration**.
2. У розділі Settings > MCP установіть для **Public Cacti URL** адресу, якою користуються клієнти, наприклад `https://cacti.example.com/cacti`. Потрібен HTTPS, за винятком `localhost`, `127.0.0.1` та `[::1]`. Доки це значення не встановлено, `mcp.php` відповідає кодом HTTP 400 з помилкою JSON-RPC, поле `data` якої містить `FAILED_PRECONDITION` та `PUBLIC_URL_REQUIRED`. `api.php` це налаштування не зчитує.

   ![Розділ Settings > MCP із полем Public Cacti URL](../../images/settings-public-url.png)

3. Надайте право доступу **MCP and Abilities API** кожному користувачеві, який володітиме токеном. Жоден користувач не отримує його автоматично.
4. Переконайтеся, що вебсервер передає заголовок `Authorization` та інформацію про шлях (path info) до PHP (див. нижче).
5. Відкрийте Management > MCP та відкрийте ті можливості, які мають бачити клієнти.

**Оновлення зі збірки для розробки.** Плагін перебуває на стадії попереднього випуску, і його таблиці змінювалися під час розробки без міграцій. Якщо ви встановлювали ранішу збірку, видаліть плагін і встановіть його знову. Повторне встановлення зберігає таблиці, які вже існують, тому спершу видаліть старі таблиці `plugin_mcp_token`, `plugin_mcp_audit` та `plugin_mcp_ability` (а також відповідні таблиці зі збірок, створених до перейменування). Зробіть їхню резервну копію, якщо вам потрібна історія; токени з тих збірок відкликаються під час видалення плагіна і не переносяться.

### Вебсервер

Конфігурації Apache, які видаляють заголовок `Authorization` перед передачею до PHP, потребують додавання цього рядка до відповідного віртуального хосту або каталогу з подальшим перезавантаженням конфігурації:

```apache
SetEnvIf Authorization "(.+)" HTTP_AUTHORIZATION=$1
```

Apache із `mod_php` обслуговував маршрути `api.php` без додаткового налаштування шляхів.

Маршрути `api.php` розташовані у частині шляху після імені скрипту (`/plugins/mcp/api.php/v1/abilities`), тому nginx має зіставляти URI, де після `.php` іде продовження шляху, відокремлювати path info та передавати його до PHP. Блок `location ~ \.php$` ніколи не відповідає таким URL-адресам; nginx відповідає власною HTML-сторінкою 404. Наведений нижче шаблон `location` і два рядки для path-info були перевірені з PHP-FPM; решта рядків є стандартним шаблоном:

```nginx
location ~ \.php(/|$) {
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php-fpm.sock;   # your PHP-FPM socket or host:port
}
```

Відкоригуйте рядки `include` та `fastcgi_pass` відповідно до блоку, який уже обслуговує Cacti. Не додавайте `try_files $fastcgi_script_name =404;` до цього блоку: це очищає `$fastcgi_path_info`, і тоді `api.php` відповідає помилкою 404 `UNKNOWN_PATH`. Якщо вашій конфігурації потрібен `try_files`, спершу збережіть значення за допомогою `set $path_info $fastcgi_path_info;` і передайте `fastcgi_param PATH_INFO $path_info;`.

`mcp.php` не має маршрутів у шляху й не потребує цих налаштувань.

## Консоль

Management > MCP містить три вкладки. Вам потрібне право доступу **MCP Administration**. Наведені тут і нижче знімки екрана зроблено в збірці Cacti для розробки з тестовими даними.

- **Abilities** містить список усіх зареєстрованих можливостей із зазначенням плагіна, категорії, необхідного права доступу та стану відкритості. Позначте рядки та виберіть Expose або Hide; перед застосуванням змін з'явиться підтвердження. Вбудовані можливості `cacti-*` відкриті за замовчуванням. Можливості інших плагінів спочатку приховані, тому встановлення плагіна ніколи нічого не публікує, доки адміністратор сам не вирішить цього зробити. Відкритість лише звужує доступ: користувачеві все одно потрібне відповідне право доступу для можливості.

  ![Вкладка Abilities зі списком вбудованих можливостей, їхніх прав доступу та стану відкритості](../../images/console-abilities.png)
- **Tokens** містить список токенів із власником, автором, часом створення, терміном дії, останнім використанням і станом (Active, Expired, Revoked). Позначте рядки та виберіть Revoke, щоб відкликати їх. Відкликані токени не можна використати повторно. Create Token створює новий токен.

  ![Вкладка Tokens зі списком токенів, де вказано власника, термін дії, останнє використання та стан, над формою Create Token](../../images/console-tokens.png)
- **Audit** містить записи аудиту від найновіших до найстаріших і дозволяє фільтрувати за користувачем, можливістю та результатом.

  ![Вкладка Audit зі списком викликів із користувачем, токеном, можливістю та результатом, а також фільтрами](../../images/console-audit.png)

## Токени

Персональний токен читає дані Cacti від імені свого власника. Він має формат `cmcp_pat_` із подальшими 64 шістнадцятковими символами в нижньому регістрі та несе єдину область `abilities:read`. Те, що він може бачити, визначається правами доступу (realms) Cacti та дозволами на пристрої його власника, а не самим токеном. Власником має бути увімкнений користувач, який має право доступу **MCP and Abilities API**.

Токени завжди створюються для конкретного користувача, мають термін дії та можуть бути відкликані:

- **Консоль.** Management > MCP > Tokens > Create Token. Термін дії становить від 1 до 365 днів і за замовчуванням дорівнює 90. Токен генерується сервером і показується один раз на сторінці відповіді, тому негайно скопіюйте його до свого менеджера секретів. Ви можете створити токен для себе. Для створення токена для іншого користувача також потрібне право доступу Users/Groups, оскільки токен читає дані Cacti від імені того користувача.
- **My MCP Tokens.** Будь-який користувач із правом доступу MCP and Abilities API може керувати власними токенами; див. нижче.
- **Командний рядок.** `tokens.php` запускається лише з CLI під обліковим записом ОС, який має права на адміністрування Cacti. Він приймає токен зі змінної середовища, щоб значення ніколи не з'являлося в командному рядку чи списку процесів. Термін дії становить від 1 до 365 днів і за замовчуванням дорівнює 30. Створення та відкликання токена через CLI фіксується в журналі аудиту так само, як і в консолі, із зазначенням власника токена як виконавця, оскільки CLI не має користувача Cacti, тож запис аудиту не позначає дію як виконану з CLI. `--list` виводить усі токени у форматі JSON (ID, власник, області, часові мітки, прапорець відкликання) і ніколи не виводить значення токена; `--help` показує довідку щодо використання.

  ```console
  export CACTI_MCP_TOKEN="$(printf 'cmcp_pat_%s\n' "$(openssl rand -hex 32)")"
  # Store this value in your secret manager before you end this shell session.
  php plugins/mcp/tokens.php --create=USERNAME --days=30
  php plugins/mcp/tokens.php --list
  php plugins/mcp/tokens.php --revoke=ID
  ```

Токени не можна створювати для гостьового облікового запису, для вимкнених користувачів або для користувачів без права доступу **MCP and Abilities API** ані з консолі, ані з командного рядка, ані через My MCP Tokens. Cacti зберігає налаштування гостя як ім'я користувача або як ID користувача, і плагін розпізнає обидва варіанти. Токен, власник якого стає гостьовим обліковим записом, припиняє працювати під час наступного запиту.

### Мої токени MCP

Сторінка Management > My MCP Tokens (`plugins/mcp/mcp_tokens.php`) не потребує права адміністрування: вона охоплюється правом доступу **MCP and Abilities API**, і пункт меню з'являється лише для користувачів, які мають це право. Сторінка завжди працює для користувача, який увійшов у систему. Меню Cacti є частиною консолі, тому користувач без доступу до консолі відкриває сторінку за її адресою.

![Вкладка My Tokens зі списком токенів поточного користувача та формою створення](../../images/my-tokens.png)

- **Tokens** відображає ваші токени, створює новий (від 1 до 365 днів, за замовчуванням 90, показується один раз у відповіді) і відкликає ваші власні токени. Ви не можете переглядати або відкликати чужі токени.
- **Activity** відображає виконані вами дії від найновіших до найстаріших: виклики, зроблені з вашими токенами, та зміни токенів, які ви виконали.
- **Available Tools** відображає можливості, які ваш токен може використовувати прямо зараз, із ID, назвою та описом кожної можливості. Список відповідає вашим дозволам у Cacti та параметрам відкритості, обраним адміністратором.

  ![Список Available Tools із відображенням ID, назви та опису кожної можливості](../../images/my-tools.png)

Встановлення, виконане до появи цієї сторінки, містить перелік файлів права доступу без `mcp_tokens.php`. Цей перелік реєструється під час встановлення; він не оновлюється під час увімкнення або вимкнення плагіна. Видаліть і встановіть плагін знову, а потім повторно надайте права доступу, оскільки Cacti видаляє надані права доступу під час видалення плагіна.

У базі даних зберігається лише SHA-256 геш токена, тому втрачений токен неможливо відновити; відкличте його та створіть інший. Ротація виконується так само: створіть новий токен, перемкніть клієнт, а потім відкличте старий. Прострочений токен, відкликаний токен, вимкнений власник або втрачене право доступу призведуть до відмови під час наступного запиту. Токени приймаються лише в заголовку `Authorization: Bearer`; токен у рядку запиту або в тілі запиту не приймається.

## Підключення клієнта

Використовуйте кінцеву точку MCP `https://cacti.example.com/cacti/plugins/mcp/mcp.php`, передаючи токен у заголовку `Authorization: Bearer`. Зберігайте токен у змінній середовища або менеджері секретів і посилайтеся на нього з конфігурації клієнта, замість того щоб записувати його значення у файл.

### Claude Code

Додайте кінцеву точку до файлу `.mcp.json` проєкту з посиланням на токен за назвою. Claude Code розгортає `${VAR}` у `url` та `headers`, тож файл не містить секрету й безпечний для коміту. Експортуйте `CACTI_MCP_TOKEN` у середовищі, з якого запускається Claude Code.

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

Ви також можете додати її з командного рядка:

```console
claude mcp add --transport http cacti https://cacti.example.com/cacti/plugins/mcp/mcp.php \
  --header "Authorization: Bearer $CACTI_MCP_TOKEN"
```

За використання подвійних лапок оболонка спочатку розгортає `$CACTI_MCP_TOKEN`, тому значення токена записується у файл конфігурації для вибраної області `--scope` (`local`, `user` або `project`; типово `local`). Не використовуйте таку форму з `--scope project` і не додавайте цей файл до системи контролю версій. Надавайте перевагу посиланню у `.mcp.json`, наведеному вище. Claude Code зчитує деякі змінні облікових даних (наприклад, `ANTHROPIC_AUTH_TOKEN`) як порожні у віддалених `url` і `headers`; `CACTI_MCP_TOKEN` до них не належить. Джерело: [Документація Claude Code MCP](https://code.claude.com/docs/en/mcp).

### GitHub Copilot у VS Code

Використовуйте файл `.mcp.json` у корені робочої області (або файл користувача `~/.copilot/mcp-config.json`). Ці нативні для Copilot файли використовують об'єкт верхнього рівня `mcpServers` і посилання на змінні середовища виду `${NAME}` у значеннях заголовків:

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

Експортуйте `CACTI_MCP_TOKEN` у середовищі, з якого запускається VS Code. Нативні файли Copilot не підтримують запити `inputs`. Майстер налаштування VS Code відхиляє значення `${...}`, тому додайте заголовок `Authorization`, відредагувавши файл вручну, а не через майстер. Майстер налаштування пропонує файл у корені робочої області лише тоді, коли ввімкнено експериментальний параметр `chat.mcp.workspaceRootConfig.enabled`. Див. [Довідник із конфігурації MCP у VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

**Застарілий формат: `.vscode/mcp.json`.** VS Code зазначає, що нові конфігурації Copilot не повинні використовувати `.vscode/mcp.json` або `mcp.json` профілю; вони належать до застарілої локальної обв'язки (Local harness), яку буде видалено у лютому 2027 року. Якщо ви досі його використовуєте, формат, керований редактором, приймає ключ верхнього рівня `servers` і може запитувати токен:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "cacti-mcp-token",
      "description": "Cacti MCP token",
      "password": true
    }
  ],
  "servers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${input:cacti-mcp-token}"
      }
    }
  }
}
```

### Клієнти, що підтримують лише stdio

[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) — це необов'язковий адаптер, що працює як локальний stdio MCP-сервер і викликає HTTP API плагіна. Використовуйте його для клієнта, який не може підключатися до віддаленого HTTP-сервера. Йому потрібен той самий персональний токен, і він взаємодіє з `api.php`.

### Поведінка MCP

Кінцева точка обслуговує лише інструменти: кожна відкрита й дозволена можливість є інструментом із назвою, що відповідає її ID, зі своїми вхідною та вихідною схемами й анотаціями «лише для читання» (`openWorldHint` має значення `false`). Вона обробляє `initialize`, `server/discover`, `ping`, `tools/list` та `tools/call`. Вона не зберігає сесію, не надсилає `Mcp-Session-Id` (і ігнорує отриманий заголовок) та не приймає пакетні запити JSON-RPC. Повідомлення без `id` є сповіщенням і отримує HTTP 202 без тіла відповіді. Дозволено лише метод `POST`.

- **Ревізії.** Запит, що містить `io.modelcontextprotocol/protocolVersion` у `params._meta`, повинен вказувати `2026-07-28`; усе інше отримує помилку `-32022`. Такі запити також повинні мати відповідні заголовки `Mcp-Protocol-Version`, `Mcp-Method` і (для `tools/call`) `Mcp-Name`, інакше повертається помилка `-32020`. Інші запити обробляються як `2025-11-25`: `initialize` відповідає цією ревізією, а для будь-якого іншого методу заголовок `Mcp-Protocol-Version`, якщо він надісланий, має дорівнювати `2025-11-25`, `2025-06-18` або `2025-03-26`.
- **Помилки інструментів.** Помилка можливості, зокрема аргументи, що не відповідають схемі, або значення `arguments`, яке не є JSON-об'єктом, повертається як результат інструмента з `isError: true` та помилкою AIP-193 у `structuredContent`, а не як помилка протоколу.
- **Помилки протоколу.** Збої, які не є помилками інструментів, повертаються як об'єкти помилок JSON-RPC (код `-32000` зі статусом і причиною в `data`, або стандартні коди): відсутній Public Cacti URL, відхилений `Origin`, запит за вимкненого плагіна або на віддаленому поллері, а також непередбачені помилки сервера (`-32603`, із записом деталей у журнал Cacti, а не у відповідь). Першочергові перевірки запиту (405, 413, 415) і помилки автентифікації (401 `INVALID_TOKEN`, 403 `REALM_REQUIRED`) зберігають тіло формату AIP-193, описане в розділі HTTP API.

## HTTP API

Базовий URL: `https://cacti.example.com/cacti/plugins/mcp/api.php`. Контракт наведено в [openapi.json](../../../openapi.json).

| Метод і шлях | Призначення |
| --- | --- |
| `GET /v1/abilities` | Список дозволених можливостей. Параметри запиту: `pageSize`, `pageToken` та `filter` у вигляді `category = "inventory"`. |
| `GET /v1/abilities/{id}` | Отримати одну можливість. |
| `POST /v1/abilities/{id}:execute` | Виконати її. Тіло запиту — рівно `{"arguments": {...}}`. Відповідь — `{"requestId": "...", "result": {...}}`. |

```console
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" \
  https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" -H 'Content-Type: application/json' \
  -d '{"arguments": {"filter": "state = \"DOWN\""}}' \
  'https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities/cacti-list-devices:execute'
```

Помилки відповідають AIP-193: об'єкт `error` із полями `code`, `message`, `status` та `details`, який містить `ErrorInfo` з доменом `cacti.net` і стабільною причиною `reason`. Проблеми з аргументами додають елемент `BadRequest` із назвою поля. Тіло запиту обмежене 64 КБ, а результат — 1 МБ. Обидві кінцеві точки відповідають лише на головному поллері й повертають `UNAVAILABLE` (`PLUGIN_UNAVAILABLE`), коли плагін вимкнено або сервер не є головним поллером.

| HTTP | Значення `reason` |
| --- | --- |
| 400 | `INVALID_ARGUMENTS`, `INVALID_FILTER`, `INVALID_PAGE_TOKEN`, `LOG_UNAVAILABLE` |
| 401 | `INVALID_TOKEN` (також надсилає `WWW-Authenticate: Bearer`) |
| 403 | `REALM_REQUIRED` |
| 404 | `ABILITY_NOT_FOUND`, `DEVICE_NOT_FOUND`, `UNKNOWN_PATH` |
| 405 | `METHOD_NOT_ALLOWED` (надсилає `Allow`) |
| 413 | `REQUEST_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR`, `INVALID_RESULT` |
| 503 | `AUDIT_UNAVAILABLE`, `PLUGIN_UNAVAILABLE`, `CACTI_UNAVAILABLE` |

## Написання можливості (для авторів плагінів)

Увімкнений плагін Cacti реєструє можливості за допомогою функції, яку він приєднує до хука `abilities_register`, зазвичай у своїй функції `plugin_<slug>_install()`:

```php
api_plugin_register_hook('acme', 'abilities_register', 'acme_abilities_register', 'setup.php');
```

Функція отримує `AbilitiesRegistrar`, обмежений областю дії цього плагіна. Значення, яке вона повертає, ігнорується.

```php
function acme_abilities_register(AbilitiesRegistrar $registrar) : void {
	$registrar->registerCategory('acme-widgets', 'Widgets');

	$registrar->register('acme-get-widget-count', [
		'label'         => 'Get widget count',
		'description'   => 'Count the widgets the caller may see.',
		'category'      => 'acme-widgets',
		'input_schema'  => ['type' => 'object', 'properties' => new stdClass(), 'additionalProperties' => false],
		'output_schema' => [
			'type'                 => 'object',
			'properties'           => ['count' => ['type' => 'integer', 'minimum' => 0]],
			'required'             => ['count'],
			'additionalProperties' => false
		],
		'annotations' => ['readOnly' => true, 'destructive' => false, 'idempotent' => true],
		'permission'  => fn (int $userId) => is_realm_allowed(ACME_REALM_ID, $userId),
		'execute'     => fn (int $userId, stdClass $args) => ['count' => acme_count_widgets($userId)]
	]);
}
```

Правила, що перевіряються під час реєстрації:

- **Ідентифікатори.** Ідентифікатор відповідає шаблону `^[a-z][a-z0-9]*(-[a-z0-9]+){1,7}$`, має довжину не більше 64 символів і повинен починатися зі слагу плагіна та дефіса: `acme-` у прикладі вище. Слагом є назва каталогу плагіна, тому каталог із назвою на кшталт `my_plugin` не може нічого зареєструвати. Каталог плагіна з назвою `cacti` відхиляється; цей простір імен належить вбудованим можливостям.
- **Визначення.** Рівно такі ключі: `label`, `description` (до 4096 байтів), `category`, `input_schema`, `output_schema`, `annotations`, `permission`, `execute`. Категорія вже має існувати: використовуйте вбудовану (`inventory`, `system`) або зареєструйте власну через `registerCategory()`, чий ідентифікатор унікальний для всіх плагінів і відповідає `^[a-z][a-z0-9-]{0,31}$`.
- **Лише для читання.** `annotations` має містити рівно `readOnly: true`, `destructive: false`, `idempotent: true`. Будь-що інше спричиняє виняток.
- **Схеми.** `input_schema` та `output_schema` повинні мати на верхньому рівні `type` зі значенням `object`. Діалект компактний і працює за принципом безпечної відмови (fail-closed). Об'єкти мають бути закритими (`additionalProperties: false` із наявним `properties`); інші типи — це `integer` і `number` (`minimum`, `maximum`), `string` (`minLength`, `maxLength`, `enum`, `pattern`), `boolean` і `array` (потребує `items` та `maxItems`). Тип можна зробити таким, що допускає `null`, у вигляді `['string', 'null']`. Рядки аргументів типово обмежені 4096 символами; рядки результату обмежуються лише оголошеним `maxLength` і загальним лімітом розміру результату. Загалом можна зареєструвати не більше 256 можливостей.
- **`permission(int $userId): bool`.** Повинна повертати рівно `true` для надання доступу. Ідентифікатор користувача належить власнику токена; ніколи не зчитуйте стан сесії.
- **`execute(int $userId, stdClass $args): array`.** Аргументи `$args` уже перевірено на відповідність `input_schema`. Перевіряйте дозволи на рівні об'єктів самостійно. Повертайте асоціативний масив, що точно відповідає `output_schema`; список, зайве поле або понад 1 МБ JSON перетворюються на помилку `INVALID_RESULT`. Для помилок, видимих клієнту (наприклад, `NOT_FOUND`), викидайте `AbilitiesError`.
- **Порожні об'єкти.** PHP кодує `[]` як JSON-масив. Усюди, де вихідна схема оголошує `object`, на будь-якій глибині, реєстр трактує `[]` як порожній об'єкт і надсилає `{}`; `new stdClass()` також працює. Непорожній список ніколи не вважається об'єктом і завершується помилкою `INVALID_RESULT`. Порожня мапа `properties` у схемі може бути задана як `[]` або `new stdClass()`; обидва варіанти публікуються як `{}`.
- **Ізоляція збоїв.** Кожен плагін виконує реєстрацію в тимчасову копію, яка зберігається лише тоді, коли ваша функція завершується нормально. Якщо вона викидає виняток, жодна з ваших можливостей не реєструється, а збій записується до журналу.

Можливості з плагінів спочатку приховані. Адміністратор відкриває їх на вкладці Abilities у консолі, а в стовпці Required Realm для них відображається "Set by the plugin".

## Модель безпеки

- **Лише Bearer.** `api.php` та `mcp.php` приймають персональний токен у заголовку
  `Authorization` і більше нічого. Вони відкидають файли cookie, `$_POST` і
  `$_REQUEST` до завантаження Cacti та знищують сеанс, який запускає Cacti, тому вхід
  через браузер ніколи не надає доступу до API.
- **Обхідний шлях для CSRF.** Захист CSRF у Cacti відхиляє JSON POST-запит без
  CSRF-токена Cacti, який жоден клієнт MCP не може надіслати. Лише для цих двох
  кінцевих точок плагін перейменовує метод запиту перед завантаженням Cacti та
  відновлює його після цього, тож захист пропускає їх. Це безпечно, оскільки CSRF
  захищає запити, які браузер автентифікує за допомогою файлів cookie, а ці кінцеві
  точки не приймають жодної ідентифікації через cookie: міжсайтова сторінка не може
  додати bearer-токен. Сторінки консолі зберігають повний захист від CSRF. Цей обхідний
  механізм є тимчасовим, доки Cacti не запропонує підтримуваний виняток; див.
  `lib/bootstrap.php`.
- **Перевірка Origin.** На `mcp.php`, якщо запит містить заголовок `Origin`, він має
  точно відповідати схемі, хосту та порту публічної URL-адреси Cacti, інакше запит
  відхиляється з помилкою `ORIGIN_NOT_ALLOWED`. Запит без заголовка `Origin`, що є
  типовим способом підключення небраузерних клієнтів, дозволяється. Це не дає
  вебсторінці керувати кінцевою точкою з браузера відвідувача. `api.php` не застосовує
  цю перевірку.
- **Лише для читання.** Реєстрація відхиляє будь-яку можливість, яка не є доступною
  лише для читання, неруйнівною та ідемпотентною.
- **Застосовуються як відкритість, так і області прав.** Можливість має бути
  відкритою, а власник токена повинен мати її область прав. Якщо таблицю відкритості
  неможливо прочитати, усі можливості приховуються замість повернення до усталених
  значень.
- **Приховані, невідомі та недозволені виглядають однаково.** Клієнт не може
  відрізнити можливість, якої не існує, від прихованої або тієї, яку його користувач не
  має права використовувати: виявлення пропускає її, а виконання повертає `NOT_FOUND`
  (`ABILITY_NOT_FOUND`).
- **Токени.** Зберігаються у вигляді гешів SHA-256, показуються один раз, завжди мають
  строк дії, можуть бути відкликані та відхиляються, якщо власника вимкнено або він
  втрачає область прав.
- **Аудит.** `plugin_mcp_audit` записує ідентифікатор запиту, ідентифікатор токена,
  ідентифікатор користувача, можливість, результат (`started`, `succeeded`, `failed`,
  `denied`, `rejected`) та часові мітки. Вона ніколи не записує аргументи, результати
  чи значення токенів. Можливість запускається лише після запису її рядка `started`;
  якщо таблиця аудиту недоступна, виклик завершується помилкою `UNAVAILABLE` і не
  виконується. Виклик, відхилений до запуску, записується як один рядок: `denied` для
  невідомої, прихованої або недозволеної можливості, `rejected` для аргументів, що не
  відповідають схемі. Створення та відкликання токенів із консолі, розділу My MCP
  Tokens та CLI записуються як `mcp-token-create` і `mcp-token-revoke` із результатом
  `succeeded`, причому відкликання записується лише для активного токена. Виявлення та
  виклики, у яких `arguments` не є об'єктом JSON, не журналюються.
- **Журнал збоїв.** Неочікуваний збій, `INVALID_RESULT` або недоступна таблиця аудиту
  записують один рядок до журналу Cacti з категорією `MCP`: ідентифікатор можливості,
  фіксована причина та клас винятку. Повідомлення, аргументи й токени ніколи не
  журналюються.
- **Лише головний опитувач.** Обидві кінцеві точки, обидві сторінки консолі та
  `tokens.php` відмовляються працювати будь-де інде.

## Життєвий цикл

Вимкнення плагіна блокує обидві кінцеві точки. Видалення відкликає кожен токен і
зберігає три таблиці (`plugin_mcp_token`, `plugin_mcp_audit`, `plugin_mcp_ability`)
для подальшого зберігання даних; повторне встановлення не відновлює активність
відкликаного токена. Створюйте резервні копії таблиць разом із базою даних Cacti та
застосовуйте політику зберігання аудиту поза плагіном.

## Розроблення та тестування

Набір тестів містить звичайні PHP-скрипти в `tests/`, а також модульні тести PHPUnit у `tests/Unit/` і статичний аналіз PHPStan (рівень 6), що запускаються без встановленого Cacti:

```console
for t in tests/*.php; do php "$t" || break; done
composer install
composer phpstan
composer test
git archive --format=tar.gz --prefix=mcp/ HEAD > mcp.tar.gz
```

CI запускається на PHP від 8.2 до 8.5: завдання `test`, яке перевіряє синтаксис PHP (`php -l`) і запускає 13 звичайних PHP-скриптів тестування, перелічених у `.github/workflows/ci.yml`, завдання `quality`, яке виконує `composer phpstan` і `composer test`, та завдання `package`, яке збирає інсталяційний архів `mcp/` (за винятком файлів розроблення і тестування, перелічених у `.gitattributes`) і його файл `SHA256SUMS`. Тести, які взаємодіють із Cacti, використовують фікстури на межі допоміжних функцій Cacti; вони не перевіряють повноцінну інсталяцію Cacti.

### Інтеграційні тести

`tests/integration/run.sh 1.2.31` або `tests/integration/run.sh develop` встановлює
плагін у справжній Cacti в контейнерах і виконує проти нього живі перевірки. Для
цього потрібні Docker із Compose версії 2.23.1 або новішої, git та openssl. `KEEP=1`
залишає стек запущеним для налагодження. CI запускає їх щоночі та за вимогою, а не
під час pull-запитів.

## Локалізація

Cacti MCP постачає скомпільовані каталоги GNU gettext у `locales/po/` та
`locales/LC_MESSAGES/`, а також локалізовані файли README у `docs/i18n/` для
англійської та ще 47 локалей (19 основних локалей рівня 1, 15 африканських, 10 азійських, а також боснійська, хорватська та сербська локалі), використовуючи текстовий домен `mcp` (`locales/po/mcp.pot`).
Cacti завантажує відповідний каталог автоматично, коли ввімкнено підтримку мов.

## Участь у розробленні

Pull-запити надсилаються до гілки `develop`. Підтримуйте сумісність робочого коду з
PHP 8.2 і дотримуйтеся стилю Cacti: табуляція, рядки в одинарних лапках, а також
допоміжні функції Cacti для роботи з базою даних і правами доступу. Додавайте тести
для зміненої логіки валідації, авторизації або поведінки протоколу та підписуйте
коміти за допомогою `git commit -s`. Узгоджуйте зміни HTTP API з
[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp).
