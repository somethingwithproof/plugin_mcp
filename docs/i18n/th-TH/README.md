Cacti MCP เป็นปลั๊กอินของ Cacti ที่ช่วยให้ไคลเอนต์ AI อ่านข้อมูล Cacti ของคุณผ่านการดำเนินการที่มีชื่อและกรองตามสิทธิ์ซึ่งเรียกว่าความสามารถ (abilities) โดยให้บริการได้สองรูปแบบจากตัวปลั๊กอินเอง ได้แก่ เอนด์พอยต์ MCP (`mcp.php`, Streamable HTTP) และ HTTP API รูปแบบ AIP (`api.php`) ทั้งนี้ Cacti ยังคงเป็นผู้ควบคุมการให้สิทธิ์และการประมวลผล ไคลเอนต์จะไม่คิวรีฐานข้อมูลโดยตรง แต่สามารถเรียกใช้ได้เฉพาะความสามารถที่ผู้ดูแลระบบเปิดเผยไว้และได้รับอนุญาตจาก realm ของ Cacti ของเจ้าของโทเค็นเท่านั้น

ผู้พัฒนาปลั๊กอินสามารถลงทะเบียนความสามารถแบบอ่านอย่างเดียวของตนเองผ่านฮุก `abilities_register` และความสามารถเหล่านั้นจะปรากฏต่อไคลเอนต์ MCP ในรูปแบบเครื่องมือโดยไม่ต้องเขียนโค้ดโปรโตคอลเพิ่มเติม

**สถานะ: รุ่นก่อนเผยแพร่จริง (pre-release) เวอร์ชัน 0.1.0** ยังไม่มีรุ่นที่ติดแท็กเผยแพร่

สิ่งที่ใช้งานได้ในปัจจุบัน:

- ความสามารถในตัวแบบอ่านอย่างเดียวสำหรับข้อมูลเวอร์ชันระบบและรายการอุปกรณ์
- โทเค็นการเข้าถึงส่วนบุคคล (`cmcp_pat_...`) เป็นข้อมูลรับรองเพียงรูปแบบเดียว
- คอนโซล Management > MCP: เปิดเผยหรือซ่อนความสามารถ สร้างและเพิกถอนโทเค็น และอ่านบันทึกการตรวจสอบ (audit log)
- Management > My MCP Tokens: ผู้ใช้สามารถจัดการโทเค็นของตนเอง ดูประวัติกิจกรรม และดูว่าโทเค็นของตนใช้งานเครื่องมือใดได้บ้าง
- MCP ผ่าน Streamable HTTP รุ่นโปรโตคอล `2026-07-28` และ `2025-11-25` รองรับเฉพาะเครื่องมือ (tools) เท่านั้น

สิ่งที่ยังไม่พร้อมใช้งาน:

- การลงชื่อเข้าใช้ด้วย OAuth 2.1 ตัวเชื่อมต่อแบบโฮสต์ที่ไม่สามารถส่งโทเค็นส่วนบุคคลได้ เช่น ตัวเชื่อมต่อแบบกำหนดเองของ ChatGPT และ claude.ai จะยังไม่สามารถเชื่อมต่อได้จนกว่าฟีเจอร์นี้จะพร้อมใช้งาน ซึ่งวางแผนไว้ใน Plan 2 โดยแผนดังกล่าวยังไม่ได้เขียนขึ้น
- ความสามารถแบบเขียนข้อมูล สามารถลงทะเบียนได้เฉพาะความสามารถแบบอ่านอย่างเดียวเท่านั้น

รายละเอียดการออกแบบอยู่ใน[ข้อกำหนดการออกแบบเอนด์พอยต์](../../superpowers/specs/2026-11-19-mcp-endpoint-design.md) และลำดับการพัฒนาอยู่ใน [docs/plan.md](../../plan.md)

## ความสามารถในตัว

| รหัส (ID) | อาร์กิวเมนต์ | Cacti realm ที่ต้องใช้ |
| --- | --- | --- |
| `cacti-get-system-info` | ไม่มี | 15 |
| `cacti-list-devices` | ทางเลือก: `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-get-device` | จำเป็น: `name` เช่น `devices/12` | 3 |

ทุกการเรียกใช้งานยังต้องอาศัย realm **MCP and Abilities API** สำหรับเจ้าของโทเค็น ขอบเขตสิทธิ์ `abilities:read` (โทเค็นส่วนบุคคลทุกอันมีสิทธิ์นี้) และความสามารถนั้นต้องถูกเปิดเผยไว้ด้วย แท็บ Abilities ในคอนโซลจะแสดง realm ที่ความสามารถในตัวแต่ละรายการต้องการ

- `cacti-list-devices` จะส่งคืนข้อมูลแบบแบ่งหน้าสูงสุดหน้าละ 100 อุปกรณ์ (ค่าเริ่มต้น 50) พร้อมด้วย `nextPageToken` โทเค็นสำหรับแบ่งหน้าจะใช้ได้เฉพาะกับ `filter` และ `orderBy` เดียวกันเท่านั้น `filter` เป็นนิพจน์แบบ AIP-160 ของการเปรียบเทียบที่เชื่อมด้วย `AND` เช่น `state = "DOWN" AND disabled = false` ฟิลด์ที่รองรับการกรองได้แก่ `displayName`, `hostname`, `disabled`, `site`, `poller`, `deviceTemplate`, `externalId` และ `state` ส่วน `orderBy` รับค่า `displayName`, `hostname` หรือ `name` โดยแต่ละค่าสามารถต่อท้ายด้วย `desc` ได้
- การคิวรีอุปกรณ์จะผ่านฟังก์ชัน `get_allowed_devices()` ของ Cacti ดังนั้นผู้ใช้จะเห็นเฉพาะอุปกรณ์ที่ Cacti อนุญาตให้แสดงต่อผู้ใช้นั้นเท่านั้น
- ฟิลด์ข้อมูลอุปกรณ์จะไม่รวมสตริงชุมชน SNMP (community strings), รหัสผ่าน (passphrases) และข้อมูลรับรองอื่น ๆ

## การติดตั้ง

ต้องใช้ Cacti 1.2.31 ขึ้นไป, PHP 8.2 ขึ้นไป และตัวโพลเลอร์หลัก (main poller) ต้องเปิดใช้งานการยืนยันตัวตนของ Cacti ไว้ ปลั๊กอินจะปฏิเสธการยืนยันตัวตนหากปิดอยู่

ไดเรกทอรีของปลั๊กอินต้องตั้งชื่อว่า `mcp` ไม่ใช่ `plugin_mcp` ทั้ง slug ของปลั๊กอิน ชื่อ realm โดเมนคำแปล และ URL ล้วนใช้ `mcp`

จากซอร์สโค้ดที่โคลนมา:

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_mcp.git mcp
```

จนกว่าจะมีการเผยแพร่รุ่นที่ติดแท็ก คุณสามารถดาวน์โหลดอาร์ติแฟกต์ `mcp-plugin` จาก[การรัน CI ที่สำเร็จ](https://github.com/somethingwithproof/plugin_mcp/actions/workflows/ci.yml)แทนได้ ภายในประกอบด้วย `mcp.tar.gz` และ `SHA256SUMS` ให้ตรวจสอบค่า checksum แล้วแตกไฟล์ `mcp.tar.gz` ภายในไดเรกทอรี `plugins/` ของ Cacti เพื่อให้ผลลัพธ์เป็น `plugins/mcp/` ไฟล์ซอร์สโค้ดที่ GitHub สร้างให้อัตโนมัติจะใช้ชื่อไดเรกทอรีระดับบนสุดต่างออกไป อาร์ติแฟกต์นี้จะไม่รวม `docs/` (รวมถึงภาพหน้าจอด้านล่าง), `tests/` และ `.github/` ดังนั้นลิงก์ใน README ที่ชี้ไปยัง `docs/` จะใช้งานได้บน GitHub แต่ใช้ไม่ได้ในชุดที่ติดตั้งแล้ว

จากนั้น:

1. ใน Plugin Management ให้ติดตั้งและเปิดใช้งาน **Cacti MCP** ผู้ดูแลระบบที่ทำการติดตั้งจะได้รับ realm **MCP Administration** โดยอัตโนมัติ
2. ใน Settings > MCP ให้ตั้งค่า **Public Cacti URL** เป็นที่อยู่ที่ไคลเอนต์ใช้เชื่อมต่อ เช่น `https://cacti.example.com/cacti` จำเป็นต้องใช้ HTTPS ยกเว้น `localhost`, `127.0.0.1` และ `[::1]` หากยังไม่ได้ตั้งค่านี้ `mcp.php` จะตอบกลับด้วย HTTP 400 พร้อมข้อผิดพลาด JSON-RPC ที่มี `data` เป็น `FAILED_PRECONDITION` และ `PUBLIC_URL_REQUIRED` ส่วน `api.php` จะไม่อ่านค่านี้

   ![Settings > MCP แสดงฟิลด์ Public Cacti URL](../../images/settings-public-url.png)

3. มอบสิทธิ์ realm **MCP and Abilities API** ให้กับผู้ใช้แต่ละคนที่จะเป็นเจ้าของโทเค็น จะไม่มีผู้ใช้รายใดได้รับสิทธิ์นี้โดยอัตโนมัติ
4. ตรวจสอบให้แน่ใจว่าเว็บเซิร์ฟเวอร์ส่งต่อส่วนหัว `Authorization` และข้อมูลพาธ (path info) ไปยัง PHP (ดูด้านล่าง)
5. เปิด Management > MCP แล้วเปิดเผยความสามารถที่คุณต้องการให้ไคลเอนต์มองเห็น

**การอัปเกรดจากบิลด์สำหรับการพัฒนา** ปลั๊กอินยังอยู่ในรุ่นก่อนเผยแพร่จริง และโครงสร้างตารางมีการเปลี่ยนแปลงระหว่างการพัฒนาโดยไม่มีสคริปต์ไมเกรชัน หากคุณเคยติดตั้งบิลด์ก่อนหน้าไว้ ให้ถอนการติดตั้งแล้วติดตั้งใหม่อีกครั้ง การติดตั้งใหม่จะยังคงเก็บตารางที่มีอยู่เดิมไว้ ดังนั้นให้ลบตาราง `plugin_mcp_token`, `plugin_mcp_audit` และ `plugin_mcp_ability` เดิมทิ้งก่อน (รวมถึงตารางเทียบเท่าจากบิลด์ก่อนการเปลี่ยนชื่อ) ให้สำรองข้อมูลไว้หากคุณต้องการเก็บประวัติการใช้งาน โทเค็นจากบิลด์เหล่านั้นจะถูกเพิกถอนเมื่อถอนการติดตั้งและจะไม่ถูกโอนย้ายมาด้วย

### เว็บเซิร์ฟเวอร์

การตั้งค่า Apache ที่ตัดส่วนหัว `Authorization` ออกก่อนส่งถึง PHP จำเป็นต้องเพิ่มคำสั่งนี้ใน virtual host หรือไดเรกทอรีที่เกี่ยวข้อง แล้วรีโหลดเซิร์ฟเวอร์:

```apache
SetEnvIf Authorization "(.+)" HTTP_AUTHORIZATION=$1
```

Apache ที่ใช้ `mod_php` สามารถให้บริการเส้นทางของ `api.php` ได้โดยไม่ต้องตั้งค่าพาธเพิ่มเติม

เส้นทางของ `api.php` จะอยู่ในพาธที่ต่อท้ายชื่อสคริปต์ (`/plugins/mcp/api.php/v1/abilities`) ดังนั้น nginx ต้องจับคู่ URI ที่มีพาธต่อท้าย `.php` แยกส่วน path info ออกมา แล้วส่งต่อไปยัง PHP บล็อก `location ~ \.php$` จะไม่ตรงกับ URL เหล่านี้เลย ทำให้ nginx ตอบกลับด้วยหน้า HTML 404 ของตนเอง รูปแบบ location และบรรทัด path-info สองบรรทัดด้านล่างนี้ได้รับการตรวจสอบกับ PHP-FPM แล้ว ส่วนบรรทัดอื่น ๆ เป็นค่ามาตรฐานทั่วไป:

```nginx
location ~ \.php(/|$) {
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php-fpm.sock;   # your PHP-FPM socket or host:port
}
```

ปรับบรรทัด `include` และ `fastcgi_pass` ให้ตรงกับบล็อกที่ให้บริการ Cacti อยู่เดิม อย่าเพิ่ม `try_files $fastcgi_script_name =404;` ลงในบล็อกนี้ เพราะจะล้างค่า `$fastcgi_path_info` และทำให้ `api.php` ตอบกลับด้วย 404 `UNKNOWN_PATH` หากการตั้งค่าของคุณจำเป็นต้องใช้ `try_files` ให้บันทึกค่าไว้ก่อนด้วย `set $path_info $fastcgi_path_info;` แล้วส่ง `fastcgi_param PATH_INFO $path_info;`

`mcp.php` ไม่มีเส้นทางพาธย่อยและไม่จำเป็นต้องใช้การตั้งค่าเหล่านี้

## คอนโซล

Management > MCP มีสามแท็บ โดยคุณต้องมีสิทธิ์ realm **MCP Administration** ภาพหน้าจอในส่วนนี้และด้านล่างมาจากบิลด์สำหรับการพัฒนาของ Cacti พร้อมข้อมูลตัวอย่าง

- **Abilities** แสดงรายการความสามารถที่ลงทะเบียนไว้ทั้งหมด พร้อมปลั๊กอิน หมวดหมู่ realm ที่ต้องใช้ และสถานะการเปิดเผย เลือกแถวแล้วเลือก Expose หรือ Hide โดยจะมีให้ยืนยันก่อนการเปลี่ยนแปลงจะมีผล ความสามารถในตัว `cacti-*` จะถูกเปิดเผยเป็นค่าเริ่มต้น ส่วนความสามารถจากปลั๊กอินอื่นจะเริ่มต้นแบบซ่อนไว้ ดังนั้นการติดตั้งปลั๊กอินจะไม่เผยแพร่สิ่งใดจนกว่าผู้ดูแลระบบจะตัดสินใจ การเปิดเผยเป็นการจำกัดสิทธิ์เพิ่มเติมเท่านั้น ผู้ใช้ยังคงต้องมี realm ของความสามารถนั้นด้วย

  ![แท็บ Abilities แสดงรายการความสามารถในตัวพร้อม realm และสถานะการเปิดเผย](../../images/console-abilities.png)
- **Tokens** แสดงรายการโทเค็นพร้อมเจ้าของ ผู้สร้าง เวลาที่สร้าง วันหมดอายุ การใช้งานล่าสุด และสถานะ (Active, Expired, Revoked) เลือกแถวแล้วเลือก Revoke เพื่อเพิกถอน โทเค็นที่ถูกเพิกถอนแล้วจะไม่สามารถนำกลับมาใช้ได้อีก ใช้ Create Token เพื่อสร้างโทเค็นใหม่

  ![แท็บ Tokens แสดงรายการโทเค็นพร้อมเจ้าของ วันหมดอายุ การใช้งานล่าสุด และสถานะ เหนือฟอร์ม Create Token](../../images/console-tokens.png)
- **Audit** แสดงแถวบันทึกการตรวจสอบโดยเรียงจากล่าสุดก่อน และกรองตามผู้ใช้ ความสามารถ และผลลัพธ์ได้

  ![แท็บ Audit แสดงรายการเรียกใช้งานพร้อมผู้ใช้ โทเค็น ความสามารถ และผลลัพธ์ พร้อมตัวกรอง](../../images/console-audit.png)

## โทเค็น

โทเค็นส่วนบุคคลจะอ่านข้อมูล Cacti ในนามของเจ้าของ โดยมีรูปแบบเป็น `cmcp_pat_` ตามด้วยอักขระฐานสิบหกตัวพิมพ์เล็ก 64 ตัว และมีขอบเขตสิทธิ์เพียงหนึ่งเดียวคือ `abilities:read` สิ่งที่โทเค็นมองเห็นได้จะถูกกำหนดโดย realm ของ Cacti และสิทธิ์การเข้าถึงอุปกรณ์ของเจ้าของ ไม่ใช่ตัวโทเค็นเอง เจ้าของต้องเป็นผู้ใช้ที่เปิดใช้งานอยู่และถือสิทธิ์ realm **MCP and Abilities API**

โทเค็นจะถูกสร้างขึ้นให้ผู้ใช้เฉพาะรายเสมอ มีวันหมดอายุ และสามารถเพิกถอนได้:

- **คอนโซล** Management > MCP > Tokens > Create Token อายุการใช้งานอยู่ที่ 1 ถึง 365 วัน และมีค่าเริ่มต้นเป็น 90 วัน เซิร์ฟเวอร์จะสร้างโทเค็นและแสดงเพียงครั้งเดียวในหน้าผลลัพธ์ ดังนั้นให้คัดลอกเก็บไว้ในเครื่องมือจัดการข้อมูลลับของคุณทันที คุณสามารถสร้างโทเค็นให้ตนเองได้ แต่การสร้างให้ผู้ใช้อื่นจะต้องมี realm Users/Groups ด้วย เนื่องจากโทเค็นจะอ่านข้อมูล Cacti ในฐานะผู้ใช้นั้น
- **My MCP Tokens** ผู้ใช้ที่มี realm MCP and Abilities API สามารถจัดการโทเค็นของตนเองได้ ดูรายละเอียดด้านล่าง
- **บรรทัดคำสั่ง (CLI)** `tokens.php` ทำงานได้จาก CLI เท่านั้น โดยใช้บัญชีระบบปฏิบัติการที่สามารถดูแล Cacti ได้ โปรแกรมจะรับโทเค็นจากตัวแปรสภาพแวดล้อมเพื่อไม่ให้ค่าโทเค็นปรากฏในบรรทัดคำสั่งหรือรายการโพรเซส อายุการใช้งานอยู่ที่ 1 ถึง 365 วัน และมีค่าเริ่มต้นเป็น 30 วัน การสร้างและเพิกถอนโทเค็นผ่าน CLI จะถูกบันทึกตรวจสอบเช่นเดียวกับในคอนโซล โดยบันทึกเจ้าของโทเค็นเป็นผู้ดำเนินการเนื่องจาก CLI ไม่มีผู้ใช้ Cacti ดังนั้นแถวบันทึกการตรวจสอบจึงไม่ได้ระบุว่าเป็นการกระทำจาก CLI แฟล็ก `--list` จะพิมพ์โทเค็นทั้งหมดเป็น JSON (รหัส, เจ้าของ, ขอบเขตสิทธิ์, การประทับเวลา, แฟล็กการเพิกถอน) และไม่แสดงค่าโทเค็น ส่วน `--help` จะแสดงวิธีใช้งาน

  ```console
  export CACTI_MCP_TOKEN="$(printf 'cmcp_pat_%s\n' "$(openssl rand -hex 32)")"
  # Store this value in your secret manager before you end this shell session.
  php plugins/mcp/tokens.php --create=USERNAME --days=30
  php plugins/mcp/tokens.php --list
  php plugins/mcp/tokens.php --revoke=ID
  ```

ไม่สามารถสร้างโทเค็นให้บัญชีผู้เยี่ยมชม (guest) ผู้ใช้ที่ถูกปิดใช้งาน หรือผู้ใช้ที่ไม่มี realm **MCP and Abilities API** ได้ ไม่ว่าจะผ่านคอนโซล บรรทัดคำสั่ง หรือ My MCP Tokens ทั้งนี้ Cacti อาจเก็บการตั้งค่าบัญชี guest เป็นชื่อผู้ใช้หรือรหัสผู้ใช้ และปลั๊กอินจะแปลงค่าได้ทั้งสองแบบ โทเค็นที่เจ้าของถูกเปลี่ยนเป็นบัญชี guest จะหยุดทำงานในคำขอถัดไป

### โทเค็น MCP ของฉัน

Management > My MCP Tokens (`plugins/mcp/mcp_tokens.php`) ไม่จำเป็นต้องใช้ realm ระดับผู้ดูแลระบบ แต่ครอบคลุมด้วย realm **MCP and Abilities API** และรายการเมนูจะปรากฏเฉพาะสำหรับผู้ใช้ที่ถือสิทธิ์นี้เท่านั้น หน้านี้จะดำเนินการกับผู้ใช้ที่ลงชื่อเข้าใช้อยู่เสมอ เมนูของ Cacti เป็นส่วนหนึ่งของคอนโซล ดังนั้นผู้ใช้ที่ไม่มีสิทธิ์เข้าถึงคอนโซลจึงต้องเข้าถึงหน้านี้ผ่านที่อยู่ URL โดยตรง

![แท็บ My Tokens แสดงรายการโทเค็นของผู้ใช้ที่ลงชื่อเข้าใช้และฟอร์มสร้างโทเค็น](../../images/my-tokens.png)

- **Tokens** แสดงรายการโทเค็นของคุณ สร้างโทเค็นใหม่ (1 ถึง 365 วัน ค่าเริ่มต้น 90 วัน แสดงเพียงครั้งเดียวในหน้าผลลัพธ์) และเพิกถอนโทเค็นของคุณเอง คุณไม่สามารถดูหรือเพิกถอนโทเค็นของผู้อื่นได้
- **Activity** แสดงรายการกิจกรรมที่คุณดำเนินการโดยเรียงจากล่าสุดก่อน ทั้งการเรียกใช้งานผ่านโทเค็นของคุณและการเปลี่ยนแปลงโทเค็นที่คุณทำ
- **Available Tools** แสดงรายการความสามารถที่โทเค็นของคุณใช้งานได้ในขณะนี้ พร้อมรหัส ชื่อ และคำอธิบายของแต่ละความสามารถ โดยเป็นไปตามสิทธิ์ของ Cacti ของคุณและการตั้งค่าการเปิดเผยที่ผู้ดูแลระบบเลือกไว้

  ![รายการ Available Tools แสดงรหัส ชื่อ และคำอธิบายของแต่ละความสามารถ](../../images/my-tools.png)

การติดตั้งที่ทำขึ้นก่อนที่จะมีหน้านี้อาจมีรายการไฟล์ realm ที่ยังไม่มี `mcp_tokens.php` ขั้นตอนการติดตั้งจะเป็นผู้ลงทะเบียนรายการดังกล่าว ซึ่งจะไม่อัปเดตเมื่อเปิดหรือปิดใช้งานปลั๊กอิน ให้ถอนการติดตั้งแล้วติดตั้งปลั๊กอินใหม่อีกครั้ง จากนั้นมอบสิทธิ์ realm ใหม่ เนื่องจาก Cacti จะลบสิทธิ์ realm ออกเมื่อถอนการติดตั้งปลั๊กอิน

ฐานข้อมูลจะจัดเก็บเฉพาะค่าแฮช SHA-256 ของโทเค็นเท่านั้น ดังนั้นโทเค็นที่สูญหายจึงไม่สามารถกู้คืนได้ ให้เพิกถอนแล้วสร้างใหม่ การหมุนเวียนโทเค็น (rotation) ก็ทำเช่นเดียวกัน คือสร้างโทเค็นใหม่ เปลี่ยนการตั้งค่าที่ไคลเอนต์ แล้วจึงเพิกถอนโทเค็นเดิม โทเค็นที่หมดอายุ โทเค็นที่ถูกเพิกถอน เจ้าของที่ถูกปิดใช้งาน หรือการสูญเสียสิทธิ์ realm จะทำให้คำขอถัดไปล้มเหลวทั้งหมด ระบบยอมรับโทเค็นเฉพาะในส่วนหัว `Authorization: Bearer` เท่านั้น และจะไม่ยอมรับโทเค็นที่ส่งมาใน query string หรือ body

## เชื่อมต่อไคลเอนต์

ใช้ปลายทาง MCP `https://cacti.example.com/cacti/plugins/mcp/mcp.php` โดยใส่โทเค็นในส่วนหัว `Authorization: Bearer` เก็บโทเค็นไว้ในตัวแปรสภาพแวดล้อมหรือตัวจัดการความลับ แล้วอ้างอิงจากไฟล์กำหนดค่าของไคลเอนต์แทนการเขียนค่าโทเค็นลงในไฟล์โดยตรง

### Claude Code

ใส่ปลายทางไว้ในไฟล์ `.mcp.json` ของโปรเจกต์โดยอ้างอิงโทเค็นตามชื่อ
Claude Code จะขยายค่า `${VAR}` ใน `url` และ `headers` ดังนั้นไฟล์จึงไม่มีข้อมูลความลับและปลอดภัยต่อการคอมมิต ให้ส่งออกตัวแปร `CACTI_MCP_TOKEN` ในสภาพแวดล้อมที่ใช้เริ่มต้น Claude Code

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

คุณยังสามารถเพิ่มได้จากบรรทัดคำสั่ง:

```console
claude mcp add --transport http cacti https://cacti.example.com/cacti/plugins/mcp/mcp.php \
  --header "Authorization: Bearer $CACTI_MCP_TOKEN"
```

เมื่อใช้เครื่องหมายอัญประกาศคู่ เชลล์ของคุณจะขยายค่า `$CACTI_MCP_TOKEN` ก่อน ทำให้ค่าโทเค็นถูกเขียนลงในไฟล์กำหนดค่าสำหรับ `--scope` ที่เลือก (`local`, `user` หรือ `project` โดยค่าเริ่มต้นคือ `local`) ห้ามใช้รูปแบบนี้ร่วมกับ `--scope project` และต้องกันไฟล์นี้ออกจากการควบคุมเวอร์ชัน แนะนำให้ใช้วิธีอ้างอิงในไฟล์ `.mcp.json` ด้านบนแทน Claude Code จะอ่านตัวแปรข้อมูลรับรองบางตัว (เช่น `ANTHROPIC_AUTH_TOKEN`) เป็นค่าว่างใน `url` และ `headers` ระยะไกล แต่ `CACTI_MCP_TOKEN` ไม่ได้อยู่ในกลุ่มนั้น ที่มา:
[เอกสารประกอบ Claude Code MCP](https://code.claude.com/docs/en/mcp)

### GitHub Copilot ใน VS Code

ใช้ไฟล์ `.mcp.json` ที่รากของพื้นที่ทำงาน (หรือไฟล์ของผู้ใช้ที่ `~/.copilot/mcp-config.json`)
ไฟล์แบบเนทีฟของ Copilot เหล่านี้ใช้ออบเจกต์ระดับบนสุดชื่อ `mcpServers` และการอ้างอิงตัวแปรสภาพแวดล้อมรูปแบบ `${NAME}` ในค่าส่วนหัว:

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

ส่งออกตัวแปร `CACTI_MCP_TOKEN` ในสภาพแวดล้อมที่ใช้เริ่มต้น VS Code ไฟล์แบบเนทีฟของ Copilot ไม่รองรับการถามรับค่าผ่าน `inputs` ขั้นตอนการตั้งค่าแบบมีตัวช่วยของ VS Code จะปฏิเสธค่า `${...}` ดังนั้นให้เพิ่มส่วนหัว `Authorization` โดยการแก้ไขไฟล์โดยตรง ไม่ใช่ผ่านขั้นตอนแบบมีตัวช่วย การตั้งค่าแบบมีตัวช่วยจะเสนอไฟล์ที่รากของพื้นที่ทำงานเฉพาะเมื่อเปิดใช้งานการตั้งค่าเชิงทดลอง `chat.mcp.workspaceRootConfig.enabled` เท่านั้น ดูเพิ่มเติมได้ที่
[เอกสารอ้างอิงการกำหนดค่า MCP ของ VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)

**รูปแบบเดิม: `.vscode/mcp.json`** VS Code ระบุว่าการกำหนดค่า Copilot ใหม่ไม่ควรใช้ `.vscode/mcp.json` หรือ `mcp.json` ของโปรไฟล์ เนื่องจากไฟล์เหล่านี้เป็นของ Local harness ที่เลิกใช้งานแล้วซึ่งจะถูกถอดออกในเดือนกุมภาพันธ์ 2027 หากคุณยังคงใช้งานอยู่ รูปแบบที่จัดการโดยตัวแก้ไขจะใช้คีย์ระดับบนสุดชื่อ `servers` และสามารถถามรับค่าโทเค็นได้:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "cacti-mcp-token",
      "description": "Cacti MCP token",
      "password": true
    }
  ],
  "servers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${input:cacti-mcp-token}"
      }
    }
  }
}
```

### ไคลเอนต์ที่รองรับเฉพาะ stdio

[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) เป็นอะแดปเตอร์เสริมที่ทำงานเป็นเซิร์ฟเวอร์ MCP แบบ stdio ในเครื่องและเรียกใช้งาน HTTP API ของปลั๊กอิน ใช้สำหรับไคลเอนต์ที่ไม่สามารถเชื่อมต่อกับเซิร์ฟเวอร์ HTTP ระยะไกลได้ โดยต้องใช้โทเค็นส่วนบุคคลเดียวกันและสื่อสารกับ `api.php`

### พฤติกรรมของ MCP

ปลายทางนี้ให้บริการเฉพาะเครื่องมือเท่านั้น ความสามารถที่เปิดเผยและได้รับอนุญาตแต่ละรายการจะเป็นเครื่องมือที่ตั้งชื่อตาม ID ของตน พร้อมสคีมาอินพุตและเอาต์พุต รวมถึงคำอธิบายประกอบแบบอ่านอย่างเดียว (`openWorldHint` เป็น `false`) รองรับเมธอด `initialize`, `server/discover`, `ping`, `tools/list` และ `tools/call` ไม่มีการเก็บเซสชัน ไม่ส่ง `Mcp-Session-Id` (และเพิกเฉยต่อค่าที่ได้รับ) และไม่รับชุดคำขอแบบ JSON-RPC batch ข้อความที่ไม่มี `id` ถือเป็นการแจ้งเตือนและจะได้รับ HTTP 202 โดยไม่มีเนื้อหา อนุญาตเฉพาะเมธอด `POST` เท่านั้น

- **เวอร์ชันของโปรโตคอล (Revisions)** คำขอที่มี `io.modelcontextprotocol/protocolVersion` ใน `params._meta` ต้องระบุเป็น `2026-07-28` มิฉะนั้นจะได้รับข้อผิดพลาด `-32022` คำขอดังกล่าวต้องมีส่วนหัว `Mcp-Protocol-Version`, `Mcp-Method` และ (สำหรับ `tools/call`) `Mcp-Name` ที่ตรงกันด้วย มิฉะนั้นคำตอบจะเป็นข้อผิดพลาด `-32020` คำขออื่น ๆ จะถูกถือเป็น `2025-11-25`: `initialize` จะตอบกลับด้วยเวอร์ชันดังกล่าว และในเมธอดอื่นใด หากมีการส่งส่วนหัว `Mcp-Protocol-Version` มาด้วย จะต้องเป็น `2025-11-25`, `2025-06-18` หรือ `2025-03-26`
- **ข้อผิดพลาดของเครื่องมือ (Tool errors)** ข้อผิดพลาดของความสามารถ รวมถึงอาร์กิวเมนต์ที่ไม่ตรงตามสคีมา หรือค่า `arguments` ที่ไม่ใช่ออบเจกต์ JSON จะถูกส่งกลับมาเป็นผลลัพธ์ของเครื่องมือที่มี `isError: true` และข้อผิดพลาดตามมาตรฐาน AIP-193 ใน `structuredContent` ไม่ใช่ข้อผิดพลาดระดับโปรโตคอล
- **ข้อผิดพลาดระดับโปรโตคอล (Protocol errors)** ความล้มเหลวที่ไม่ใช่ข้อผิดพลาดของเครื่องมือจะเป็นออบเจกต์ข้อผิดพลาดของ JSON-RPC (รหัส `-32000` พร้อมสถานะและเหตุผลใน `data` หรือรหัสมาตรฐาน): กรณีไม่มี Public Cacti URL, `Origin` ที่ถูกปฏิเสธ, คำขอที่ส่งมาขณะปลั๊กอินถูกปิดใช้งานหรือส่งไปยังโพลเลอร์ระยะไกล และข้อผิดพลาดของเซิร์ฟเวอร์ที่ไม่คาดคิด (`-32603` โดยรายละเอียดจะถูกบันทึกลงในล็อกของ Cacti ไม่ใช่ในการตอบกลับ) การตรวจสอบคำขอที่ทำงานก่อน (405, 413, 415) และความล้มเหลวในการยืนยันตัวตน (401 `INVALID_TOKEN`, 403 `REALM_REQUIRED`) จะยังคงใช้เนื้อหาแบบ AIP-193 ตามที่อธิบายไว้ในส่วน HTTP API

## HTTP API

URL หลัก: `https://cacti.example.com/cacti/plugins/mcp/api.php` สัญญาการเชื่อมต่อ (contract) อยู่ในไฟล์ [openapi.json](../../../openapi.json)

| เมธอดและพาธ | วัตถุประสงค์ |
| --- | --- |
| `GET /v1/abilities` | แสดงรายการความสามารถที่ได้รับอนุญาต พารามิเตอร์คิวรี: `pageSize`, `pageToken` และ `filter` ในรูปแบบ `category = "inventory"` |
| `GET /v1/abilities/{id}` | อ่านข้อมูลความสามารถรายการเดียว |
| `POST /v1/abilities/{id}:execute` | เรียกใช้งานความสามารถ เนื้อหาคำขอคือ `{"arguments": {...}}` เท่านั้น การตอบกลับคือ `{"requestId": "...", "result": {...}}` |

```console
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" \
  https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" -H 'Content-Type: application/json' \
  -d '{"arguments": {"filter": "state = \"DOWN\""}}' \
  'https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities/cacti-list-devices:execute'
```

ข้อผิดพลาดเป็นไปตามมาตรฐาน AIP-193: ออบเจกต์ `error` ที่มี `code`, `message`, `status` และ `details` ซึ่งบรรจุ `ErrorInfo` ที่มีโดเมน `cacti.net` และค่า `reason` ที่คงที่ ปัญหาเกี่ยวกับอาร์กิวเมนต์จะเพิ่มรายละเอียด `BadRequest` ที่ระบุชื่อฟิลด์ด้วย เนื้อหาคำขอจำกัดขนาดไว้ที่ 64 KB และผลลัพธ์จำกัดไว้ที่ 1 MB ปลายทางทั้งสองจะตอบสนองเฉพาะบนโพลเลอร์หลักเท่านั้น และจะคืนค่า `UNAVAILABLE` (`PLUGIN_UNAVAILABLE`) เมื่อปลั๊กอินถูกปิดใช้งานหรือเซิร์ฟเวอร์ไม่ใช่โพลเลอร์หลัก

| HTTP | ค่า `reason` |
| --- | --- |
| 400 | `INVALID_ARGUMENTS`, `INVALID_FILTER`, `INVALID_PAGE_TOKEN` |
| 401 | `INVALID_TOKEN` (ส่ง `WWW-Authenticate: Bearer` มาด้วย) |
| 403 | `REALM_REQUIRED` |
| 404 | `ABILITY_NOT_FOUND`, `DEVICE_NOT_FOUND`, `UNKNOWN_PATH` |
| 405 | `METHOD_NOT_ALLOWED` (ส่ง `Allow` มาด้วย) |
| 413 | `REQUEST_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR`, `INVALID_RESULT` |
| 503 | `AUDIT_UNAVAILABLE`, `PLUGIN_UNAVAILABLE`, `CACTI_UNAVAILABLE` |

## การเขียนความสามารถ (สำหรับผู้พัฒนาปลั๊กอิน)

ปลั๊กอินของ Cacti ที่เปิดใช้งานจะลงทะเบียนความสามารถจากฟังก์ชันที่ผูกไว้กับฮุก `abilities_register` โดยปกติจะอยู่ใน `plugin_<slug>_install()`:

```php
api_plugin_register_hook('acme', 'abilities_register', 'acme_abilities_register', 'setup.php');
```

ฟังก์ชันจะได้รับออบเจกต์ `AbilitiesRegistrar` ที่กำหนดขอบเขตไว้สำหรับปลั๊กอินนั้น ค่าที่คืนกลับจากฟังก์ชันจะถูกเพิกเฉย

```php
function acme_abilities_register(AbilitiesRegistrar $registrar) : void {
	$registrar->registerCategory('acme-widgets', 'Widgets');

	$registrar->register('acme-get-widget-count', [
		'label'         => 'Get widget count',
		'description'   => 'Count the widgets the caller may see.',
		'category'      => 'acme-widgets',
		'input_schema'  => ['type' => 'object', 'properties' => new stdClass(), 'additionalProperties' => false],
		'output_schema' => [
			'type'                 => 'object',
			'properties'           => ['count' => ['type' => 'integer', 'minimum' => 0]],
			'required'             => ['count'],
			'additionalProperties' => false
		],
		'annotations' => ['readOnly' => true, 'destructive' => false, 'idempotent' => true],
		'permission'  => fn (int $userId) => is_realm_allowed(ACME_REALM_ID, $userId),
		'execute'     => fn (int $userId, stdClass $args) => ['count' => acme_count_widgets($userId)]
	]);
}
```

กฎทั้งหมดซึ่งบังคับใช้ในขณะลงทะเบียนมีดังนี้:

- **ID** ID ต้องตรงตามรูปแบบ `^[a-z][a-z0-9]*(-[a-z0-9]+){1,7}$` มีความยาวไม่เกิน 64 อักขระ และต้องขึ้นต้นด้วย slug ของปลั๊กอินตามด้วยเครื่องหมายยัติภังค์ เช่น `acme-` ในตัวอย่างด้านบน slug คือชื่อไดเรกทอรีของปลั๊กอิน ดังนั้นไดเรกทอรีอย่าง `my_plugin` จึงไม่สามารถลงทะเบียนได้ ไดเรกทอรีปลั๊กอินที่ชื่อ `cacti` จะถูกปฏิเสธ เนื่องจากเนมสเปซนั้นสงวนไว้สำหรับความสามารถที่มีมาในตัว
- **คำนิยาม (Definition)** ต้องมีคีย์เหล่านี้ครบถ้วนและพอดี: `label`, `description` (สูงสุด 4096 ไบต์), `category`, `input_schema`, `output_schema`, `annotations`, `permission`, `execute` หมวดหมู่ต้องมีอยู่แล้ว โดยใช้หมวดหมู่ที่มีมาในตัว (`inventory`, `system`) หรือลงทะเบียนหมวดหมู่ของคุณเองด้วย `registerCategory()` ซึ่ง ID ต้องไม่ซ้ำกันในทุกปลั๊กอินและตรงตามรูปแบบ `^[a-z][a-z0-9-]{0,31}$`
- **แบบอ่านอย่างเดียวเท่านั้น** `annotations` ต้องเป็น `readOnly: true`, `destructive: false`, `idempotent: true` เท่านั้น ค่าอื่นใดจะทำให้เกิดข้อยกเว้น (throw)
- **สคีมา (Schemas)** `input_schema` และ `output_schema` แต่ละตัวต้องมี `type` ระดับบนสุดเป็น `object` รูปแบบสคีมามีขนาดเล็กและปฏิเสธไว้ก่อนเมื่อไม่ตรงเงื่อนไข ออบเจกต์ต้องเป็นแบบปิด (`additionalProperties: false` และต้องระบุ `properties`) ชนิดข้อมูลอื่น ๆ ได้แก่ `integer` และ `number` (`minimum`, `maximum`), `string` (`minLength`, `maxLength`, `enum`, `pattern`), `boolean` และ `array` (ซึ่งต้องระบุ `items` และ `maxItems`) สามารถกำหนดให้ชนิดข้อมูลเป็นค่า null ได้ในรูปแบบ `['string', 'null']` สตริงของอาร์กิวเมนต์มีค่าเริ่มต้นสูงสุดไม่เกิน 4096 อักขระ ส่วนสตริงของผลลัพธ์จะจำกัดตาม `maxLength` ที่ประกาศไว้และขีดจำกัดขนาดของผลลัพธ์เท่านั้น สามารถลงทะเบียนความสามารถได้สูงสุด 256 รายการ
- **`permission(int $userId): bool`** ต้องคืนค่า `true` อย่างแท้จริงเท่านั้นจึงจะอนุญาต รหัสผู้ใช้คือรหัสของเจ้าของโทเค็น ห้ามอ่านสถานะเซสชันโดยเด็ดขาด
- **`execute(int $userId, stdClass $args): array`** `$args` ได้รับการตรวจสอบความถูกต้องกับ `input_schema` เรียบร้อยแล้ว ให้คุณบังคับใช้สิทธิ์ระดับออบเจกต์ด้วยตนเอง คืนค่าเป็นอาร์เรย์แบบเชื่อมโยง (associative array) ที่ตรงตาม `output_schema` ทุกประการ หากคืนค่าเป็นลิสต์ มีฟิลด์เกินมา หรือ JSON มีขนาดเกิน 1 MB จะกลายเป็นข้อผิดพลาด `INVALID_RESULT` ให้โยน `AbilitiesError` สำหรับความล้มเหลวที่ไคลเอนต์ควรมองเห็นได้ เช่น `NOT_FOUND`
- **ออบเจกต์ว่าง** PHP เข้ารหัส `[]` เป็นอาร์เรย์ JSON ในทุกตำแหน่งที่สคีมาเอาต์พุตประกาศเป็น `object` ไม่ว่าจะอยู่ที่ระดับความลึกใด รีจิสทรีจะถือว่า `[]` เป็นออบเจกต์ว่างและส่ง `{}` ออกไป ทั้งนี้ `new stdClass()` ก็ใช้งานได้เช่นกัน ลิสต์ที่ไม่ว่างจะไม่นับเป็นออบเจกต์และจะล้มเหลวด้วย `INVALID_RESULT` แผนที่ `properties` ที่ว่างในสคีมาอาจเป็น `[]` หรือ `new stdClass()` ก็ได้ ซึ่งทั้งคู่จะถูกเผยแพร่เป็น `{}`
- **การแยกความล้มเหลว (Failure isolation)** ปลั๊กอินแต่ละตัวจะลงทะเบียนลงในสำเนาชั่วคราวซึ่งจะถูกเก็บไว้เฉพาะเมื่อฟังก์ชันของคุณคืนค่ากลับตามปกติเท่านั้น หากฟังก์ชันโยนข้อยกเว้น จะไม่มีความสามารถใดของคุณถูกนำไปลงทะเบียน และความล้มเหลวจะถูกบันทึกลงในล็อก

ความสามารถจากปลั๊กอินจะเริ่มต้นด้วยการซ่อนไว้ ผู้ดูแลระบบจะเป็นผู้เปิดเผยรายการเหล่านี้ในแท็บ Abilities ของคอนโซล และคอลัมน์ Required Realm สำหรับรายการเหล่านั้นจะแสดงข้อความว่า "Set by the plugin"

## โมเดลความปลอดภัย

- **ใช้ Bearer Token เท่านั้น** `api.php` และ `mcp.php` รับโทเค็นส่วนบุคคลในส่วนหัว `Authorization` เท่านั้น และไม่รับวิธีอื่น ทั้งสองปลายทางจะตัดคุกกี้, `$_POST` และ `$_REQUEST` ทิ้งก่อนที่ Cacti จะโหลด และทำลายเซสชันที่ Cacti สร้างขึ้น ดังนั้นการเข้าสู่ระบบผ่านเบราว์เซอร์จะไม่มีวันได้รับสิทธิ์เข้าถึง API
- **การแก้ปัญหาเฉพาะหน้าสำหรับ CSRF** ตัวป้องกัน CSRF ของ Cacti จะปฏิเสธคำขอ JSON POST ที่ไม่มีโทเค็น CSRF ของ Cacti ซึ่งไคลเอนต์ MCP ไม่สามารถส่งมาได้ สำหรับปลายทางทั้งสองนี้เท่านั้น ปลั๊กอินจะเปลี่ยนชื่อเมธอดของคำขอก่อนที่ Cacti จะโหลดและกู้คืนกลับในภายหลัง เพื่อให้ตัวป้องกันข้ามการตรวจสอบไป วิธีนี้ปลอดภัยเนื่องจาก CSRF ป้องกันคำขอที่เบราว์เซอร์ยืนยันตัวตนด้วยคุกกี้ และปลายทางเหล่านี้ไม่รับตัวตนจากคุกกี้ หน้าเว็บข้ามไซต์จึงไม่สามารถแนบ Bearer Token ได้ ส่วนหน้าคอนโซลยังคงการป้องกัน CSRF เต็มรูปแบบ การแก้ปัญหาเฉพาะหน้านี้เป็นเพียงชั่วคราว จนกว่า Cacti จะรองรับข้อยกเว้นอย่างเป็นทางการ โปรดดู `lib/bootstrap.php`
- **การตรวจสอบ Origin** บน `mcp.php` หากคำขอมีส่วนหัว `Origin` ค่าจะต้องตรงกับสกีม โฮสต์ และพอร์ตของ Public Cacti URL ทุกประการ มิฉะนั้นคำขอจะถูกปฏิเสธด้วย `ORIGIN_NOT_ALLOWED` ส่วนคำขอที่ไม่มีส่วนหัว `Origin` ซึ่งเป็นวิธีที่ไคลเอนต์ที่ไม่ได้ทำงานบนเบราว์เซอร์ใช้เชื่อมต่อ จะได้รับอนุญาต วิธีนี้ช่วยป้องกันไม่ให้หน้าเว็บขับเคลื่อนปลายทางจากเบราว์เซอร์ของผู้เยี่ยมชม ทั้งนี้ `api.php` ไม่ใช้การตรวจสอบนี้
- **อ่านได้อย่างเดียวเท่านั้น** การลงทะเบียนจะปฏิเสธความสามารถ (ability) ใดๆ ที่ไม่ได้เป็นแบบอ่านได้อย่างเดียว ไม่ทำลายข้อมูล และทำงานซ้ำได้ผลลัพธ์เดิม (idempotent)
- **ใช้ทั้งการเปิดเผย (Exposure) และขอบเขตสิทธิ์ (Realm)** ความสามารถต้องถูกเปิดเผยและเจ้าของโทเค็นต้องถือครองขอบเขตสิทธิ์ของความสามารถนั้น หากไม่สามารถอ่านตารางการเปิดเผยได้ ความสามารถทั้งหมดจะถูกซ่อนไว้แทนที่จะถอยกลับไปใช้ค่าเริ่มต้น
- **สิ่งที่ถูกซ่อน ไม่รู้จัก และไม่ได้รับอนุญาตจะมีลักษณะเหมือนกัน** ไคลเอนต์ไม่สามารถแยกแยะความสามารถที่ไม่มีอยู่ออกจากความสามารถที่ถูกซ่อนหรือความสามารถที่ผู้ใช้ไม่มีสิทธิ์ใช้ได้: การค้นพบจะละเว้นความสามารถนั้นและการเรียกใช้งานจะส่งคืน `NOT_FOUND` (`ABILITY_NOT_FOUND`)
- **โทเค็น** จัดเก็บเป็นแฮช SHA-256 แสดงให้เห็นเพียงครั้งเดียว มีวันหมดอายุเสมอ เพิกถอนได้ และจะถูกปฏิเสธเมื่อเจ้าของถูกปิดใช้งานหรือสูญเสียขอบเขตสิทธิ์
- **การตรวจสอบย้อนหลัง (Audit)** `plugin_mcp_audit` บันทึก ID คำขอ, ID โทเค็น, ID ผู้ใช้, ความสามารถ, ผลลัพธ์ (`started`, `succeeded`, `failed`, `denied`, `rejected`) และการประทับเวลา โดยจะไม่บันทึกอาร์กิวเมนต์ ผลลัพธ์ หรือค่าของโทเค็นเลย ความสามารถจะทำงานได้ก็ต่อเมื่อเขียนแถว `started` แล้วเท่านั้น หากตารางตรวจสอบย้อนหลังไม่พร้อมใช้งาน การเรียกใช้จะล้มเหลวด้วย `UNAVAILABLE` และไม่ทำงาน การเรียกใช้ที่ถูกปฏิเสธก่อนทำงานจะเป็นหนึ่งแถว: `denied` สำหรับความสามารถที่ไม่รู้จัก ถูกซ่อน หรือไม่ได้รับอนุญาต และ `rejected` สำหรับอาร์กิวเมนต์ที่ไม่ผ่านสคีมา การสร้างและการเพิกถอนโทเค็นจากคอนโซล, My MCP Tokens และ CLI จะถูกบันทึกเป็น `mcp-token-create` และ `mcp-token-revoke` พร้อมผลลัพธ์ `succeeded` และการเพิกถอนจะถูกบันทึกเฉพาะโทเค็นที่ยังใช้งานอยู่เท่านั้น การค้นพบและการเรียกใช้ที่ `arguments` ไม่ใช่อ็อบเจกต์ JSON จะไม่ถูกบันทึก
- **บันทึกความล้มเหลว** ความล้มเหลวที่ไม่คาดคิด, `INVALID_RESULT` หรือตารางตรวจสอบย้อนหลังที่ไม่พร้อมใช้งาน จะเขียนหนึ่งบรรทัดลงในบันทึกของ Cacti ด้วย facility `MCP`: ID ความสามารถ, เหตุผลคงที่ และคลาสของข้อยกเว้น ข้อความ อาร์กิวเมนต์ และโทเค็นจะไม่ถูกบันทึกเลย
- **ตัวโพลหลักเท่านั้น** ทั้งสองปลายทาง ทั้งสองหน้าคอนโซล และ `tokens.php` จะปฏิเสธการทำงานในตำแหน่งอื่นใดทั้งหมด

## วงจรชีวิต

การปิดใช้งานปลั๊กอินจะบล็อกปลายทางทั้งสอง การถอนการติดตั้งจะเพิกถอนโทเค็นทุกตัวและเก็บรักษาตารางทั้งสาม (`plugin_mcp_token`, `plugin_mcp_audit`, `plugin_mcp_ability`) ไว้เพื่อการเก็บรักษาข้อมูล การติดตั้งซ้ำจะไม่เปิดใช้งานโทเค็นที่ถูกเพิกถอนไปแล้วอีกครั้ง ให้สำรองข้อมูลตารางเหล่านี้ร่วมกับฐานข้อมูลของ Cacti และใช้นโยบายการเก็บรักษาบันทึกการตรวจสอบย้อนหลังภายนอกปลั๊กอิน

## การพัฒนาและการทดสอบ

การทดสอบเป็นสคริปต์ PHP ธรรมดาที่ทำงานได้โดยไม่ต้องมี Cacti:

```console
for t in tests/*.php; do php "$t" || break; done
git archive --format=tar.gz --prefix=mcp/ HEAD > mcp.tar.gz
```

CI จะทำการตรวจวิเคราะห์ (lint) โค้ด PHP และรันสคริปต์ใน `tests/` (แต่ละสคริปต์ระบุไว้ใน `.github/workflows/ci.yml`) บน PHP 8.2 ถึง 8.5 จากนั้นจึงสร้างไฟล์เก็บถาวร `mcp/` ที่ติดตั้งได้พร้อมค่า checksum การทดสอบที่เกี่ยวข้องกับ Cacti จะใช้ข้อมูลจำลอง (fixtures) ที่ขอบเขตตัวช่วยของ Cacti โดยไม่ได้ทดสอบบนการติดตั้ง Cacti เต็มรูปแบบ

### การทดสอบแบบบูรณาการ

`tests/integration/run.sh 1.2.31` หรือ `tests/integration/run.sh develop` จะติดตั้งปลั๊กอินลงใน Cacti จริงภายในคอนเทนเนอร์และรันการตรวจสอบแบบสดกับระบบนั้น โดยต้องใช้ Docker พร้อม Compose เวอร์ชัน 2.23.1 หรือใหม่กว่า, git และ openssl การกำหนด `KEEP=1` จะเปิดสแต็กทิ้งไว้เพื่อการดีบัก CI จะรันการทดสอบนี้ทุกคืนและเมื่อมีการร้องขอ ไม่ใช่บนพูลรีเควสต์

## การแปลภาษาท้องถิ่น

Cacti MCP จัดส่งแคตตาล็อก GNU gettext ที่คอมไพล์แล้วภายใต้ `locales/po/` และ `locales/LC_MESSAGES/` และ README ที่แปลเป็นภาษาท้องถิ่นภายใต้ `docs/i18n/` สำหรับภาษาอังกฤษรวมกับอีก 47 ภาษาท้องถิ่น (19 ภาษา Broad Tier 1, 15 ภาษาแอฟริกา, 10 ภาษาเอเชีย รวมถึงภาษาบอสเนีย โครเอเชีย และเซอร์เบีย) โดยใช้โดเมนข้อความ `mcp` (`locales/po/mcp.pot`) Cacti จะโหลดแคตตาล็อกที่ตรงกันโดยอัตโนมัติเมื่อเปิดใช้งานการรองรับภาษา

## การมีส่วนร่วม

พูลรีเควสต์ให้ส่งไปที่ `develop` รักษาโค้ดสำหรับการใช้งานจริงให้เข้ากันได้กับ PHP 8.2 และใช้รูปแบบของ Cacti: การเยื้องด้วยแท็บ, สตริงแบบอัญประกาศเดี่ยว และตัวช่วยฐานข้อมูลและสิทธิ์ของ Cacti เพิ่มการทดสอบสำหรับการเปลี่ยนแปลงการตรวจสอบความถูกต้อง การให้สิทธิ์ หรือพฤติกรรมของโปรโตคอล และลงนามรับรองคอมมิตด้วย `git commit -s` ประสานงานการเปลี่ยนแปลงต่อ HTTP API กับ [cacti-mcp](https://github.com/somethingwithproof/cacti-mcp)
