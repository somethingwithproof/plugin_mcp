Cacti MCP என்பது திறன்கள் எனப்படும் பெயரிடப்பட்ட, அனுமதி-வடிகட்டப்பட்ட செயல்பாடுகள் மூலம் உங்கள் Cacti தரவை AI கிளையன்ட்கள் படிக்க அனுமதிக்கும் ஒரு Cacti செருகுநிரலாகும். இது செருகுநிரலிலிருந்தே இரண்டு வழிகளில் அவற்றை வழங்குகிறது: ஒரு MCP முனைப்புள்ளி (`mcp.php`, Streamable HTTP) மற்றும் ஒரு AIP-பாணி HTTP API (`api.php`). அங்கீகாரம் மற்றும் செயல்பாட்டின் பொறுப்பை Cacti தொடர்ந்து வகிக்கிறது. ஒரு கிளையன்ட் ஒருபோதும் தரவுத்தளத்தை நேரடியாக வினவுவதில்லை; நிர்வாகி வெளிப்படுத்திய மற்றும் டோக்கன் உரிமையாளரின் Cacti பகுதிகள் அனுமதிக்கும் ஒரு திறனை மட்டுமே அது அழைக்க முடியும்.

செருகுநிரல் ஆசிரியர்கள் `abilities_register` கொக்கி வழியாகத் தங்கள் சொந்த படிக்க-மட்டுமான திறன்களைப் பதிவு செய்யலாம், மேலும் அவை எந்த நெறிமுறைக் குறியீடும் இல்லாமல் MCP கிளையன்ட்களுக்குக் கருவிகளாகத் தோன்றும்.

**நிலை: முன்-வெளியீடு, பதிப்பு 0.1.0.** குறியிடப்பட்ட வெளியீடு எதுவும் இல்லை.

தற்போது கிடைப்பவை:

- கணினிப் பதிப்புகள் மற்றும் சாதனப் பட்டியலுக்கான படிக்க-மட்டுமான உள்ளமைக்கப்பட்ட திறன்கள்.
- ஒரே சான்றாகத் தனிப்பட்ட அணுகல் டோக்கன்கள் (`cmcp_pat_...`).
- மேலாண்மை > MCP கன்சோல்: திறன்களை வெளிப்படுத்தவும் அல்லது மறைக்கவும், டோக்கன்களை உருவாக்கவும் மற்றும் திரும்பப் பெறவும், தணிக்கைப் பதிவைப் படிக்கவும்.
- மேலாண்மை > எனது MCP டோக்கன்கள்: பயனர்கள் தங்கள் சொந்த டோக்கன்களை நிர்வகிக்கிறார்கள், தங்கள் செயல்பாட்டைப் பார்க்கிறார்கள், மற்றும் தங்கள் டோக்கன்கள் எந்தக் கருவிகளைப் பயன்படுத்த முடியும் என்பதைப் பார்க்கிறார்கள்.
- Streamable HTTP வழியாக MCP, நெறிமுறைப் பதிப்புகள் `2026-07-28` மற்றும் `2025-11-25`, கருவிகள் மட்டும்.

இன்னும் கிடைக்காதவை:

- OAuth 2.1 உள்நுழைவு. தனிப்பட்ட டோக்கனை அனுப்ப முடியாத ChatGPT மற்றும் claude.ai தனிப்பயன் இணைப்பிகள் போன்ற ஹோஸ்ட் செய்யப்பட்ட இணைப்பிகள், இது உருவாக்கப்படும் வரை இணைக்க முடியாது. இது திட்டம் 2 ஆகத் திட்டமிடப்பட்டுள்ளது; அந்தத் திட்டம் இன்னும் எழுதப்படவில்லை.
- எழுதும் திறன்கள். படிக்க-மட்டுமான திறன்கள் மட்டுமே பதிவு செய்ய முடியும்.

வடிவமைப்பு [முனைப்புள்ளி வடிவமைப்பு விவரக்குறிப்பில்](../../superpowers/specs/2026-11-19-mcp-endpoint-design.md) உள்ளது, மற்றும் உருவாக்க வரிசை [docs/plan.md](../../plan.md) இல் உள்ளது.

## உள்ளமைக்கப்பட்ட திறன்கள்

| ஐடி | அளவுருக்கள் | தேவையான Cacti பகுதி |
| --- | --- | --- |
| `cacti-get-system-info` | எதுவுமில்லை | 15 |
| `cacti-list-devices` | விருப்பத்தேர்வு `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-get-device` | கட்டாயம் `name`, எடுத்துக்காட்டாக `devices/12` | 3 |

ஒவ்வொரு அழைப்பிற்கும் டோக்கன் உரிமையாளருக்கான **MCP மற்றும் திறன்கள் API** பகுதி, `abilities:read` வரம்பு (ஒவ்வொரு தனிப்பட்ட டோக்கனிலும் இது உள்ளது), மற்றும் வெளிப்படுத்தப்பட்ட திறன் ஆகியவை தேவை. கன்சோலின் திறன்கள் தாவல் ஒவ்வொரு உள்ளமைக்கப்பட்ட திறனுக்கும் தேவையான பகுதியைக் காட்டுகிறது.

- `cacti-list-devices` அதிகபட்சம் 100 சாதனங்கள் கொண்ட பக்கங்களையும் (இயல்புநிலை 50) ஒரு `nextPageToken` ஐயும் திருப்பி அனுப்புகிறது. ஒரு பக்க டோக்கன் அதே `filter` மற்றும் `orderBy` ஆகியவற்றுக்கு மட்டுமே செல்லுபடியாகும். `filter` என்பது `AND` மூலம் இணைக்கப்பட்ட ஒப்பீடுகளின் AIP-160 வெளிப்பாடாகும், எடுத்துக்காட்டாக `state = "DOWN" AND disabled = false`. வடிகட்டிப் புலங்கள் `displayName`, `hostname`, `disabled`, `site`, `poller`, `deviceTemplate`, `externalId`, மற்றும் `state` ஆகும். `orderBy` என்பது `displayName`, `hostname`, அல்லது `name` ஆகியவற்றை ஏற்கிறது, ஒவ்வொன்றும் விருப்பமாக `desc` ஐத் தொடர்ந்து வரலாம்.
- சாதன வினவல்கள் Cacti இன் `get_allowed_devices()` வழியாகச் செல்கின்றன, எனவே Cacti தங்களுக்குக் காட்டும் சாதனங்களை மட்டுமே ஒரு பயனர் பார்க்கிறார்.
- சாதனப் புலங்களில் SNMP சமூகச் சரங்கள், கடவுச்சொற்றொடர்கள் மற்றும் பிற சான்றுகள் தவிர்க்கப்படுகின்றன.

## நிறுவுதல்

Cacti 1.2.31 அல்லது அதற்குப் பிந்தையது, PHP 8.2 அல்லது அதற்குப் பிந்தையது, மற்றும் முதன்மை போல்லர் தேவை. Cacti அங்கீகாரம் இயக்கப்பட்டிருக்க வேண்டும்; அது முடக்கப்பட்டிருக்கும்போது செருகுநிரல் அங்கீகரிக்க மறுக்கிறது.

செருகுநிரல் கோப்பகத்திற்கு `plugin_mcp` என்று இல்லாமல் `mcp` என்று பெயரிடப்பட வேண்டும். செருகுநிரல் ஸ்லக், பகுதிப் பெயர்கள், மொழிபெயர்ப்புத் தளம் மற்றும் URLகள் அனைத்தும் `mcp` ஐப் பயன்படுத்துகின்றன.

மூலக் குறியீடு பதிவிறக்கத்திலிருந்து:

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_mcp.git mcp
```

குறியிடப்பட்ட வெளியீடுகள் இருக்கும் வரை, அதற்குப் பதிலாக வெற்றிகரமான [CI இயக்கத்திலிருந்து](https://github.com/somethingwithproof/plugin_mcp/actions/workflows/ci.yml) `mcp-plugin` கலைப்பொருளைப் பதிவிறக்கலாம். இதில் `mcp.tar.gz` மற்றும் `SHA256SUMS` உள்ளன. செக்சம்மைச் சரிபார்த்து, பின்னர் Cacti இன் `plugins/` கோப்பகத்திற்குள் `mcp.tar.gz` ஐப் பிரித்தெடுக்கவும், இதனால் முடிவு `plugins/mcp/` ஆக இருக்கும். GitHub இன் தானியங்கி மூலக் காப்பகங்கள் வேறுபட்ட உயர்மட்டக் கோப்பகப் பெயரைப் பயன்படுத்துகின்றன. இந்தக் காப்பகம் `docs/` (கீழே உள்ள திரைப்பிடிப்புகள் உட்பட), `tests/`, மற்றும் `.github/` ஆகியவற்றைத் தவிர்க்கிறது, எனவே `docs/` க்குள் செல்லும் README இணைப்புகள் GitHub இல் வேலை செய்யும் ஆனால் நிறுவப்பட்ட நகலில் வேலை செய்யாது.

பின்னர்:

1. செருகுநிரல் மேலாண்மையில், **Cacti MCP** ஐ நிறுவி இயக்கவும். நிறுவும் நிர்வாகி தானாகவே **MCP நிர்வாகம்** பகுதியைப் பெறுவார்.
2. அமைப்புகள் > MCP கீழ், **பொது Cacti URL** ஐக் கிளையன்ட்கள் பயன்படுத்தும் முகவரிக்கு அமைக்கவும், எடுத்துக்காட்டாக `https://cacti.example.com/cacti`. `localhost`, `127.0.0.1`, மற்றும் `[::1]` தவிர்த்து HTTPS தேவைப்படுகிறது. இது அமைக்கப்படும் வரை, `mcp.php` ஆனது `data` மதிப்பு `FAILED_PRECONDITION` மற்றும் `PUBLIC_URL_REQUIRED` ஆக உள்ள JSON-RPC பிழையுடன் HTTP 400 பதிலை அளிக்கும். `api.php` இதைப் படிப்பதில்லை.

   ![பொது Cacti URL புலத்தைக் காட்டும் அமைப்புகள் > MCP](../../images/settings-public-url.png)

3. டோக்கனை வைத்திருக்கப்போகும் ஒவ்வொரு பயனருக்கும் **MCP மற்றும் திறன்கள் API** பகுதியை வழங்கவும். எந்தப் பயனரும் அதைத் தானாகப் பெறுவதில்லை.
4. இணையச் சேவையகம் `Authorization` தலைப்பு மற்றும் பாதைத் தகவலை PHP க்கு அனுப்புவதை உறுதிசெய்யவும் (கீழே காண்க).
5. மேலாண்மை > MCP ஐத் திறந்து கிளையன்ட்கள் பார்க்க விரும்பும் திறன்களை வெளிப்படுத்தவும்.

**மேம்பாட்டு உருவாக்கத்திலிருந்து மேம்படுத்துதல்.** இந்தச் செருகுநிரல் முன்-வெளியீட்டு நிலையில் உள்ளது, மேலும் அதன் அட்டவணைகள் இடம்பெயர்வுகள் இல்லாமல் மேம்பாட்டின் போது மாற்றப்பட்டன. நீங்கள் முந்தைய உருவாக்கத்தை நிறுவியிருந்தால், அதை நிறுவல் நீக்கி மீண்டும் நிறுவவும். மீண்டும் நிறுவுவது ஏற்கனவே உள்ள அட்டவணைகளை வைத்திருக்கும், எனவே முதலில் பழைய `plugin_mcp_token`, `plugin_mcp_audit`, மற்றும் `plugin_mcp_ability` அட்டவணைகளை (மற்றும் பெயர் மாற்றத்திற்கு முன் செய்யப்பட்ட உருவாக்கங்களிலிருந்து வந்த அதற்கு இணையான அட்டவணைகளை) நீக்கவும். அவற்றின் வரலாறு உங்களுக்குத் தேவைப்பட்டால் காப்புப்பிரதி எடுக்கவும்; அந்த உருவாக்கங்களிலிருந்து வந்த டோக்கன்கள் நிறுவல் நீக்கப்படும்போது திரும்பப் பெறப்படும் மற்றும் தொடராது.

### இணையச் சேவையகம்

PHP க்கு முன் `Authorization` தலைப்பை நீக்கும் Apache அமைப்புகளுக்குத் தொடர்புடைய மெய்நிகர் புரவலன் அல்லது கோப்பகத்தில் இது தேவைப்படுகிறது, அதைத் தொடர்ந்து மறுஏற்றம் செய்ய வேண்டும்:

```apache
SetEnvIf Authorization "(.+)" HTTP_AUTHORIZATION=$1
```

`mod_php` உடன் கூடிய Apache கூடுதல் பாதை உள்ளமைவு இல்லாமல் `api.php` வழிகளை வழங்கியது.

`api.php` வழிகள் ஸ்கிரிப்ட் பெயருக்குப் பிறகு உள்ள பாதையில் (`/plugins/mcp/api.php/v1/abilities`) இருப்பதால், `.php` ஐத் தொடர்ந்து கூடுதல் பாதை வரும் URIகளை nginx பொருத்த வேண்டும், பாதைத் தகவலைப் பிரிக்க வேண்டும், மேலும் அதை PHP க்கு அனுப்ப வேண்டும். ஒரு `location ~ \.php$` தொகுதி இந்த URLகளை ஒருபோதும் பொருத்துவதில்லை; nginx தனது சொந்த HTML 404 உடன் பதிலளிக்கிறது. கீழே உள்ள இருப்பிட வடிவம் மற்றும் இரண்டு பாதை-தகவல் வரிகள் PHP-FPM உடன் சரிபார்க்கப்பட்டன; மற்ற வரிகள் நிலையான வார்ப்புருக்கள் ஆகும்:

```nginx
location ~ \.php(/|$) {
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php-fpm.sock;   # your PHP-FPM socket or host:port
}
```

ஏற்கனவே Cacti ஐ வழங்கும் தொகுதியுடன் பொருந்தும்படி `include` மற்றும் `fastcgi_pass` வரிகளைச் சரிசெய்யவும். இந்தத் தொகுதியில் `try_files $fastcgi_script_name =404;` ஐச் சேர்க்க வேண்டாம்: அது `$fastcgi_path_info` ஐ அழித்துவிடும், பின்னர் `api.php` 404 `UNKNOWN_PATH` பதிலை அளிக்கும். உங்கள் உள்ளமைவுக்கு `try_files` தேவைப்பட்டால், முதலில் `set $path_info $fastcgi_path_info;` மூலம் மதிப்பைச் சேமித்து `fastcgi_param PATH_INFO $path_info;` ஐ அனுப்பவும்.

`mcp.php` க்குப் பாதை வழிகள் இல்லை, மேலும் அதற்கு அவை தேவையில்லை.

## கன்சோல்

மேலாண்மை > MCP மூன்று தாவல்களைக் கொண்டுள்ளது. உங்களுக்கு **MCP நிர்வாகம்** பகுதி தேவை. இங்கும் கீழேயும் உள்ள திரைப்பிடிப்புகள் மாதிரித் தரவுகளுடன் கூடிய Cacti மேம்பாட்டு உருவாக்கத்திலிருந்து எடுக்கப்பட்டவை.

- **திறன்கள்** பதிவுசெய்யப்பட்ட ஒவ்வொரு திறனையும் அதன் செருகுநிரல், வகை, அதற்குத் தேவையான பகுதி மற்றும் அது வெளிப்படுத்தப்பட்டுள்ளதா என்பதுடன் பட்டியலிடுகிறது. வரிசைகளைத் தேர்ந்தெடுத்து வெளிப்படுத்து அல்லது மறை என்பதைத் தேர்ந்தெடுக்கவும்; மாற்றம் பொருந்தும் முன் நீங்கள் உறுதிப்படுத்த வேண்டும். உள்ளமைக்கப்பட்ட `cacti-*` திறன்கள் இயல்புநிலையாக வெளிப்படுத்தப்படுகின்றன. பிற செருகுநிரல்களின் திறன்கள் மறைக்கப்பட்ட நிலையிலேயே தொடங்கும், எனவே ஒரு நிர்வாகி முடிவு செய்யும் வரை ஒரு செருகுநிரலை நிறுவுவது எதையும் வெளியிடாது. வெளிப்படுத்தல் அணுகலைக் குறுக்குகிறது மட்டுமே: ஒரு பயனருக்கு இன்னும் அந்தத் திறனின் பகுதி தேவை.

  ![உள்ளமைக்கப்பட்ட திறன்களையும் அவற்றின் பகுதிகளையும் வெளிப்பாடு நிலையையும் பட்டியலிடும் திறன்கள் தாவல்](../../images/console-abilities.png)
- **டோக்கன்கள்** டோக்கன்களை உரிமையாளர், உருவாக்கியவர், உருவாக்கம், காலாவதி, கடைசிப் பயன்பாடு மற்றும் நிலை (செயலில், காலாவதியானது, திரும்பப் பெறப்பட்டது) ஆகியவற்றுடன் பட்டியலிடுகிறது. வரிசைகளைத் தேர்ந்தெடுத்து அவற்றைத் திரும்பப் பெற திரும்பப் பெறு என்பதைத் தேர்ந்தெடுக்கவும். திரும்பப் பெறப்பட்ட டோக்கன்களை மீண்டும் பயன்படுத்த முடியாது. டோக்கனை உருவாக்கு என்பது புதிய ஒன்றை உருவாக்குகிறது.

  ![டோக்கனை உருவாக்கு படிவத்திற்கு மேலே உரிமையாளர், காலாவதி, கடைசிப் பயன்பாடு மற்றும் நிலையுடன் டோக்கன்களைப் பட்டியலிடும் டோக்கன்கள் தாவல்](../../images/console-tokens.png)
- **தணிக்கை** தணிக்கை வரிசைகளைப் புதியது முதலில் வருமாறு பட்டியலிடுகிறது, மேலும் பயனர், திறன் மற்றும் விளைவு ஆகியவற்றின் அடிப்படையில் வடிகட்டுகிறது.

  ![வடிகட்டிகளுடன் பயனர், டோக்கன், திறன் மற்றும் விளைவு ஆகியவற்றின் அடிப்படையில் அழைப்புகளைப் பட்டியலிடும் தணிக்கைத் தாவல்](../../images/console-audit.png)

## டோக்கன்கள்

ஒரு தனிப்பட்ட டோக்கன் அதன் உரிமையாளராக Cacti ஐப் படிக்கிறது. இது `cmcp_pat_` ஐத் தொடர்ந்து 64 சிற்றெழுத்து அறுபதின்ம எழுத்துக்களைக் கொண்ட வடிவத்தைக் கொண்டுள்ளது மற்றும் ஒற்றை வரம்பான `abilities:read` ஐக் கொண்டுள்ளது. அது எதைப் பார்க்க முடியும் என்பது டோக்கனால் அல்ல, அதன் உரிமையாளரின் Cacti பகுதிகள் மற்றும் சாதன அனுமதிகளால் தீர்மானிக்கப்படுகிறது. உரிமையாளர் **MCP மற்றும் திறன்கள் API** பகுதியைக் கொண்ட இயக்கப்பட்ட பயனராக இருக்க வேண்டும்.

டோக்கன்கள் எப்போதும் ஒரு பயனருக்காக உருவாக்கப்படுகின்றன, காலாவதியாகின்றன, மற்றும் திரும்பப் பெறப்படலாம்:

- **கன்சோல்.** மேலாண்மை > MCP > டோக்கன்கள் > டோக்கனை உருவாக்கு. ஆயுட்காலம் 1 முதல் 365 நாட்கள் வரை மற்றும் இயல்புநிலை 90 ஆகும். டோக்கன் சேவையகத்தால் உருவாக்கப்பட்டுப் பதில் பக்கத்தில் ஒரு முறை மட்டுமே காட்டப்படும், எனவே உடனடியாக அதை உங்கள் இரகசிய மேலாளரில் நகலெடுக்கவும். உங்களுக்காக ஒரு டோக்கனை உருவாக்கலாம். மற்றொரு பயனருக்கு ஒன்றை உருவாக்கப் பயனர்கள்/குழுக்கள் பகுதியும் தேவை, ஏனெனில் டோக்கன் அந்தப் பயனராக Cacti ஐப் படிக்கிறது.
- **எனது MCP டோக்கன்கள்.** MCP மற்றும் திறன்கள் API பகுதியைக் கொண்ட எந்தப் பயனரும் தங்கள் சொந்த டோக்கன்களை நிர்வகிக்கலாம்; கீழே காண்க.
- **கட்டளை வரி.** `tokens.php` ஆனது Cacti ஐ நிர்வகிக்கக்கூடிய ஒரு OS கணக்காக CLI இலிருந்து மட்டுமே இயங்கும். கட்டளை வரியிலோ செயல்முறைப் பட்டியலிலோ மதிப்பு ஒருபோதும் தோன்றாதபடி அது சூழலிலிருந்து டோக்கனைப் பெறுகிறது. ஆயுட்காலம் 1 முதல் 365 நாட்கள் வரை மற்றும் இயல்புநிலை 30 ஆகும். CLI க்கு Cacti பயனர் இல்லாததால், CLI வழியாக ஒரு டோக்கனை உருவாக்குவதும் திரும்பப் பெறுவதும் டோக்கனின் உரிமையாளரைச் செயல்படுபவராகக் கொண்டு கன்சோலைப் போலவே தணிக்கை செய்யப்படுகிறது, எனவே செயல் CLI இலிருந்து வந்ததாகத் தணிக்கை வரிசை குறிப்பதில்லை. `--list` ஒவ்வொரு டோக்கனையும் JSON ஆக (ஐடி, உரிமையாளர், வரம்புகள், நேரமுத்திரைகள், திரும்பப் பெறப்பட்ட கொடி) அச்சிடுகிறது மற்றும் டோக்கன் மதிப்பை ஒருபோதும் அச்சிடுவதில்லை; `--help` பயன்பாட்டைக் காட்டுகிறது.

  ```console
  export CACTI_MCP_TOKEN="$(printf 'cmcp_pat_%s\n' "$(openssl rand -hex 32)")"
  # Store this value in your secret manager before you end this shell session.
  php plugins/mcp/tokens.php --create=USERNAME --days=30
  php plugins/mcp/tokens.php --list
  php plugins/mcp/tokens.php --revoke=ID
  ```

விருந்தினர் கணக்கிற்கோ, முடக்கப்பட்ட பயனர்களுக்கோ, அல்லது **MCP மற்றும் திறன்கள் API** பகுதி இல்லாத பயனர்களுக்கோ, கன்சோல், கட்டளை வரி அல்லது எனது MCP டோக்கன்கள் ஆகியவற்றிலிருந்து டோக்கன்களை உருவாக்க முடியாது. Cacti விருந்தினர் அமைப்பை ஒரு பயனர்பெயராகவோ அல்லது பயனர் ஐடியாகவோ சேமிக்கிறது, மேலும் செருகுநிரல் இரண்டையும் தீர்க்கிறது. யாருடைய உரிமையாளர் விருந்தினர் கணக்காக மாறுகிறாரோ அந்த டோக்கன் அதன் அடுத்த கோரிக்கையில் வேலை செய்வதை நிறுத்திவிடும்.

### எனது MCP டோக்கன்கள்

மேலாண்மை > எனது MCP டோக்கன்கள் (`plugins/mcp/mcp_tokens.php`) க்கு எந்த நிர்வாகப் பகுதியும் தேவையில்லை: இது **MCP மற்றும் திறன்கள் API** பகுதியால் உள்ளடக்கப்பட்டுள்ளது, மேலும் அதை வைத்திருக்கும் பயனர்களுக்கு மட்டுமே பட்டியல் உள்ளீடு தோன்றும். இந்தப் பக்கம் எப்போதும் உள்நுழைந்த பயனரின் மீது செயல்படுகிறது. Cacti இன் பட்டியல் கன்சோலின் ஒரு பகுதியாகும், எனவே கன்சோல் அணுகல் இல்லாத பயனர் அதன் முகவரி மூலம் பக்கத்தை அடைகிறார்.

![உள்நுழைந்த பயனரின் டோக்கன்களையும் உருவாக்கும் படிவத்தையும் பட்டியலிடும் எனது டோக்கன்கள் தாவல்](../../images/my-tokens.png)

- **டோக்கன்கள்** உங்கள் டோக்கன்களைப் பட்டியலிடுகிறது, ஒன்றை உருவாக்குகிறது (1 முதல் 365 நாட்கள், இயல்புநிலை 90, பதிலில் ஒரு முறை காட்டப்படும்), மற்றும் உங்களுடையதைத் திரும்பப் பெறுகிறது. வேறொருவருடையதை உங்களால் பார்க்கவோ திரும்பப் பெறவோ முடியாது.
- **செயல்பாடு** நீங்கள் செய்த செயல்களைப் புதியது முதலில் வருமாறு பட்டியலிடுகிறது: உங்கள் டோக்கன்களுடன் செய்யப்பட்ட அழைப்புகள் மற்றும் நீங்கள் செய்த டோக்கன் மாற்றங்கள்.
- **கிடைக்கும் கருவிகள்** உங்கள் டோக்கன் இப்போது பயன்படுத்தக்கூடிய திறன்களை, ஒவ்வொரு திறனின் ஐடி, பெயர் மற்றும் விளக்கத்துடன் பட்டியலிடுகிறது. இது உங்கள் Cacti அனுமதிகளையும் நிர்வாகி தேர்ந்தெடுத்த வெளிப்பாடு அமைப்புகளையும் பின்பற்றுகிறது.

  ![ஒவ்வொரு திறனின் ஐடி, பெயர் மற்றும் விளக்கத்தைக் காட்டும் கிடைக்கும் கருவிகள் பட்டியல்](../../images/my-tools.png)

இந்தப் பக்கம் இருப்பதற்கு முன் செய்யப்பட்ட நிறுவலில் `mcp_tokens.php` இல்லாத பகுதி கோப்புப் பட்டியல் இருக்கும். நிறுவுதல் பட்டியலைப் பதிவு செய்கிறது; செருகுநிரலை இயக்குவதாலோ முடக்குவதாலோ இது புதுப்பிக்கப்படுவதில்லை. ஒரு செருகுநிரல் நிறுவல் நீக்கப்படும்போது Cacti பகுதி மானியங்களை நீக்குவதால், செருகுநிரலை நிறுவல் நீக்கி மீண்டும் நிறுவி, பின்னர் பகுதிகளை மீண்டும் வழங்கவும்.

தரவுத்தளம் டோக்கனின் SHA-256 ஹேஷை மட்டுமே சேமிக்கிறது, எனவே தொலைந்த டோக்கனை மீட்டெடுக்க முடியாது; அதைத் திரும்பப் பெற்று வேறொன்றை உருவாக்கவும். சுழற்சியும் அதே போன்றது: புதிய டோக்கனை உருவாக்கவும், கிளையன்ட்டை மாற்றவும், பின்னர் பழையதைத் திரும்பப் பெறவும். காலாவதியான டோக்கன், திரும்பப் பெறப்பட்ட டோக்கன், முடக்கப்பட்ட உரிமையாளர் அல்லது இழந்த பகுதி ஆகிய ஒவ்வொன்றும் அடுத்த கோரிக்கையில் தோல்வியடையும். டோக்கன்கள் `Authorization: Bearer` தலைப்பில் மட்டுமே ஏற்கப்படுகின்றன; வினவல் சரத்தில் அல்லது உள்ளடக்கத்தில் உள்ள டோக்கன் ஏற்கப்படுவதில்லை.

## கிளையன்ட்டை இணைக்கவும்

`Authorization: Bearer` தலைப்பில் டோக்கனுடன் `https://cacti.example.com/cacti/plugins/mcp/mcp.php` என்ற MCP முனையத்தைப் பயன்படுத்தவும். டோக்கனின் மதிப்பை ஒரு கோப்பில் எழுதுவதற்குப் பதிலாக, அதை ஒரு சூழல் மாறி அல்லது ரகசிய மேலாளரில் வைத்து, கிளையன்ட் உள்ளமைவிலிருந்து அதைக் குறிப்பிடவும்.

### Claude Code

டோக்கனைப் பெயரால் குறிப்பிடும் ஒரு திட்ட `.mcp.json` கோப்பில் முனையத்தை இடவும். Claude Code ஆனது `url` மற்றும் `headers` ஆகியவற்றில் `${VAR}` என்பதை விரிவுபடுத்தும், எனவே கோப்பில் எந்த ரகசியமும் இருக்காது மற்றும் commit செய்யப் பாதுகாப்பானது. Claude Code-ஐத் தொடங்கும் சூழலில் `CACTI_MCP_TOKEN` என்பதை ஏற்றுமதி செய்யவும்.

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

நீங்கள் இதை கட்டளை வரியிலிருந்தும் சேர்க்கலாம்:

```console
claude mcp add --transport http cacti https://cacti.example.com/cacti/plugins/mcp/mcp.php \
  --header "Authorization: Bearer $CACTI_MCP_TOKEN"
```

இரட்டை மேற்கோள்களுடன், உங்கள் ஷெல் முதலில் `$CACTI_MCP_TOKEN` என்பதை விரிவுபடுத்தும், எனவே தேர்ந்தெடுக்கப்பட்ட `--scope` (`local`, `user`, அல்லது `project`; இயல்புநிலை `local`) என்பதற்கான உள்ளமைவுக் கோப்பில் டோக்கன் மதிப்பு எழுதப்படும். அந்த வடிவத்தை `--scope project` உடன் பயன்படுத்த வேண்டாம், மேலும் அந்தக் கோப்பைப் பதிப்புக் கட்டுப்பாட்டிற்கு வெளியே வைத்திருக்கவும். மேலே உள்ள `.mcp.json` குறிப்பைத் தேர்ந்தெடுக்கவும். Claude Code தொலைநிலை `url` மற்றும் `headers` ஆகியவற்றில் சில நற்சான்றிதழ் மாறிகளை (`ANTHROPIC_AUTH_TOKEN` போன்றவை) காலியாகப் படிக்கிறது; `CACTI_MCP_TOKEN` அவற்றில் ஒன்றல்ல. ஆதாரம்: [Claude Code MCP ஆவணங்கள்](https://code.claude.com/docs/en/mcp).

### VS Code-இல் GitHub Copilot

பணியிட மூலத்தில் உள்ள `.mcp.json` (அல்லது பயனர் கோப்பு `~/.copilot/mcp-config.json`) என்பதைப் பயன்படுத்தவும். இந்த Copilot-இயல்புக் கோப்புகள் மேல்-நிலை `mcpServers` பொருளையையும், தலைப்பு மதிப்புகளில் `${NAME}` சூழல்-மாறி குறிப்புகளையும் பயன்படுத்துகின்றன:

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

VS Code-ஐத் தொடங்கும் சூழலில் `CACTI_MCP_TOKEN` என்பதை ஏற்றுமதி செய்யவும். இயல்பு Copilot கோப்புகள் `inputs` தூண்டுதல்களை ஆதரிக்காது. VS Code-இன் வழிகாட்டப்பட்ட அமைப்பு `${...}` மதிப்புகளை நிராகரிக்கிறது, எனவே வழிகாட்டப்பட்ட ஓட்டத்தின் மூலம் அல்லாமல் கோப்பைத் திருத்துவதன் மூலம் `Authorization` தலைப்பைச் சேர்க்கவும். சோதனை ரீதியான `chat.mcp.workspaceRootConfig.enabled` அமைப்பு இயக்கப்பட்டிருக்கும்போது மட்டுமே வழிகாட்டப்பட்ட அமைப்பு பணியிட மூலக் கோப்பை வழங்கும். [VS Code MCP உள்ளமைவுக் குறிப்பைப்](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) பார்க்கவும்.

**பழைய முறை: `.vscode/mcp.json`.** புதிய Copilot உள்ளமைவுகள் `.vscode/mcp.json` அல்லது சுயவிவர `mcp.json` ஆகியவற்றைப் பயன்படுத்தக் கூடாது என்று VS Code கூறுகிறது; அவை பிப்ரவரி 2027-இல் அகற்றப்படவுள்ள, வழக்கற்றுப் போன உள்ளூர் ஹார்னெஸ்ஸுக்கு உரியவை. நீங்கள் இன்னும் அதைப் பயன்படுத்தினால், எடிட்டரால் நிர்வகிக்கப்படும் வடிவம் மேல்-நிலை `servers` விசையைப் பெறுகிறது மற்றும் டோக்கனுக்காகக் கேட்க முடியும்:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "cacti-mcp-token",
      "description": "Cacti MCP token",
      "password": true
    }
  ],
  "servers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${input:cacti-mcp-token}"
      }
    }
  }
}
```

### stdio-ஐ மட்டுமே பேசும் கிளையன்ட்கள்

[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) என்பது உள்ளூர் stdio MCP சேவையகமாக இயங்கி செருகுநிரலின் HTTP API-ஐ அழைக்கும் ஒரு விருப்பத் தகவி ஆகும். தொலைநிலை HTTP சேவையகத்துடன் இணைக்க முடியாத கிளையன்ட்டுக்கு இதைப் பயன்படுத்தவும். இதற்கு அதே தனிப்பட்ட டோக்கன் தேவைப்படுகிறது மற்றும் இது `api.php` உடன் தொடர்பு கொள்கிறது.

### MCP செயல்பாடு

இந்த முனையம் கருவிகளை மட்டுமே வழங்குகிறது: வெளிப்படுத்தப்பட்ட, அனுமதிக்கப்பட்ட ஒவ்வொரு திறனும் அதன் அடையாள எண் பெயரால், அதன் உள்ளீடு மற்றும் வெளியீடு திட்டங்கள் மற்றும் படிக்க-மட்டுமான குறிப்புகளுடன் (`openWorldHint` என்பது `false`) ஒரு கருவியாக இருக்கும். இது `initialize`, `server/discover`, `ping`, `tools/list`, மற்றும் `tools/call` ஆகியவற்றைக் கையாளுகிறது. இது எந்த அமர்வையும் வைத்திருக்காது, `Mcp-Session-Id` என்பதை அனுப்பாது (பெறும் ஒன்றையும் புறக்கணிக்கும்), மேலும் JSON-RPC தொகுப்புகளை ஏற்காது. `id` இல்லாத ஒரு செய்தி அறிவிப்பாகும், மேலும் அது உள்ளடக்கம் இல்லாத HTTP 202 பதிலைப் பெறும். `POST` மட்டுமே அனுமதிக்கப்படுகிறது.

- **திருத்தங்கள்.** `params._meta` என்பதில் `io.modelcontextprotocol/protocolVersion` என்பதைக் கொண்டுள்ள ஒரு கோரிக்கை `2026-07-28` எனக் குறிப்பிட வேண்டும்; வேறு எதுவும் `-32022` பிழையைப் பெறும். அத்தகைய கோரிக்கைகள் பொருந்தக்கூடிய `Mcp-Protocol-Version`, `Mcp-Method`, மற்றும் (`tools/call` என்பதற்கு) `Mcp-Name` தலைப்புகளையும் கொண்டிருக்க வேண்டும், இல்லையெனில் பதில் `-32020` பிழையாக இருக்கும். மற்ற கோரிக்கைகள் `2025-11-25` ஆகக் கருதப்படுகின்றன: `initialize` அந்தத் திருத்தத்துடன் பதிலளிக்கிறது, மேலும் வேறு எந்த முறையிலும் `Mcp-Protocol-Version` தலைப்பு அனுப்பப்பட்டால், அது `2025-11-25`, `2025-06-18`, அல்லது `2025-03-26` ஆக இருக்க வேண்டும்.
- **கருவிப் பிழைகள்.** திட்டத்துடன் பொருந்தாத அளவுருக்கள் அல்லது JSON பொருளாக இல்லாத `arguments` மதிப்பு உட்பட ஒரு திறன் பிழை, நெறிமுறைப் பிழையாக இல்லாமல், `isError: true` மற்றும் `structuredContent` என்பதில் AIP-193 பிழையுடன் கூடிய கருவி முடிவாகத் திரும்ப வரும்.
- **நெறிமுறைப் பிழைகள்.** கருவிப் பிழைகள் அல்லாத தோல்விகள் JSON-RPC பிழைப் பொருள்களாகும் (`data` என்பதில் நிலை மற்றும் காரணத்துடன் கூடிய குறியீடு `-32000`, அல்லது நிலையான குறியீடுகள்): விடுபட்ட பொது Cacti URL, நிராகரிக்கப்பட்ட `Origin`, செருகுநிரல் முடக்கப்பட்டிருக்கும்போது அல்லது தொலைநிலை போல்லரில் வரும் கோரிக்கை, மற்றும் எதிர்பாராத சேவையகப் பிழைகள் (`-32603`, இதன் விவரம் பதிலில் அல்லாமல் Cacti பதிவில் எழுதப்படும்). முதலில் இயங்கும் கோரிக்கைச் சரிபார்ப்புகளும் (405, 413, 415) அங்கீகாரத் தோல்விகளும் (401 `INVALID_TOKEN`, 403 `REALM_REQUIRED`) HTTP API என்பதன் கீழ் விவரிக்கப்பட்டுள்ள AIP-193 உடலைத் தக்கவைத்துக் கொள்கின்றன.

## HTTP API

அடிப்படை URL: `https://cacti.example.com/cacti/plugins/mcp/api.php`. ஒப்பந்தம் [openapi.json](../../../openapi.json) என்பதில் உள்ளது.

| முறை மற்றும் பாதை | நோக்கம் |
| --- | --- |
| `GET /v1/abilities` | அனுமதிக்கப்பட்ட திறன்களைப் பட்டியலிடவும். வினவல்: `pageSize`, `pageToken`, மற்றும் `category = "inventory"` வடிவத்தில் `filter`. |
| `GET /v1/abilities/{id}` | ஒரு திறனைப் படிக்கவும். |
| `POST /v1/abilities/{id}:execute` | அதை இயக்கவும். உடல் சரியாக `{"arguments": {...}}` ஆக இருக்கும். பதில் `{"requestId": "...", "result": {...}}` ஆக இருக்கும். |

```console
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" \
  https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" -H 'Content-Type: application/json' \
  -d '{"arguments": {"filter": "state = \"DOWN\""}}' \
  'https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities/cacti-list-devices:execute'
```

பிழைகள் AIP-193-ஐப் பின்பற்றுகின்றன: `cacti.net` என்ற களத்தையும் நிலையான `reason` என்பதையும் கொண்ட `ErrorInfo`-ஐக் கொண்டுள்ள `code`, `message`, `status`, மற்றும் `details` ஆகியவற்றைக் கொண்ட ஒரு `error` பொருள். அளவுருச் சிக்கல்கள் புலத்தின் பெயரைக் குறிப்பிடும் ஒரு `BadRequest` விவரத்தைச் சேர்க்கின்றன. கோரிக்கை உடல்கள் 64 KB ஆகவும், முடிவுகள் 1 MB ஆகவும் வரையறுக்கப்பட்டுள்ளன. இரண்டு முனையங்களும் முதன்மை போல்லரில் மட்டுமே பதிலளிக்கின்றன, மேலும் செருகுநிரல் முடக்கப்பட்டிருக்கும்போது அல்லது சேவையகம் முதன்மை போல்லராக இல்லாதபோது `UNAVAILABLE` (`PLUGIN_UNAVAILABLE`) என்பதைத் திருப்பி அனுப்புகின்றன.

| HTTP | `reason` மதிப்புகள் |
| --- | --- |
| 400 | `INVALID_ARGUMENTS`, `INVALID_FILTER`, `INVALID_PAGE_TOKEN` |
| 401 | `INVALID_TOKEN` (`WWW-Authenticate: Bearer` என்பதையும் அனுப்புகிறது) |
| 403 | `REALM_REQUIRED` |
| 404 | `ABILITY_NOT_FOUND`, `DEVICE_NOT_FOUND`, `UNKNOWN_PATH` |
| 405 | `METHOD_NOT_ALLOWED` (`Allow` என்பதை அனுப்புகிறது) |
| 413 | `REQUEST_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR`, `INVALID_RESULT` |
| 503 | `AUDIT_UNAVAILABLE`, `PLUGIN_UNAVAILABLE`, `CACTI_UNAVAILABLE` |

## ஒரு திறனை எழுதுதல் (செருகுநிரல் ஆசிரியர்கள்)

இயக்கப்பட்ட ஒரு Cacti செருகுநிரல், வழக்கமாக அதன் `plugin_<slug>_install()` என்பதில், `abilities_register` கொக்கியுடன் அது இணைக்கும் ஒரு செயலியிலிருந்து திறன்களைப் பதிவு செய்கிறது:

```php
api_plugin_register_hook('acme', 'abilities_register', 'acme_abilities_register', 'setup.php');
```

இந்தச் செயலி செருகுநிரலுக்கு வரையறுக்கப்பட்ட `AbilitiesRegistrar` ஒன்றைப் பெறுகிறது. அதன் திரும்பும் மதிப்பு புறக்கணிக்கப்படுகிறது.

```php
function acme_abilities_register(AbilitiesRegistrar $registrar) : void {
	$registrar->registerCategory('acme-widgets', 'Widgets');

	$registrar->register('acme-get-widget-count', [
		'label'         => 'Get widget count',
		'description'   => 'Count the widgets the caller may see.',
		'category'      => 'acme-widgets',
		'input_schema'  => ['type' => 'object', 'properties' => new stdClass(), 'additionalProperties' => false],
		'output_schema' => [
			'type'                 => 'object',
			'properties'           => ['count' => ['type' => 'integer', 'minimum' => 0]],
			'required'             => ['count'],
			'additionalProperties' => false
		],
		'annotations' => ['readOnly' => true, 'destructive' => false, 'idempotent' => true],
		'permission'  => fn (int $userId) => is_realm_allowed(ACME_REALM_ID, $userId),
		'execute'     => fn (int $userId, stdClass $args) => ['count' => acme_count_widgets($userId)]
	]);
}
```

பதிவின்போது செயல்படுத்தப்படும் அனைத்து விதிகளும்:

- **அடையாள எண்கள்.** ஒரு அடையாள எண் `^[a-z][a-z0-9]*(-[a-z0-9]+){1,7}$` என்பதோடு பொருந்த வேண்டும், அதிகபட்சம் 64 எழுத்துகள் இருக்க வேண்டும், மேலும் மேலே உள்ள `acme-` போலச் செருகுநிரலின் ஸ்லக் மற்றும் ஒரு இடைக்கோட்டுடன் தொடங்க வேண்டும். ஸ்லக் என்பது செருகுநிரல் கோப்பகப் பெயராகும், எனவே `my_plugin` போன்ற கோப்பகத்தால் எதையும் பதிவு செய்ய முடியாது. `cacti` எனப் பெயரிடப்பட்ட செருகுநிரல் கோப்பகம் நிராகரிக்கப்படும்; அந்தப் பெயர்வெளி உள்ளமைக்கப்பட்டவற்றுக்கு உரியது.
- **வரையறை.** சரியாக இந்த விசைகள் இருக்க வேண்டும்: `label`, `description` (4096 பைட்டுகள் வரை), `category`, `input_schema`, `output_schema`, `annotations`, `permission`, `execute`. வகை ஏற்கனவே இருக்க வேண்டும்: உள்ளமைக்கப்பட்ட ஒன்றைப் (`inventory`, `system`) பயன்படுத்தவும் அல்லது `registerCategory()` மூலம் உங்களுடையதைப் பதிவு செய்யவும்; அதன் அடையாள எண் அனைத்து செருகுநிரல்களிலும் தனித்துவமானதாக இருக்க வேண்டும் மற்றும் `^[a-z][a-z0-9-]{0,31}$` என்பதோடு பொருந்த வேண்டும்.
- **படிக்க-மட்டும்.** `annotations` என்பது சரியாக `readOnly: true`, `destructive: false`, `idempotent: true` என இருக்க வேண்டும். வேறு எதுவும் பிழையை வீசும்.
- **திட்டங்கள்.** `input_schema` மற்றும் `output_schema` ஆகிய இரண்டும் மேல்-நிலை `type` `object` என்பதைக் கொண்டிருக்க வேண்டும். இந்த விதிமுறை சிறியது மற்றும் கடுமையாகச் சரிபார்க்கக்கூடியது. பொருள்கள் மூடப்பட்டிருக்க வேண்டும் (`additionalProperties: false`, மற்றும் `properties` இருக்க வேண்டும்); மற்ற வகைகள் `integer` மற்றும் `number` (`minimum`, `maximum`), `string` (`minLength`, `maxLength`, `enum`, `pattern`), `boolean`, மற்றும் `array` (`items` மற்றும் `maxItems` தேவை) ஆகும். ஒரு வகையை `['string', 'null']` என null ஏற்கக்கூடியதாக மாற்றலாம். அளவுரு சரங்கள் இயல்பாக அதிகபட்சம் 4096 எழுத்துகளுக்கு வரையறுக்கப்பட்டுள்ளன; முடிவுச் சரங்கள் அறிவிக்கப்பட்ட `maxLength` மற்றும் முடிவு அளவு வரம்பால் மட்டுமே கட்டுப்படுத்தப்படுகின்றன. அதிகபட்சம் 256 திறன்களை மட்டுமே பதிவு செய்ய முடியும்.
- **`permission(int $userId): bool`.** அனுமதிக்கச் சரியாக `true` என்பதைத் திருப்பி அனுப்ப வேண்டும். பயனர் அடையாள எண் டோக்கன் உரிமையாளருடையது; அமர்வு நிலையை ஒருபோதும் படிக்க வேண்டாம்.
- **`execute(int $userId, stdClass $args): array`.** `$args` ஏற்கனவே `input_schema` என்பதற்கு எதிராகச் சரிபார்க்கப்பட்டது. பொருள்-நிலை அனுமதிகளை நீங்களே செயல்படுத்தவும். `output_schema` என்பதோடு சரியாகப் பொருந்தும் ஒரு துணை அணியைத் திருப்பி அனுப்பவும்; ஒரு பட்டியல், கூடுதல் புலம், அல்லது 1 MB-க்கு அதிகமான JSON ஆகியவை `INVALID_RESULT` பிழையாக மாறும். `NOT_FOUND` போன்ற கிளையன்ட்டுக்குத் தெரியும் தோல்விக்கு `AbilitiesError` என்பதை வீசவும்.
- **காலியான பொருள்கள்.** PHP ஆனது `[]` என்பதை JSON அணியாகக் குறியாக்கம் செய்கிறது. வெளியீட்டுத் திட்டம் எந்த ஆழத்திலும் `object` ஒன்றை அறிவிக்கும் இடமெல்லாம், பதிவகம் `[]` என்பதைக் காலியான பொருளாகக் கருதி `{}` என்பதை அனுப்புகிறது; `new stdClass()` என்பதும் செயல்படும். காலியாக இல்லாத ஒரு பட்டியல் ஒருபோதும் பொருளாகக் கருதப்படாது மற்றும் `INVALID_RESULT` உடன் தோல்வியடையும். ஒரு திட்டத்தில் உள்ள காலியான `properties` வரைபடம் `[]` அல்லது `new stdClass()` ஆக இருக்கலாம்; இரண்டும் `{}` ஆக வெளியிடப்படுகின்றன.
- **தோல்வி தனிமைப்படுத்தல்.** ஒவ்வொரு செருகுநிரலும் ஒரு தற்காலிக நகலில் பதிவு செய்கிறது, உங்கள் செயலி இயல்பாகத் திரும்பினால் மட்டுமே அது தக்கவைக்கப்படும். அது பிழையை வீசினால், உங்கள் திறன்கள் எதுவும் பதிவு செய்யப்படாது, மேலும் தோல்வி பதிவு செய்யப்படும்.

செருகுநிரல்களிலிருந்து வரும் திறன்கள் மறைக்கப்பட்ட நிலையில் தொடங்கும். நிர்வாகி அவற்றை கன்சோலின் Abilities தாவலில் வெளிப்படுத்துவார், மேலும் அவற்றிற்கான Required Realm நெடுவரிசையில் "Set by the plugin" எனக் காட்டப்படும்.

## பாதுகாப்பு மாதிரி

- **Bearer டோக்கன் மட்டும்.** `api.php` மற்றும் `mcp.php` ஆகியவை `Authorization` தலைப்பில் உள்ள தனிப்பட்ட டோக்கனை மட்டுமே ஏற்கின்றன, வேறு எதையும் ஏற்காது. Cacti ஏற்றப்படுவதற்கு முன்பே இவை குக்கீகள், `$_POST`, மற்றும் `$_REQUEST` ஆகியவற்றை நீக்கி, Cacti தொடங்கும் அமர்வை அழித்துவிடுகின்றன; எனவே உலாவி உள்நுழைவு ஒருபோதும் API அணுகலை வழங்காது.
- **CSRF மாற்று வழி.** Cacti-யின் CSRF பாதுகாப்பு, Cacti CSRF டோக்கன் இல்லாத JSON POST கோரிக்கையை நிராகரிக்கிறது; ஆனால் எந்தவொரு MCP கிளையண்டாலும் அதை அனுப்ப முடியாது. இந்த இரண்டு முனையங்களுக்கு மட்டும், Cacti ஏற்றப்படுவதற்கு முன்பு செருகுநிரல் கோரிக்கை முறையை மறுபெயரிட்டு, பின்னர் அதை மீட்டமைக்கிறது; இதனால் பாதுகாப்பு சோதனை இவற்றைத் தவிர்க்கிறது. உலாவி குக்கீகள் மூலம் அங்கீகரிக்கும் கோரிக்கைகளை மட்டுமே CSRF பாதுகாக்கிறது என்பதாலும், இந்த முனையங்கள் எந்த குக்கீ அடையாளத்தையும் ஏற்பதில்லை என்பதாலும் இது பாதுகாப்பானது: ஒரு குறுக்கு-தள பக்கத்தால் bearer டோக்கனை இணைக்க முடியாது. கன்சோல் பக்கங்கள் முழுமையான CSRF பாதுகாப்பைத் தொடர்ந்து கொண்டிருக்கும். Cacti ஆதரிக்கப்படும் விலக்கு அளிக்கும் வரை இந்த மாற்று வழி தற்காலிகமானது; `lib/bootstrap.php` ஐப் பார்க்கவும்.
- **Origin சரிபார்ப்பு.** `mcp.php` இல், கோரிக்கையில் `Origin` தலைப்பு இருந்தால், அது Public Cacti URL-இன் scheme, host, மற்றும் port ஆகியவற்றுடன் துல்லியமாகப் பொருந்த வேண்டும்; இல்லையெனில் கோரிக்கை `ORIGIN_NOT_ALLOWED` உடன் நிராகரிக்கப்படும். உலாவி அல்லாத கிளையண்டுகள் இணைக்கும் முறையான, `Origin` தலைப்பு இல்லாத கோரிக்கை அனுமதிக்கப்படும். இது பார்வையாளரின் உலாவியிலிருந்து ஒரு வலைப்பக்கம் இந்த முனையத்தை இயக்குவதைத் தடுக்கிறது. `api.php` இந்தச் சரிபார்ப்பைப் பயன்படுத்துவதில்லை.
- **படிக்க மட்டும் மட்டுமே.** படிக்க மட்டும், அழிவற்ற, மற்றும் தன்னிலை மாற்றாத தன்மையில் இல்லாத எந்தவொரு திறனையும் பதிவு நிராகரிக்கிறது.
- **வெளிப்பாடு மற்றும் பகுதிகள் இரண்டும் பொருந்தும்.** ஒரு திறன் வெளிப்படுத்தப்பட்டிருக்க வேண்டும் மற்றும் டோக்கன் உரிமையாளர் அதற்கான பகுதியை வைத்திருக்க வேண்டும். வெளிப்பாட்டு அட்டவணையைப் படிக்க முடியாவிட்டால், இயல்புநிலைகளுக்குத் திரும்புவதற்குப் பதிலாக ஒவ்வொரு திறனும் மறைக்கப்படும்.
- **மறைக்கப்பட்டவை, அறியப்படாதவை, மற்றும் அனுமதியற்றவை ஒரே மாதிரியாகத் தோன்றும்.** ஒரு திறன் இல்லையா, மறைக்கப்பட்டுள்ளதா, அல்லது அதன் பயனர் அதைப் பயன்படுத்த முடியாதா என்பதை ஒரு கிளையண்டால் வேறுபடுத்தி அறிய முடியாது: கண்டறிதல் அதைத் தவிர்க்கிறது மற்றும் செயல்படுத்தல் `NOT_FOUND` (`ABILITY_NOT_FOUND`) ஐத் திருப்பி அனுப்புகிறது.
- **டோக்கன்கள்.** SHA-256 ஹேஷ்களாகச் சேமிக்கப்படுகின்றன, ஒருமுறை மட்டுமே காட்டப்படுகின்றன, எப்போதும் காலாவதியாகும் தன்மை கொண்டவை, ரத்து செய்யக்கூடியவை, மேலும் உரிமையாளர் முடக்கப்படும்போது அல்லது பகுதியை இழக்கும்போது நிராகரிக்கப்படுகின்றன.
- **தணிக்கை.** `plugin_mcp_audit` என்பது கோரிக்கை ID, டோக்கன் ID, பயனர் ID, திறன், முடிவு (`started`, `succeeded`, `failed`, `denied`, `rejected`), மற்றும் நேர முத்திரைகளைப் பதிவு செய்கிறது. இது ஒருபோதும் அளவுருக்கள், முடிவுகள், அல்லது டோக்கன் மதிப்புகளைப் பதிவு செய்வதில்லை. அதன் `started` வரி எழுதப்பட்ட பிறகே ஒரு திறன் இயங்கும்; தணிக்கை அட்டவணை கிடைக்கவில்லை என்றால் அழைப்பு `UNAVAILABLE` உடன் தோல்வியடையும் மற்றும் இயங்காது. இயங்குவதற்கு முன்பே நிராகரிக்கப்படும் அழைப்பு ஒரு வரியாகப் பதிவாகும்: அறியப்படாத, மறைக்கப்பட்ட, அல்லது அனுமதியற்ற திறனுக்கு `denied`, மற்றும் schema-வில் தோல்வியடையும் அளவுருக்களுக்கு `rejected`. கன்சோல், My MCP Tokens, மற்றும் CLI வழியாகச் செய்யப்படும் டோக்கன் உருவாக்கம் மற்றும் ரத்து செய்தல் ஆகியவை `succeeded` முடிவுடன் `mcp-token-create` மற்றும் `mcp-token-revoke` எனப் பதிவு செய்யப்படுகின்றன, மேலும் ரத்து செய்தல் செயல்பாட்டில் இருந்த டோக்கனுக்கு மட்டுமே பதிவு செய்யப்படும். கண்டறிதல், மற்றும் `arguments` என்பது JSON பொருளாக இல்லாத அழைப்பு ஆகியவை பதிவு செய்யப்படுவதில்லை.
- **தோல்விப் பதிவு.** எதிர்பாராத தோல்வி, `INVALID_RESULT`, அல்லது கிடைக்காத தணிக்கை அட்டவணை ஆகியவை Cacti பதிவில் `MCP` வசதியுடன் ஒரு வரியை எழுதும்: திறன் ID, நிலையான காரணம், மற்றும் விதிவிலக்கு வகுப்பு. செய்திகள், அளவுருக்கள், மற்றும் டோக்கன்கள் ஒருபோதும் பதிவு செய்யப்படுவதில்லை.
- **முதன்மைப் போலர் மட்டும்.** இரண்டு முனையங்களும், இரண்டு கன்சோல் பக்கங்களும், மற்றும் `tokens.php` ஆகியவை வேறு எங்கும் செயல்பட மறுக்கின்றன.

## வாழ்க்கைச் சுழற்சி

செருகுநிரலை முடக்குவது இரண்டு முனையங்களையும் தடுக்கும். நிறுவல் நீக்குவது ஒவ்வொரு டோக்கனையும் ரத்து செய்து, தரவு தக்கவைப்பிற்காக மூன்று அட்டவணைகளையும் (`plugin_mcp_token`, `plugin_mcp_audit`, `plugin_mcp_ability`) வைத்திருக்கும்; மீண்டும் நிறுவுவது ரத்து செய்யப்பட்ட டோக்கனை மீண்டும் செயல்படுத்தாது. Cacti தரவுத்தளத்துடன் சேர்த்து இந்த அட்டவணைகளையும் காப்புப் பிரதி எடுத்து, செருகுநிரலுக்கு வெளியே ஒரு தணிக்கைத் தக்கவைப்புக் கொள்கையைப் பயன்படுத்தவும்.

## உருவாக்கம் மற்றும் சோதனைகள்

சோதனைகள் என்பவை Cacti இல்லாமலேயே இயங்கும் எளிய PHP ஸ்கிரிப்டுகள் ஆகும்:

```console
for t in tests/*.php; do php "$t" || break; done
git archive --format=tar.gz --prefix=mcp/ HEAD > mcp.tar.gz
```

CI ஆனது PHP 8.2 முதல் 8.5 வரை PHP குறியீட்டை lint செய்து `tests/` இல் உள்ள ஸ்கிரிப்டுகளை இயக்குகிறது (ஒவ்வொன்றும் `.github/workflows/ci.yml` இல் பட்டியலிடப்பட்டுள்ளது), பின்னர் நிறுவக்கூடிய `mcp/` காப்பகத்தையும் அதன் checksum-ஐயும் உருவாக்குகிறது. Cacti-ஐத் தொடும் சோதனைகள் Cacti உதவி எல்லையில் fixtures-ஐப் பயன்படுத்துகின்றன; அவை முழுமையான Cacti நிறுவலைச் சோதிப்பதில்லை.

### ஒருங்கிணைப்புச் சோதனைகள்

`tests/integration/run.sh 1.2.31` அல்லது `tests/integration/run.sh develop` என்பது கொள்கலன்களில் உள்ள உண்மையான Cacti-இல் செருகுநிரலை நிறுவி அதற்கு எதிராக நேரடிச் சரிபார்ப்புகளை இயக்குகிறது. இதற்கு Compose v2.23.1 அல்லது அதற்குப் பிந்தைய பதிப்பு கொண்ட Docker, git மற்றும் openssl தேவை. பிழைதிருத்தத்திற்காக stack-ஐத் தொடர்ந்து இயக்க `KEEP=1` உதவுகிறது. CI இதை இரவுதோறும் மற்றும் தேவைப்படும்போது மட்டுமே இயக்குகிறது, pull request-களில் இயக்குவதில்லை.

## உள்ளூர்மயமாக்கல்

Cacti MCP ஆனது `mcp` உரைத் களத்தைப் (`locales/po/mcp.pot`) பயன்படுத்தி, `locales/po/` மற்றும் `locales/LC_MESSAGES/` இன் கீழ் தொகுக்கப்பட்ட GNU gettext பட்டியல்களையும், ஆங்கிலம் மற்றும் 44 மொழிகளுக்கான (19 Broad Tier 1, 15 ஆப்பிரிக்க, மற்றும் 10 ஆசிய மொழிகள்) உள்ளூர்மயமாக்கப்பட்ட README-களையும் `docs/i18n/` இன் கீழ் வழங்குகிறது. மொழி ஆதரவு இயக்கப்படும்போது Cacti பொருத்தமான பட்டியலைத் தானாகவே ஏற்றும்.

## பங்களித்தல்

Pull request-கள் `develop` கிளைக்குச் செல்ல வேண்டும். தயாரிப்புக் குறியீட்டை PHP 8.2 உடன் இணக்கமாக வைத்திருங்கள் மற்றும் Cacti-யின் பாணியைப் பயன்படுத்துங்கள்: tab-கள், ஒற்றை மேற்கோள் சரங்கள், மற்றும் Cacti-யின் தரவுத்தளம் மற்றும் அனுமதி உதவிகள். மாற்றப்பட்ட சரிபார்ப்பு, அங்கீகாரம், அல்லது நெறிமுறை நடத்தைக்கான சோதனைகளைச் சேர்த்து, `git commit -s` உடன் கமிட்களில் கையொப்பமிடுங்கள். HTTP API-க்கான மாற்றங்களை [cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) உடன் ஒருங்கிணைக்கவும்.
