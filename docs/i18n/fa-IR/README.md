Cacti MCP یک افزونه برای Cacti است که به کلاینت‌های هوش مصنوعی امکان می‌دهد داده‌های Cacti شما را از طریق عملیات نام‌گذاری‌شده و فیلترشده بر اساس سطح دسترسی به نام «قابلیت‌ها» (abilities) بخوانند. این افزونه قابلیت‌ها را به دو روش از درون خود افزونه ارائه می‌دهد: یک نقطه پایانی MCP (`mcp.php`، از نوع Streamable HTTP) و یک API مبتنی بر HTTP به سبک AIP (`api.php`). کنترل صدور مجوز و اجرا همچنان بر عهده Cacti باقی می‌ماند. کلاینت هرگز مستقیماً از پایگاه داده پرس‌وجو نمی‌کند؛ بلکه فقط می‌تواند قابلیتی را فراخوانی کند که مدیر سیستم آن را در دسترس قرار داده باشد و قلمروهای (realms) Cacti متعلق به مالک توکن اجازه آن را بدهند.

نویسندگان افزونه‌ها می‌توانند قابلیت‌های فقط‌خواندنی خود را از طریق قلاب `abilities_register` ثبت کنند و این قابلیت‌ها بدون نیاز به هیچ کد پروتکلی، به‌عنوان ابزار در اختیار کلاینت‌های MCP قرار می‌گیرند.

**وضعیت: پیش‌انتشار، نسخه 0.1.0.** هنوز هیچ انتشار برچسب‌گذاری‌شده‌ای (tagged release) وجود ندارد.

امکانات موجود در حال حاضر:

- قابلیت‌های توکار فقط‌خواندنی برای نسخه‌های سیستم و فهرست موجودی دستگاه‌ها.
- توکن‌های دسترسی شخصی (`cmcp_pat_...`) به‌عنوان تنها گواهی احراز هویت.
- کنسول «مدیریت > MCP»: در دسترس قرار دادن یا پنهان‌کردن قابلیت‌ها، ایجاد و لغو توکن‌ها، و خواندن گزارش ممیزی.
- «مدیریت > توکن‌های MCP من»: کاربران توکن‌های خودشان را مدیریت می‌کنند، فعالیت خود را می‌بینند و مشاهده می‌کنند که توکن‌هایشان از کدام ابزارها می‌توانند استفاده کنند.
- پشتیبانی از MCP روی Streamable HTTP، نسخه‌های پروتکل `2026-07-28` و `2025-11-25`، فقط برای ابزارها.

امکانات غیرفعال در حال حاضر:

- ورود با OAuth 2.1. رابط‌های میزبانی‌شده‌ای که نمی‌توانند توکن شخصی ارسال کنند، مانند رابط‌های سفارشی ChatGPT و claude.ai، تا زمان پیاده‌سازی این قابلیت نمی‌توانند متصل شوند. این مورد به‌عنوان طرح ۲ برنامه‌ریزی شده است و هنوز نوشته نشده است.
- قابلیت‌های نوشتن. فقط قابلیت‌های فقط‌خواندنی امکان ثبت دارند.

طراحی در [مشخصات طراحی نقطه پایانی](../../superpowers/specs/2026-11-19-mcp-endpoint-design.md) و ترتیب ساخت در [docs/plan.md](../../plan.md) آمده است.

## قابلیت‌های توکار

| شناسه | آرگومان‌ها | قلمرو Cacti موردنیاز |
| --- | --- | --- |
| `cacti-get-system-info` | ندارد | 15 |
| `cacti-list-devices` | اختیاری: `pageSize`، `pageToken`، `filter`، `orderBy` | 3 |
| `cacti-get-device` | الزامی: `name`، مانند `devices/12` | 3 |

هر فراخوانی همچنین به قلمرو **MCP and Abilities API** برای مالک توکن، دامنه `abilities:read` (که هر توکن شخصی آن را دارد) و در دسترس بودن قابلیت نیاز دارد. زبانه «قابلیت‌ها» در کنسول، قلمرو موردنیاز هر قابلیت توکار را نشان می‌دهد.

- قابلیت `cacti-list-devices` صفحه‌هایی تا حداکثر ۱۰۰ دستگاه (به‌صورت پیش‌فرض ۵۰) و یک `nextPageToken` برمی‌گرداند. توکن صفحه فقط برای همان `filter` و `orderBy` معتبر است. `filter` یک عبارت AIP-160 از مقایسه‌هایی است که با `AND` به هم متصل شده‌اند، برای مثال `state = "DOWN" AND disabled = false`. فیلدهای فیلتر عبارت‌اند از `displayName`، `hostname`، `disabled`، `site`، `poller`، `deviceTemplate`، `externalId` و `state`. پارامتر `orderBy` مقادیر `displayName`، `hostname` یا `name` را می‌پذیرد که هر کدام می‌تواند به‌صورت اختیاری با `desc` همراه شود.
- پرس‌وجوهای دستگاه از طریق تابع `get_allowed_devices()` در Cacti انجام می‌شوند، بنابراین کاربر فقط دستگاه‌هایی را می‌بیند که Cacti به او نمایش می‌دهد.
- فیلدهای دستگاه شامل رشته‌های community مربوط به SNMP، عبارت‌های عبور و سایر اطلاعات محرمانه نمی‌شوند.

## نصب

نیازمند Cacti نسخه 1.2.31 یا جدیدتر، PHP نسخه 8.2 یا جدیدتر و poller اصلی است. احراز هویت Cacti باید فعال باشد؛ در صورت غیرفعال بودن، افزونه از احراز هویت خودداری می‌کند.

نام پوشه افزونه باید `mcp` باشد، نه `plugin_mcp`. نام کوتاه افزونه، نام قلمروها، دامنه ترجمه و نشانی‌ها همگی از `mcp` استفاده می‌کنند.

از طریق دریافت کد منبع:

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_mcp.git mcp
```

تا زمانی که انتشارهای برچسب‌گذاری‌شده وجود ندارند، می‌توانید به‌جای آن آرتیفکت `mcp-plugin` را از یک [اجرای CI](https://github.com/somethingwithproof/plugin_mcp/actions/workflows/ci.yml) موفق بارگیری کنید. این آرتیفکت شامل `mcp.tar.gz` و `SHA256SUMS` است. مقدار کنترلی (checksum) را بررسی کنید، سپس `mcp.tar.gz` را درون پوشه `plugins/` در Cacti استخراج کنید تا مسیر نهایی به صورت `plugins/mcp/` باشد. بایگانی‌های خودکار کد منبع در GitHub از نام پوشه سطح بالای متفاوتی استفاده می‌کنند. این بایگانی فاقد `docs/` (از جمله تصویرهای زیر)، `tests/` و `.github/` است، بنابراین پیوندهای README به `docs/` در GitHub کار می‌کنند ولی در نسخه نصب‌شده کار نمی‌کنند.

سپس:

1. در بخش مدیریت افزونه‌ها، **Cacti MCP** را نصب و فعال کنید. مدیری که افزونه را نصب می‌کند به‌صورت خودکار قلمرو **MCP Administration** را دریافت می‌کند.
2. در مسیر تنظیمات > MCP، مقدار **نشانی عمومی Cacti** (Public Cacti URL) را روی آدرسی که کلاینت‌ها استفاده می‌کنند تنظیم کنید، برای مثال `https://cacti.example.com/cacti`. استفاده از HTTPS به‌جز برای `localhost`، `127.0.0.1` و `[::1]` الزامی است. تا زمانی که این مقدار تنظیم نشود، `mcp.php` با کد HTTP 400 و یک خطای JSON-RPC پاسخ می‌دهد که مقدار `data` آن برابر با `FAILED_PRECONDITION` و `PUBLIC_URL_REQUIRED` است. فایل `api.php` این مقدار را نمی‌خواند.

   ![تنظیمات > MCP که فیلد نشانی عمومی Cacti را نشان می‌دهد](../../images/settings-public-url.png)

3. قلمرو **MCP and Abilities API** را به هر کاربری که مالک یک توکن خواهد بود اعطا کنید. هیچ کاربری این قلمرو را به‌صورت خودکار دریافت نمی‌کند.
4. اطمینان حاصل کنید که وب‌سرور سرآیند `Authorization` و اطلاعات مسیر (path info) را به PHP ارسال می‌کند (بخش زیر را ببینید).
5. بخش مدیریت > MCP را باز کنید و قابلیت‌هایی را که می‌خواهید کلاینت‌ها ببینند در دسترس قرار دهید.

**ارتقا از یک نسخه توسعه‌ای.** این افزونه در مرحله پیش‌انتشار است و جدول‌های آن در طول توسعه بدون اسکریپت‌های مهاجرت تغییر کرده‌اند. اگر نسخه قبلی را نصب کرده بودید، آن را حذف نصب (uninstall) و دوباره نصب کنید. نصب مجدد جدول‌هایی را که از قبل وجود دارند نگه می‌دارد، بنابراین ابتدا جدول‌های قدیمی `plugin_mcp_token`، `plugin_mcp_audit` و `plugin_mcp_ability` (و جدول‌های معادل از نسخه‌های پیش از تغییر نام) را حذف کنید. اگر به تاریخچه آن‌ها نیاز دارید از آن‌ها نسخه پشتیبان بگیرید؛ توکن‌های آن نسخه‌ها هنگام حذف نصب لغو می‌شوند و به نسخه جدید منتقل نمی‌گردند.

### وب‌سرور

تنظیمات Apache که پیش از رسیدن درخواست به PHP سرآیند `Authorization` را حذف می‌کنند، به این تنظیم در میزبان مجازی (virtual host) یا پوشه مربوطه و سپس بارگذاری مجدد سرویس نیاز دارند:

```apache
SetEnvIf Authorization "(.+)" HTTP_AUTHORIZATION=$1
```

سرور Apache با `mod_php` مسیرهای `api.php` را بدون نیاز به پیکربندی اضافه برای مسیر سرویس‌دهی می‌کند.

مسیرهای `api.php` در ادامه مسیر پس از نام اسکریپت قرار دارند (`/plugins/mcp/api.php/v1/abilities`)، بنابراین nginx باید نشانی‌هایی را که در آن‌ها بعد از `.php` ادامه مسیر وجود دارد تطبیق دهد، اطلاعات مسیر را جدا کند و آن را به PHP بفرستد. یک بلوک `location ~ \.php$` هرگز با این نشانی‌ها تطبیق نمی‌یابد و nginx با صفحه 404 HTML خودش پاسخ می‌دهد. الگوی location و دو خط مربوط به path-info در زیر با PHP-FPM آزمایش و تأیید شده‌اند؛ سایر خط‌ها تنظیمات متداول استاندارد هستند:

```nginx
location ~ \.php(/|$) {
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php-fpm.sock;   # your PHP-FPM socket or host:port
}
```

خط‌های `include` و `fastcgi_pass` را طوری تنظیم کنید که با بلوکی که از قبل Cacti را سرویس‌دهی می‌کند مطابقت داشته باشند. دستور `try_files $fastcgi_script_name =404;` را به این بلوک اضافه نکنید: این دستور مقدار `$fastcgi_path_info` را پاک می‌کند و در نتیجه `api.php` پاسخ 404 با خطای `UNKNOWN_PATH` برمی‌گرداند. اگر پیکربندی شما به `try_files` نیاز دارد، ابتدا مقدار را با `set $path_info $fastcgi_path_info;` ذخیره کنید و سپس `fastcgi_param PATH_INFO $path_info;` را ارسال کنید.

فایل `mcp.php` مسیرهای زیرشاخه‌ای ندارد و به این تنظیمات نیازی ندارد.

## کنسول

بخش مدیریت > MCP دارای سه زبانه است. برای دسترسی به آن به قلمرو **MCP Administration** نیاز دارید. تصویرهای اینجا و بخش‌های بعدی از یک نسخه توسعه‌ای Cacti با داده‌های نمونه گرفته شده‌اند.

- **قابلیت‌ها** (Abilities) هر قابلیت ثبت‌شده را به همراه افزونه، دسته‌بندی، قلمرو موردنیاز و وضعیت در دسترس بودن آن فهرست می‌کند. ردیف‌ها را انتخاب کرده و گزینه نمایش (Expose) یا پنهان‌کردن (Hide) را بزنید؛ پیش از اعمال تغییر باید تأیید کنید. قابلیت‌های توکار `cacti-*` به‌صورت پیش‌فرض در دسترس هستند. قابلیت‌های سایر افزونه‌ها در ابتدا پنهان هستند، بنابراین نصب یک افزونه هیچ چیزی را منتشر نمی‌کند تا زمانی که مدیر تصمیم بگیرد. در دسترس قرار دادن فقط دسترسی را محدودتر می‌کند: کاربر همچنان به قلمرو مربوط به آن قابلیت نیاز دارد.

  ![زبانه قابلیت‌ها که قابلیت‌های توکار را به همراه قلمروها و وضعیت در دسترس بودن آن‌ها فهرست می‌کند](../../images/console-abilities.png)
- **توکن‌ها** (Tokens) توکن‌ها را به همراه مالک، سازنده، زمان ایجاد، انقضا، آخرین استفاده و وضعیت (فعال، منقضی‌شده، لغوشده) فهرست می‌کند. ردیف‌ها را انتخاب کرده و برای لغو آن‌ها گزینه لغو (Revoke) را بزنید. توکن‌های لغوشده دوباره قابل استفاده نیستند. گزینه ایجاد توکن (Create Token) یک توکن جدید می‌سازد.

  ![زبانه توکن‌ها که توکن‌ها را با مالک، انقضا، آخرین استفاده و وضعیت در بالای فرم ایجاد توکن فهرست می‌کند](../../images/console-tokens.png)
- **ممیزی** (Audit) ردیف‌های ممیزی را از جدیدترین به قدیمی‌ترین فهرست می‌کند و بر اساس کاربر، قابلیت و نتیجه فیلتر می‌شود.

  ![زبانه ممیزی که فراخوانی‌ها را با کاربر، توکن، قابلیت و نتیجه به همراه فیلترها فهرست می‌کند](../../images/console-audit.png)

## توکن‌ها

یک توکن شخصی به عنوان مالک خود به خواندن داده‌های Cacti می‌پردازد. قالب آن شامل `cmcp_pat_` به همراه ۶۴ نویسه هگزادسیمال با حروف کوچک است و فقط یک دامنه یعنی `abilities:read` را حمل می‌کند. آنچه این توکن می‌تواند ببیند بر اساس قلمروها و مجوزهای دستگاه مالک در Cacti تعیین می‌شود، نه خود توکن. مالک باید یک کاربر فعال باشد که دارای قلمرو **MCP and Abilities API** است.

توکن‌ها همیشه برای یک کاربر ساخته می‌شوند، تاریخ انقضا دارند و قابل لغو هستند:

- **کنسول.** مدیریت > MCP > توکن‌ها > ایجاد توکن. طول عمر توکن ۱ تا ۳۶۵ روز و به‌صورت پیش‌فرض ۹۰ روز است. توکن توسط سرور تولید می‌شود و فقط یک بار در صفحه پاسخ نمایش داده می‌شود، بنابراین بلافاصله آن را در مدیر رمزهای محرمانه خود کپی کنید. می‌توانید برای خودتان توکن بسازید. ساخت توکن برای کاربر دیگر نیازمند قلمرو Users/Groups نیز هست، زیرا توکن با هویت آن کاربر اطلاعات Cacti را می‌خواند.
- **توکن‌های MCP من.** هر کاربری که قلمرو MCP and Abilities API را داشته باشد می‌تواند توکن‌های خودش را مدیریت کند؛ بخش زیر را ببینید.
- **خط فرمان.** فایل `tokens.php` فقط از طریق CLI و با یک حساب کاربری سیستم‌عامل که مجوز مدیریت Cacti را دارد اجرا می‌شود. این ابزار توکن را از متغیرهای محیطی می‌خواند تا مقدار توکن هرگز در خط فرمان یا فهرست پردازش‌ها ظاهر نشود. طول عمر آن ۱ تا ۳۶۵ روز و به‌صورت پیش‌فرض ۳۰ روز است. ایجاد و لغو یک توکن از طریق CLI نیز مانند کنسول ممیزی می‌شود و مالک توکن به‌عنوان عامل ثبت می‌گردد، زیرا CLI کاربر Cacti ندارد؛ بنابراین ردیف ممیزی نشان نمی‌دهد که اقدام از طریق CLI انجام شده است. گزینه `--list` همه توکن‌ها را به صورت JSON (شناسه، مالک، دامنه‌ها، برچسب‌های زمانی، پرچم لغوشده) چاپ می‌کند و هرگز مقدار توکن را نمایش نمی‌دهد؛ گزینه `--help` راهنمای استفاده را نشان می‌دهد.

  ```console
  export CACTI_MCP_TOKEN="$(printf 'cmcp_pat_%s\n' "$(openssl rand -hex 32)")"
  # Store this value in your secret manager before you end this shell session.
  php plugins/mcp/tokens.php --create=USERNAME --days=30
  php plugins/mcp/tokens.php --list
  php plugins/mcp/tokens.php --revoke=ID
  ```

امکان ایجاد توکن برای حساب مهمان (guest)، کاربران غیرفعال یا کاربرانی که قلمرو **MCP and Abilities API** را ندارند، نه از کنسول، نه از خط فرمان و نه از بخش «توکن‌های MCP من» وجود ندارد. Cacti تنظیمات مهمان را به‌صورت نام کاربری یا شناسه کاربری ذخیره می‌کند و افزونه هر دو را تشخیص می‌دهد. توکنی که مالک آن به حساب مهمان تبدیل شود، در درخواست بعدی از کار می‌افتد.

### توکن‌های MCP من

بخش «مدیریت > توکن‌های MCP من» (`plugins/mcp/mcp_tokens.php`) نیازی به قلمرو مدیریت ندارد: با قلمرو **MCP and Abilities API** پوشش داده می‌شود و گزینه منو فقط برای کاربرانی ظاهر می‌شود که این قلمرو را دارند. این صفحه همیشه روی کاربر واردشده عمل می‌کند. منوی Cacti بخشی از کنسول است، بنابراین کاربری که به کنسول دسترسی ندارد می‌تواند با نشانی مستقیم به این صفحه برسد.

![زبانه توکن‌های من که توکن‌های کاربر واردشده و فرم ایجاد را فهرست می‌کند](../../images/my-tokens.png)

- **توکن‌ها** توکن‌های شما را فهرست می‌کند، توکن جدید می‌سازد (۱ تا ۳۶۵ روز، پیش‌فرض ۹۰ روز، فقط یک بار در پاسخ نمایش داده می‌شود) و توکن‌های خودتان را لغو می‌کند. شما نمی‌توانید توکن‌های هیچ فرد دیگری را ببینید یا لغو کنید.
- **فعالیت‌ها** اقداماتی را که انجام داده‌اید از جدیدترین به قدیمی‌ترین فهرست می‌کند: فراخوانی‌های انجام‌شده با توکن‌های شما و تغییراتی که روی توکن‌ها داده‌اید.
- **ابزارهای دردسترس** قابلیت‌هایی را فهرست می‌کند که یک توکن متعلق به شما همین الان می‌تواند از آن‌ها استفاده کند، به همراه شناسه، نام و توضیحات هر قابلیت. این فهرست از مجوزهای Cacti شما و تنظیمات در دسترس بودن انتخاب‌شده توسط مدیر پیروی می‌کند.

  ![فهرست ابزارهای دردسترس که شناسه، نام و توضیحات هر قابلیت را نشان می‌دهد](../../images/my-tools.png)

نصب‌هایی که پیش از وجود این صفحه انجام شده‌اند، فهرست فایل‌های قلمرویی بدون `mcp_tokens.php` دارند. فرآیند نصب این فهرست را ثبت می‌کند؛ فعال یا غیرفعال کردن افزونه آن را به‌روزرسانی نمی‌کند. افزونه را حذف نصب و دوباره نصب کنید و سپس قلمروها را مجدداً اعطا کنید، زیرا Cacti هنگام حذف نصب افزونه، اعطاهای قلمرو را پاک می‌کند.

پایگاه داده فقط درهم‌ساز (هش) SHA-256 توکن را ذخیره می‌کند، بنابراین توکن گم‌شده قابل بازیابی نیست؛ آن را لغو کرده و یکی دیگر بسازید. چرخش توکن (rotation) نیز به همین شکل است: یک توکن جدید بسازید، کلاینت را به آن تغییر دهید و سپس توکن قبلی را لغو کنید. توکن منقضی‌شده، توکن لغوشده، مالک غیرفعال‌شده یا از دست دادن قلمرو هر کدام باعث خطا در درخواست بعدی می‌شوند. توکن‌ها فقط در سرآیند `Authorization: Bearer` پذیرفته می‌شوند؛ توکن در رشته پرس‌وجو (query string) یا بدنه درخواست پذیرفته نمی‌شود.

## اتصال یک کلاینت

از نقطه پایانی MCP به نشانی `https://cacti.example.com/cacti/plugins/mcp/mcp.php` به همراه توکن در هدر `Authorization: Bearer` استفاده کنید. توکن را در یک متغیر محیطی یا مدیر اسرار (secret manager) نگه دارید و به جای نوشتن مقدار آن در فایل، از پیکربندی کلاینت به آن ارجاع دهید.

### Claude Code

نقطه پایانی را در فایل `.mcp.json` پروژه قرار دهید تا به صورت اسمی به توکن ارجاع دهد. Claude Code مقدار `${VAR}` را در `url` و `headers` بسط می‌دهد؛ بنابراین این فایل حاوی هیچ رازی نیست و کامیت کردن آن ایمن است. متغیر `CACTI_MCP_TOKEN` را در محیطی که Claude Code را اجرا می‌کند export کنید.

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

همچنین می‌توانید آن را از خط فرمان اضافه کنید:

```console
claude mcp add --transport http cacti https://cacti.example.com/cacti/plugins/mcp/mcp.php \
  --header "Authorization: Bearer $CACTI_MCP_TOKEN"
```

با استفاده از دابل کوتیشن، پوسته (shell) ابتدا `$CACTI_MCP_TOKEN` را بسط می‌دهد؛ بنابراین مقدار توکن در فایل پیکربندی برای `--scope` انتخاب‌شده (`local`، `user` یا `project`؛ پیش‌فرض `local`) نوشته می‌شود. از این شکل با `--scope project` استفاده نکنید و فایل را خارج از کنترل نسخه نگه دارید. ارجاع `.mcp.json` در بالا را در اولویت قرار دهید. Claude Code برخی متغیرهای احراز هویت (مانند `ANTHROPIC_AUTH_TOKEN`) را در `url` و `headers` راه‌دور به صورت خالی می‌خواند؛ `CACTI_MCP_TOKEN` جزو آن‌ها نیست. منبع: [مستندات MCP در Claude Code](https://code.claude.com/docs/en/mcp).

### GitHub Copilot در VS Code

از یک فایل `.mcp.json` در ریشه فضای کاری (یا فایل کاربری `~/.copilot/mcp-config.json`) استفاده کنید. این فایل‌های بومی Copilot از یک آبجکت سطح بالا به نام `mcpServers` و ارجاع‌های متغیر محیطی `${NAME}` در مقادیر هدر استفاده می‌کنند:

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

متغیر `CACTI_MCP_TOKEN` را در محیطی که VS Code را اجرا می‌کند export کنید. فایل‌های بومی Copilot از اعلان‌های `inputs` پشتیبانی نمی‌کنند. راه‌اندازی هدایت‌شده (guided setup) در VS Code مقادیر `${...}` را رد می‌کند؛ بنابراین هدر `Authorization` را با ویرایش مستقیم فایل اضافه کنید، نه از طریق جریان هدایت‌شده. راه‌اندازی هدایت‌شده فایل ریشه فضای کاری را تنها زمانی پیشنهاد می‌دهد که تنظیم آزمایشی `chat.mcp.workspaceRootConfig.enabled` روشن باشد. برای اطلاعات بیشتر [مرجع پیکربندی MCP در VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) را ببینید.

**روش قدیمی: `.vscode/mcp.json`.** VS Code اعلام کرده است که پیکربندی‌های جدید Copilot نباید از `.vscode/mcp.json` یا فایل `mcp.json` پروفایل استفاده کنند؛ این‌ها متعلق به Local harness منسوخ‌شده هستند که در فوریه ۲۰۲۷ حذف خواهد شد. اگر همچنان از آن استفاده می‌کنید، قالب مدیریت‌شده توسط ویرایشگر یک کلید سطح بالای `servers` می‌گیرد و می‌تواند برای دریافت توکن اعلان نمایش دهد:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "cacti-mcp-token",
      "description": "Cacti MCP token",
      "password": true
    }
  ],
  "servers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${input:cacti-mcp-token}"
      }
    }
  }
}
```

### کلاینت‌هایی که فقط stdio پشتیبانی می‌کنند

[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) یک آداپتور اختیاری است که به عنوان یک سرور MCP محلی از نوع stdio اجرا می‌شود و HTTP API افزونه را فراخوانی می‌کند. از آن برای کلاینتی استفاده کنید که نمی‌تواند به یک سرور HTTP راه‌دور متصل شود. این ابزار به همان توکن شخصی نیاز دارد و با `api.php` ارتباط برقرار می‌کند.

### رفتار MCP

این نقطه پایانی فقط ابزارها را ارائه می‌دهد: هر قابلیت (ability) عرضه‌شده و مجاز، ابزاری است که با شناسه آن نام‌گذاری شده و دارای طرحواره‌های ورودی و خروجی و حاشیه‌نویسی‌های فقط-خواندنی است (`openWorldHint` برابر با `false` است). این نقطه پایانی متدهای `initialize`، `server/discover`، `ping`، `tools/list` و `tools/call` را پردازش می‌کند. هیچ نشستی (session) نگهداری نمی‌کند، `Mcp-Session-Id` ارسال نمی‌کند (و اگر دریافت کند نادیده می‌گیرد) و دسته‌های JSON-RPC (batches) را نمی‌پذیرد. پیامی که بدون `id` باشد یک اعلان (notification) است و پاسخ HTTP 202 بدون بدنه دریافت می‌کند. فقط متد `POST` مجاز است.

- **نسخه‌ها (Revisions).** درخواستی که `io.modelcontextprotocol/protocolVersion` را در `params._meta` دارد باید مقدار `2026-07-28` را مشخص کند؛ هر مقدار دیگری خطای `-32022` دریافت می‌کند. چنین درخواست‌هایی همچنین باید هدرهای منطبق `Mcp-Protocol-Version`، `Mcp-Method` و (برای `tools/call`) `Mcp-Name` را همراه داشته باشند، در غیر این صورت پاسخ خطای `-32020` خواهد بود. سایر درخواست‌ها به عنوان `2025-11-25` در نظر گرفته می‌شوند: `initialize` با همان نسخه پاسخ می‌دهد و در هر متد دیگری، هدر `Mcp-Protocol-Version` در صورت ارسال باید `2025-11-25`، `2025-06-18` یا `2025-03-26` باشد.
- **خطاهای ابزار.** خطای یک قابلیت، از جمله آرگومان‌هایی که با طرحواره مطابقت ندارند یا مقدار `arguments` که یک آبجکت JSON نیست، به عنوان نتیجه ابزار با `isError: true` و خطای AIP-193 در `structuredContent` برگردانده می‌شود، نه به عنوان خطای پروتکل.
- **خطاهای پروتکل.** خطاهایی که خطای ابزار نیستند، آبجکت‌های خطای JSON-RPC هستند (کد `-32000` با وضعیت و دلیل در `data`، یا کدهای استاندارد): نبود Public Cacti URL، رد شدن `Origin`، درخواست در زمان غیرفعال بودن افزونه یا روی یک poller راه‌دور، و خطاهای غیرمنتظره سرور (`-32603` که جزئیات آن در گزارش Cacti نوشته می‌شود، نه در پاسخ). بررسی‌های درخواستی که ابتدا اجرا می‌شوند (405، 413، 415) و خطاهای احراز هویت (401 `INVALID_TOKEN`، 403 `REALM_REQUIRED`) بدنه AIP-193 شرح‌داده‌شده در بخش HTTP API را حفظ می‌کنند.

## HTTP API

نشانی پایه (Base URL): `https://cacti.example.com/cacti/plugins/mcp/api.php`. قرارداد در [openapi.json](../../../openapi.json) آمده است.

| متد و مسیر | هدف |
| --- | --- |
| `GET /v1/abilities` | فهرست قابلیت‌های مجاز. پارامترهای کوئری: `pageSize`، `pageToken` و `filter` به شکل `category = "inventory"`. |
| `GET /v1/abilities/{id}` | خواندن یک قابلیت. |
| `POST /v1/abilities/{id}:execute` | اجرای آن. بدنه دقیقاً به شکل `{"arguments": {...}}` است. پاسخ به شکل `{"requestId": "...", "result": {...}}` است. |

```console
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" \
  https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" -H 'Content-Type: application/json' \
  -d '{"arguments": {"filter": "state = \"DOWN\""}}' \
  'https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities/cacti-list-devices:execute'
```

خطاها از AIP-193 پیروی می‌کنند: یک آبجکت `error` با فیلدهای `code`، `message`، `status` و `details` که شامل یک `ErrorInfo` با دامنه `cacti.net` و یک `reason` پایدار است. مشکلات مربوط به آرگومان‌ها یک جزئیات `BadRequest` اضافه می‌کنند که نام فیلد را مشخص می‌کند. اندازه بدنه درخواست‌ها به ۶۴ کیلوبایت و نتایج به ۱ مگابایت محدود است. هر دو نقطه پایانی فقط روی poller اصلی پاسخ می‌دهند و هنگامی که افزونه غیرفعال است یا سرور poller اصلی نیست، `UNAVAILABLE` (`PLUGIN_UNAVAILABLE`) را برمی‌گردانند.

| HTTP | مقادیر `reason` |
| --- | --- |
| 400 | `INVALID_ARGUMENTS`, `INVALID_FILTER`, `INVALID_PAGE_TOKEN` |
| 401 | `INVALID_TOKEN` (همچنین `WWW-Authenticate: Bearer` را ارسال می‌کند) |
| 403 | `REALM_REQUIRED` |
| 404 | `ABILITY_NOT_FOUND`, `DEVICE_NOT_FOUND`, `UNKNOWN_PATH` |
| 405 | `METHOD_NOT_ALLOWED` (`Allow` را ارسال می‌کند) |
| 413 | `REQUEST_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR`, `INVALID_RESULT` |
| 503 | `AUDIT_UNAVAILABLE`, `PLUGIN_UNAVAILABLE`, `CACTI_UNAVAILABLE` |

## نوشتن یک قابلیت (نویسندگان افزونه)

یک افزونه فعال Cacti قابلیت‌ها را از طریق تابعی ثبت می‌کند که به قلاب (hook) `abilities_register` متصل می‌کند؛ معمولاً در تابع `plugin_<slug>_install()` خود:

```php
api_plugin_register_hook('acme', 'abilities_register', 'acme_abilities_register', 'setup.php');
```

این تابع یک `AbilitiesRegistrar` دریافت می‌کند که دامنه آن محدود به همین افزونه است. مقدار بازگشتی آن نادیده گرفته می‌شود.

```php
function acme_abilities_register(AbilitiesRegistrar $registrar) : void {
	$registrar->registerCategory('acme-widgets', 'Widgets');

	$registrar->register('acme-get-widget-count', [
		'label'         => 'Get widget count',
		'description'   => 'Count the widgets the caller may see.',
		'category'      => 'acme-widgets',
		'input_schema'  => ['type' => 'object', 'properties' => new stdClass(), 'additionalProperties' => false],
		'output_schema' => [
			'type'                 => 'object',
			'properties'           => ['count' => ['type' => 'integer', 'minimum' => 0]],
			'required'             => ['count'],
			'additionalProperties' => false
		],
		'annotations' => ['readOnly' => true, 'destructive' => false, 'idempotent' => true],
		'permission'  => fn (int $userId) => is_realm_allowed(ACME_REALM_ID, $userId),
		'execute'     => fn (int $userId, stdClass $args) => ['count' => acme_count_widgets($userId)]
	]);
}
```

قوانینی که همگی در زمان ثبت اعمال می‌شوند:

- **شناسه‌ها (IDs).** یک شناسه باید با `^[a-z][a-z0-9]*(-[a-z0-9]+){1,7}$` مطابقت داشته باشد، حداکثر ۶۴ کاراکتر باشد و با نامک (slug) افزونه و یک خط تیره شروع شود: در بالا `acme-`. نامک همان نام پوشه افزونه است، بنابراین پوشه‌ای مانند `my_plugin` نمی‌تواند هیچ قابلیتی ثبت کند. پوشه افزونه‌ای با نام `cacti` رد می‌شود؛ آن فضای نام متعلق به قابلیت‌های داخلی است.
- **تعریف.** دقیقاً این کلیدها: `label`، `description` (تا ۴۰۹۶ بایت)، `category`، `input_schema`، `output_schema`، `annotations`، `permission`، `execute`. دسته‌بندی باید از قبل وجود داشته باشد: از یک دسته‌بندی داخلی (`inventory`، `system`) استفاده کنید یا دسته‌بندی خود را با `registerCategory()` ثبت کنید که شناسه آن در میان همه افزونه‌ها یکتا باشد و با `^[a-z][a-z0-9-]{0,31}$` مطابقت داشته باشد.
- **فقط حالت فقط-خواندنی.** `annotations` باید دقیقاً دارای مقادیر `readOnly: true`، `destructive: false` و `idempotent: true` باشد. هر چیز دیگری استثنا (throw) ایجاد می‌کند.
- **طرحواره‌ها (Schemas).** هر یک از `input_schema` و `output_schema` باید در سطح بالا `type` برابر با `object` داشته باشند. گویش (dialect) این طرحواره کوچک است و در صورت خطا به صورت ایمن رد می‌کند (fails closed). آبجکت‌ها باید بسته باشند (`additionalProperties: false` همراه با وجود `properties`)؛ سایر نوع‌ها عبارت‌اند از `integer` و `number` (`minimum`، `maximum`)، `string` (`minLength`، `maxLength`، `enum`، `pattern`)، `boolean` و `array` (که به `items` و `maxItems` نیاز دارد). یک نوع می‌تواند به صورت `['string', 'null']` مقدارپذیر با `null` (nullable) شود. رشته‌های آرگومان به طور پیش‌فرض حداکثر ۴۰۹۶ کاراکتر هستند؛ رشته‌های نتیجه فقط توسط `maxLength` اعلام‌شده و محدودیت اندازه نتیجه محدود می‌شوند. حداکثر ۲۵۶ قابلیت قابل ثبت است.
- **`permission(int $userId): bool`.** برای اجازه دادن باید دقیقاً `true` برگرداند. شناسه کاربر متعلق به مالک توکن است؛ هرگز وضعیت نشست (session state) را نخوانید.
- **`execute(int $userId, stdClass $args): array`.** `$args` از پیش در برابر `input_schema` اعتبارسنجی شده است. مجوزهای سطح آبجکت را خودتان اعمال کنید. یک آرایه انجمنی (associative array) برگردانید که دقیقاً با `output_schema` مطابقت داشته باشد؛ یک لیست، یک فیلد اضافی یا بیش از ۱ مگابایت JSON به خطای `INVALID_RESULT` تبدیل می‌شود. برای یک خطای قابل مشاهده برای کلاینت، مانند `NOT_FOUND`، یک `AbilitiesError` پرتاب (throw) کنید.
- **آبجکت‌های خالی.** PHP آرایه `[]` را به صورت یک آرایه JSON کدگذاری می‌کند. در هر جایی از طرحواره خروجی که یک `object` تعریف شده باشد، در هر عمقی، رجیستری `[]` را به عنوان آبجکت خالی در نظر می‌گیرد و `{}` ارسال می‌کند؛ `new stdClass()` نیز کار می‌کند. یک لیست غیرخالی هرگز به عنوان آبجکت محسوب نمی‌شود و با `INVALID_RESULT` شکست می‌خورد. یک نگاشت `properties` خالی در طرحواره می‌تواند `[]` یا `new stdClass()` باشد؛ هر دو به صورت `{}` منتشر می‌شوند.
- **جداسازی خطاها.** هر افزونه در یک کپی موقت (scratch copy) ثبت می‌شود که تنها در صورتی نگه داشته می‌شود که تابع شما به طور عادی بازگردد. اگر استثنایی پرتاب شود، هیچ‌یک از قابلیت‌های شما ثبت نمی‌شوند و خطا در گزارش ثبت می‌گردد.

قابلیت‌های افزونه‌ها در ابتدا به صورت مخفی شروع می‌شوند. مدیر آن‌ها را در زبانه Abilities کنسول نمایش می‌دهد و ستون Required Realm برای آن‌ها عبارت "Set by the plugin" را نشان می‌دهد.

## مدل امنیتی

- **فقط حامل (Bearer).** فایل‌های `api.php` و `mcp.php` تنها یک توکن شخصی در سرآیند `Authorization` می‌پذیرند و بس. این دو فایل پیش از بارگذاری Cacti کوکی‌ها، `$_POST` و `$_REQUEST` را حذف می‌کنند و نشستی را که Cacti آغاز می‌کند از بین می‌برند؛ بنابراین ورود از طریق مرورگر هرگز دسترسی API اعطا نمی‌کند.
- **دور زدن موقت محافظ CSRF.** محافظ CSRF در Cacti درخواست‌های JSON POST بدون توکن CSRF مربوط به Cacti را رد می‌کند که هیچ کلاینت MCP نمی‌تواند آن را ارسال کند. تنها برای این دو نقطه پایانی، افزونه پیش از بارگذاری Cacti نام متد درخواست را تغییر می‌دهد و پس از آن بازمی‌گرداند تا محافظ از آن‌ها عبور کند. این کار ایمن است زیرا CSRF از درخواست‌هایی محافظت می‌کند که مرورگر با کوکی احراز هویت می‌کند، و این نقاط پایانی هیچ هویت مبتنی بر کوکی را نمی‌پذیرند: یک صفحه بین‌سایتی نمی‌تواند توکن حامل را پیوست کند. صفحات کنسول همچنان از حفاظت کامل CSRF برخوردارند. این راه‌حل موقت است تا زمانی که Cacti معافیت رسمی پشتیبانی‌شده‌ای ارائه دهد؛ برای جزئیات `lib/bootstrap.php` را ببینید.
- **بررسی مبدأ (Origin).** در `mcp.php`، اگر درخواست دارای سرآیند `Origin` باشد، باید دقیقاً با طرح (scheme)، میزبان و درگاه نشانی عمومی Cacti مطابقت داشته باشد، در غیر این صورت درخواست با خطای `ORIGIN_NOT_ALLOWED` رد می‌شود. درخواستی که سرآیند `Origin` نداشته باشد — که شیوه اتصال کلاینت‌های غیرمرورگری است — مجاز است. این بررسی مانع از آن می‌شود که یک صفحه وب از مرورگر بازدیدکننده به این نقطه پایانی درخواست بفرستد. فایل `api.php` این بررسی را اعمال نمی‌کند.
- **فقط خواندنی.** فرآیند ثبت هر قابلیتی را که فقط خواندنی، غیرمخرب و بی‌اثر در تکرار (idempotent) نباشد، رد می‌کند.
- **اعمال هم‌زمان نمایان‌سازی و قلمروها.** یک قابلیت باید نمایان شده باشد و دارنده توکن نیز قلمرو (realm) آن را داشته باشد. اگر جدول نمایان‌سازی قابل خواندن نباشد، همه قابلیت‌ها به جای بازگشت به مقادیر پیش‌فرض پنهان می‌شوند.
- **یکسان بودن وضعیت پنهان، ناشناخته و غیرمجاز.** کلاینت نمی‌تواند تفاوتی میان قابلیتی که وجود ندارد، پنهان است، یا کاربر مجاز به استفاده از آن نیست تشخیص دهد: کشف قابلیت‌ها آن را حذف می‌کند و اجرا مقدار `NOT_FOUND` (`ABILITY_NOT_FOUND`) برمی‌گرداند.
- **توکن‌ها.** به صورت درهم‌ساز SHA-256 ذخیره می‌شوند، تنها یک بار نمایش داده می‌شوند، همیشه دارای انقضا هستند، قابل لغو بوده و هنگام غیرفعال شدن مالک یا از دست دادن قلمرو رد می‌شوند.
- **ممیزی (Audit).** جدول `plugin_mcp_audit` شناسه درخواست، شناسه توکن، شناسه کاربر، قابلیت، نتیجه (`started`، `succeeded`، `failed`، `denied`، `rejected`) و برچسب‌های زمانی را ثبت می‌کند. این جدول هرگز آرگومان‌ها، نتایج یا مقادیر توکن را ثبت نمی‌کند. یک قابلیت تنها پس از نوشته شدن ردیف `started` اجرا می‌شود؛ اگر جدول ممیزی در دسترس نباشد، فراخوانی با خطای `UNAVAILABLE` ناموفق می‌شود و اجرا نمی‌گردد. فراخوانی‌ای که پیش از اجرا رد شود در یک ردیف ثبت می‌شود: `denied` برای قابلیت ناشناخته، پنهان یا غیرمجاز، و `rejected` برای آرگومان‌هایی که با طرحواره (schema) مطابقت ندارند. ایجاد و لغو توکن از طریق کنسول، بخش My MCP Tokens و رابط خط فرمان با عنوان `mcp-token-create` و `mcp-token-revoke` و با نتیجه `succeeded` ثبت می‌شوند، و لغو تنها برای توکنی ثبت می‌شود که فعال بوده است. عملیات کشف و فراخوانی‌ای که `arguments` آن یک شیء JSON نباشد، در گزارش ثبت نمی‌شوند.
- **گزارش خطا.** یک خطای غیرمنتظره، `INVALID_RESULT` یا در دسترس نبودن جدول ممیزی، یک خط در گزارش Cacti با بخش (facility) `MCP` می‌نویسد: شناسه قابلیت، یک دلیل ثابت و کلاس استثنا. پیام‌ها، آرگومان‌ها و توکن‌ها هرگز ثبت نمی‌شوند.
- **فقط جمع‌آوری‌کننده اصلی (Main poller).** هر دو نقطه پایانی، هر دو صفحه کنسول و `tokens.php` از اجرا در هر جای دیگری خودداری می‌کنند.

## چرخه حیات

غیرفعال کردن افزونه هر دو نقطه پایانی را مسدود می‌کند. حذف نصب افزونه همه توکن‌ها را لغو کرده و سه جدول (`plugin_mcp_token`، `plugin_mcp_audit`، `plugin_mcp_ability`) را برای نگهداری سوابق حفظ می‌کند؛ نصب مجدد یک توکن لغوشده را دوباره فعال نمی‌کند. از این جداول همراه با پایگاه داده Cacti پشتیبان بگیرید و سیاست نگهداری گزارش‌های ممیزی را خارج از افزونه اعمال کنید.

## توسعه و آزمون‌ها

آزمون‌ها اسکریپت‌های ساده PHP هستند که بدون Cacti اجرا می‌شوند:

```console
for t in tests/*.php; do php "$t" || break; done
git archive --format=tar.gz --prefix=mcp/ HEAD > mcp.tar.gz
```

سیستم CI کدهای PHP را بررسی نحوی (lint) می‌کند و اسکریپت‌های موجود در `tests/` (که هر کدام در `.github/workflows/ci.yml` فهرست شده‌اند) را روی نسخه‌های PHP 8.2 تا 8.5 اجرا می‌کند، سپس بایگانی قابل نصب `mcp/` و چک‌سام (checksum) آن را می‌سازد. آزمون‌هایی که با Cacti سر و کار دارند از داده‌های آزمایشی (fixture) در مرز توابع کمکی Cacti استفاده می‌کنند و یک نصب کامل Cacti را شبیه‌سازی نمی‌کنند.

### آزمون‌های یکپارچه‌سازی

دستور `tests/integration/run.sh 1.2.31` یا `tests/integration/run.sh develop` افزونه را در یک Cacti واقعی داخل کانتینرها نصب می‌کند و بررسی‌های زنده را روی آن اجرا می‌نماید. این کار به Docker با Compose v2.23.1 یا جدیدتر، git و openssl نیاز دارد. متغیر `KEEP=1` پشته کانتینرها را برای اشکال‌زدایی در حال اجرا نگه می‌دارد. سیستم CI این آزمون‌ها را به صورت شبانه و در صورت درخواست اجرا می‌کند، نه روی درخواست‌های ادغام (pull requests).

## بومی‌سازی

افزونه Cacti MCP کاتالوگ‌های کامپایل‌شده GNU gettext را در مسیرهای `locales/po/` و `locales/LC_MESSAGES/` و فایل‌های README بومی‌سازی‌شده را در `docs/i18n/` برای زبان انگلیسی به همراه ۴۷ زبان و محلی‌سازی (۱۹ محلی‌سازی رده اول گسترده، ۱۵ محلی‌سازی آفریقایی، ۱۰ محلی‌سازی آسیایی، و زبان‌های بوسنیایی، کرواسیایی و صربی) با استفاده از دامنه متنی `mcp` (`locales/po/mcp.pot`) ارائه می‌دهد. هنگامی که پشتیبانی زبان فعال باشد، Cacti به طور خودکار کاتالوگ متناظر را بارگذاری می‌کند.

## مشارکت

درخواست‌های ادغام (Pull requests) باید به شاخه `develop` ارسال شوند. کدهای محیط تولید را با PHP 8.2 سازگار نگه دارید و از سبک کدنویسی Cacti پیروی کنید: تورفتگی با tab، رشته‌های تک‌کوتیشن و استفاده از توابع کمکی پایگاه داده و دسترسی Cacti. برای تغییرات در اعتبارسنجی، مجوزدهی یا رفتار پروتکل، آزمون اضافه کنید و کامیت‌ها را با `git commit -s` امضا (sign off) کنید. تغییرات در HTTP API را با [cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) هماهنگ کنید.
