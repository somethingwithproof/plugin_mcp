Cacti MCP — это плагин для Cacti, позволяющий ИИ-клиентам читать данные Cacti
через именованные операции с фильтрацией прав, называемые возможностями (abilities).
Сам плагин предоставляет к ним доступ двумя способами: через конечную точку MCP
(`mcp.php`, Streamable HTTP) и HTTP API в стиле AIP (`api.php`). Авторизация и
выполнение остаются на стороне Cacti. Клиент никогда не обращается напрямую к базе
данных: он может вызывать только те возможности, к которым администратор открыл
доступ и которые разрешены областями прав Cacti владельца токена.

Авторы плагинов могут регистрировать собственные возможности только для чтения
через хук `abilities_register`, после чего они отображаются в MCP-клиентах как
инструменты без необходимости писать код протокола.

**Статус: предварительный выпуск, версия 0.1.0.** Тегированного релиза пока нет.

Доступно уже сейчас:

- Встроенные возможности только для чтения для получения сведений о версиях системы и перечня устройств.
- Персональные токены доступа (`cmcp_pat_...`) в качестве единственного вида учётных данных.
- Консоль «Управление > MCP»: открытие или скрытие доступа к возможностям, создание и отзыв токенов, просмотр журнала аудита.
- Раздел «Управление > Мои токены MCP»: пользователи управляют собственными токенами, просматривают свою активность и список доступных для их токенов инструментов.
- MCP поверх Streamable HTTP, ревизии протокола `2026-07-28` и `2025-11-25`, только инструменты.

Пока недоступно:

- Вход через OAuth 2.1. Облачные коннекторы, не поддерживающие отправку персонального токена (например, пользовательские коннекторы ChatGPT и claude.ai), не смогут подключиться, пока эта функция не будет реализована. Она запланирована в рамках Плана 2; сам план ещё не написан.
- Возможности с правом записи. Регистрация поддерживается только для возможностей только для чтения.

Архитектура описана в
[спецификации конечных точек](../../superpowers/specs/2026-11-19-mcp-endpoint-design.md),
а последовательность сборки — в [docs/plan.md](../../plan.md).

## Встроенные возможности

| ID | Аргументы | Необходимая область прав Cacti |
| --- | --- | --- |
| `cacti-get-system-info` | нет | 15 |
| `cacti-list-devices` | необязательные `pageSize`, `pageToken`, `filter`, `orderBy` | 3 |
| `cacti-get-device` | обязательный `name`, например `devices/12` | 3 |

Для каждого вызова также требуются область прав **MCP and Abilities API** у
владельца токена, область действия `abilities:read` (она есть у каждого
персонального токена) и открытый доступ к самой возможности. На вкладке
«Возможности» в консоли показано, какая область прав нужна для каждой встроенной
возможности.

- `cacti-list-devices` возвращает страницы до 100 устройств (по умолчанию 50) и
  токен следующей страницы `nextPageToken`. Токен страницы действителен только
  для тех же значений `filter` и `orderBy`. `filter` — это выражение AIP-160 из
  сравнений, объединённых через `AND`, например `state = "DOWN" AND disabled = false`.
  Для фильтрации доступны поля `displayName`, `hostname`, `disabled`, `site`,
  `poller`, `deviceTemplate`, `externalId` и `state`. `orderBy` принимает
  `displayName`, `hostname` или `name`, после каждого из которых можно указать `desc`.
- Запросы к устройствам проходят через функцию Cacti `get_allowed_devices()`,
  поэтому пользователь видит только те устройства, которые ему показывает сама Cacti.
- Поля устройств не включают строки сообщества SNMP, парольные фразы и другие
  учётные данные.

## Установка

Требуется Cacti 1.2.31 или новее, PHP 8.2 или новее и основной поллер.
Аутентификация в Cacti должна быть включена: при отключённой аутентификации плагин
отказывает в проверке подлинности.

Каталог плагина должен называться `mcp`, а не `plugin_mcp`. Идентификатор
плагина, названия областей прав, домен переводов и URL используют `mcp`.

Из исходного кода репозитория:

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_mcp.git mcp
```

Пока не вышли тегированные релизы, можно вместо этого скачать артефакт
`mcp-plugin` из успешного
[запуска CI](https://github.com/somethingwithproof/plugin_mcp/actions/workflows/ci.yml).
Он содержит `mcp.tar.gz` и `SHA256SUMS`. Проверьте контрольную сумму и распакуйте
`mcp.tar.gz` в каталог `plugins/` Cacti так, чтобы получился путь `plugins/mcp/`.
Автоматические архивы исходного кода GitHub используют другое имя корневого
каталога. Кроме того, в архив не входят каталоги `docs/` (включая приведённые
ниже снимки экрана), `tests/` и `.github/`, поэтому ссылки из README в `docs/`
работают на GitHub, но не в установленной копии.

Далее:

1. В разделе «Управление плагинами» (Plugin Management) установите и включите
   **Cacti MCP**. Администратор, выполняющий установку, автоматически получает
   область прав **MCP Administration**.
2. В разделе «Настройки > MCP» (Settings > MCP) задайте для параметра
   **Публичный URL Cacti** (Public Cacti URL) адрес, который используют клиенты,
   например `https://cacti.example.com/cacti`. Протокол HTTPS обязателен везде,
   кроме `localhost`, `127.0.0.1` и `[::1]`. Пока этот параметр не задан,
   `mcp.php` отвечает кодом HTTP 400 с ошибкой JSON-RPC, в поле `data` которой
   указаны `FAILED_PRECONDITION` и `PUBLIC_URL_REQUIRED`. `api.php` этот параметр
   не читает.

   ![Раздел «Настройки > MCP» с полем «Публичный URL Cacti»](../../images/settings-public-url.png)

3. Выдайте область прав **MCP and Abilities API** каждому пользователю, который
   будет владеть токеном. Автоматически она никому не назначается.
4. Убедитесь, что веб-сервер передаёт заголовок `Authorization` и информацию о
   пути (path info) в PHP (см. ниже).
5. Откройте «Управление > MCP» и откройте доступ к возможностям, которые должны
   быть видны клиентам.

**Обновление со сборки разработки.** Плагин находится на стадии предварительного
выпуска, и его таблицы менялись в ходе разработки без миграций. Если у вас была
установлена более ранняя сборка, удалите плагин и установите его заново. При
повторной установке уже существующие таблицы сохраняются, поэтому сначала удалите
старые таблицы `plugin_mcp_token`, `plugin_mcp_audit` и `plugin_mcp_ability` (а
также аналогичные таблицы из сборок до переименования). При необходимости
сохранения истории сделайте их резервную копию; токены из этих сборок
отзываются при удалении плагина и не переносятся.

### Веб-сервер

В конфигурациях Apache, где заголовок `Authorization` удаляется до передачи в
PHP, необходимо добавить следующую директиву в нужный виртуальный хост или
каталог и перезагрузить сервер:

```apache
SetEnvIf Authorization "(.+)" HTTP_AUTHORIZATION=$1
```

Apache с `mod_php` обслуживал маршруты `api.php` без дополнительной настройки путей.

Маршруты `api.php` располагаются в части пути после имени скрипта
(`/plugins/mcp/api.php/v1/abilities`), поэтому nginx должен сопоставлять URI, в
которых после `.php` следует продолжение пути, отделять path info и передавать
его в PHP. Блок `location ~ \.php$` никогда не совпадает с такими URL, и nginx
отвечает собственной HTML-страницей 404. Приведённый ниже шаблон `location` и две
строки для path-info проверены с PHP-FPM; остальные строки являются стандартным
шаблоном:

```nginx
location ~ \.php(/|$) {
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_pass unix:/run/php/php-fpm.sock;   # your PHP-FPM socket or host:port
}
```

Настройте строки `include` и `fastcgi_pass` в соответствии с блоком, который уже
обслуживает Cacti. Не добавляйте в этот блок `try_files $fastcgi_script_name =404;`:
он очищает `$fastcgi_path_info`, после чего `api.php` возвращает 404 `UNKNOWN_PATH`.
Если вашей конфигурации необходим `try_files`, предварительно сохраните значение
с помощью `set $path_info $fastcgi_path_info;` и передайте `fastcgi_param PATH_INFO $path_info;`.

У `mcp.php` нет маршрутов в пути, поэтому ему эти настройки не требуются.

## Консоль

Раздел «Управление > MCP» состоит из трёх вкладок. Для работы с ним требуется
область прав **MCP Administration**. Приведённые здесь и далее снимки экрана
сделаны на тестовой сборке Cacti с демонстрационными данными.

- **Возможности (Abilities)** — перечень всех зарегистрированных возможностей с
  указанием плагина, категории, требуемой области прав и статуса доступности.
  Выберите строки и нажмите «Открыть доступ» (Expose) или «Скрыть» (Hide); перед
  применением изменений потребуется подтверждение. Встроенные возможности
  `cacti-*` открыты по умолчанию. Возможности других плагинов изначально скрыты,
  поэтому установка плагина никогда ничего не публикует до решения
  администратора. Настройка видимости только сужает доступ: пользователю по-прежнему
  нужна область прав самой возможности.

  ![Вкладка «Возможности» со списком встроенных возможностей, их областей прав и статуса доступности](../../images/console-abilities.png)
- **Токены (Tokens)** — перечень токенов с указанием владельца, создателя, даты
  создания, срока действия, последнего использования и состояния (Active,
  Expired, Revoked). Выберите строки и нажмите «Отозвать» (Revoke), чтобы
  отозвать их. Отозванные токены нельзя использовать повторно. Кнопка
  «Создать токен» (Create Token) создаёт новый токен.

  ![Вкладка «Токены» со списком токенов с владельцем, сроком действия, последним использованием и состоянием над формой создания токена](../../images/console-tokens.png)
- **Аудит (Audit)** — журнал аудита в порядке от новых записей к старым с
  фильтрацией по пользователю, возможности и результату.

  ![Вкладка «Аудит» со списком вызовов с пользователем, токеном, возможностью и результатом, а также фильтрами](../../images/console-audit.png)

## Токены

Персональный токен читает данные Cacti от имени своего владельца. Он имеет вид
`cmcp_pat_` с последующими 64 шестнадцатеричными символами в нижнем регистре и
несёт единственную область действия `abilities:read`. Доступные ему данные
определяются областями прав Cacti и правами на устройства его владельца, а не
самим токеном. Владелец должен быть активным (включённым) пользователем с
областью прав **MCP and Abilities API**.

Токены всегда создаются для конкретного пользователя, имеют срок действия и могут
быть отозваны:

- **Консоль.** Управление > MCP > Токены > Создать токен. Срок действия — от 1 до
  365 дней, по умолчанию 90. Токен генерируется сервером и показывается на
  странице ответа только один раз, поэтому сразу сохраните его в менеджере
  секретов. Вы можете создать токен для себя. Для создания токена другому
  пользователю также требуется область прав «Пользователи/Группы» (Users/Groups),
  поскольку токен читает Cacti от имени этого пользователя.
- **Мои токены MCP.** Любой пользователь с областью прав MCP and Abilities API
  может самостоятельно управлять своими токенами (см. ниже).
- **Командная строка.** Скрипт `tokens.php` запускается только из CLI от имени
  учётной записи ОС с правами администрирования Cacti. Значение токена он
  получает из переменной окружения, чтобы оно не попадало в командную строку и
  список процессов. Срок действия — от 1 до 365 дней, по умолчанию 30. Создание и
  отзыв токена через CLI фиксируются в журнале аудита так же, как и действия в
  консоли, причём в качестве инициатора указывается владелец токена, так как в
  CLI нет пользователя Cacti (поэтому запись аудита не отмечает действие как
  выполненное из CLI). Флаг `--list` выводит все токены в формате JSON (ID,
  владелец, области действия, временные метки, флаг отзыва) и никогда не выводит
  само значение токена; `--help` показывает справку по использованию.

  ```console
  export CACTI_MCP_TOKEN="$(printf 'cmcp_pat_%s\n' "$(openssl rand -hex 32)")"
  # Store this value in your secret manager before you end this shell session.
  php plugins/mcp/tokens.php --create=USERNAME --days=30
  php plugins/mcp/tokens.php --list
  php plugins/mcp/tokens.php --revoke=ID
  ```

Токены нельзя создать для гостевой учётной записи, отключённых пользователей или
пользователей без области прав **MCP and Abilities API** — ни через консоль, ни
через командную строку, ни на странице «Мои токены MCP». Cacti хранит параметр
гостевой учётной записи в виде имени пользователя или его ID, и плагин корректно
распознаёт оба варианта. Токен, владелец которого становится гостевой учётной
записью, перестаёт работать при следующем же запросе.

### Мои токены MCP

Раздел «Управление > Мои токены MCP» (`plugins/mcp/mcp_tokens.php`) не требует
административной области прав: доступ к нему обеспечивается областью прав
**MCP and Abilities API**, и пункт меню отображается только у пользователей,
которые ею обладают. Страница всегда действует от имени вошедшего пользователя.
Меню Cacti является частью консоли, поэтому пользователь без доступа к консоли
открывает эту страницу по её адресу.

![Вкладка «Мои токены» со списком токенов текущего пользователя и формой создания](../../images/my-tokens.png)

- **Токены (Tokens)** — показывает ваши токены, позволяет создать новый (от 1 до
  365 дней, по умолчанию 90, значение показывается в ответе один раз) и отозвать
  свои собственные. Просматривать или отзывать чужие токены нельзя.
- **Активность (Activity)** — выводит выполненные вами действия от новых к
  старым: вызовы с использованием ваших токенов и внесённые вами изменения
  токенов.
- **Доступные инструменты (Available Tools)** — показывает возможности, которыми
  ваш токен может воспользоваться прямо сейчас, с указанием ID, названия и
  описания каждой возможности. Список следует вашим правам доступа в Cacti и
  выбранным администратором настройкам видимости.

  ![Список «Доступные инструменты» с ID, названием и описанием каждой возможности](../../images/my-tools.png)

В установках, выполненных до появления этой страницы, список файлов области прав
не содержит `mcp_tokens.php`. Этот список регистрируется при установке и не
обновляется при включении или выключении плагина. Удалите плагин и установите
его снова, затем повторно выдайте области прав, поскольку Cacti удаляет выданные
права при удалении плагина.

В базе данных хранится только SHA-256-хеш токена, поэтому утерянный токен нельзя
восстановить — отзовите его и создайте новый. Ротация выполняется так же:
создайте новый токен, переключите клиент, затем отзовите старый. Просроченный
токен, отозванный токен, отключённый владелец или утраченная область прав
приводят к отказу на следующем запросе. Токены принимаются только в заголовке
`Authorization: Bearer`; передача токена в строке запроса или теле запроса не
поддерживается.

## Подключение клиента

Используйте конечную точку MCP `https://cacti.example.com/cacti/plugins/mcp/mcp.php` и передавайте токен в заголовке `Authorization: Bearer`. Храните токен в переменной окружения или менеджере секретов и ссылайтесь на него из конфигурации клиента вместо того, чтобы записывать его значение в файл.

### Claude Code

Укажите конечную точку в файле `.mcp.json` проекта со ссылкой на токен по имени. Claude Code раскрывает `${VAR}` в полях `url` и `headers`, поэтому файл не содержит секретов и его безопасно фиксировать в системе контроля версий. Экспортируйте `CACTI_MCP_TOKEN` в окружении, из которого запускается Claude Code.

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

Вы также можете добавить сервер из командной строки:

```console
claude mcp add --transport http cacti https://cacti.example.com/cacti/plugins/mcp/mcp.php \
  --header "Authorization: Bearer $CACTI_MCP_TOKEN"
```

При использовании двойных кавычек оболочка сначала раскрывает `$CACTI_MCP_TOKEN`, поэтому значение токена записывается в файл конфигурации для выбранного `--scope` (`local`, `user` или `project`; по умолчанию `local`). Не используйте эту форму с `--scope project` и не добавляйте полученный файл в систему контроля версий. Предпочтительнее использовать ссылку в `.mcp.json`, описанную выше. В удалённых `url` и `headers` Claude Code считывает некоторые переменные учётных данных (например, `ANTHROPIC_AUTH_TOKEN`) как пустые; `CACTI_MCP_TOKEN` к ним не относится. Источник: [документация MCP для Claude Code](https://code.claude.com/docs/en/mcp).

### GitHub Copilot в VS Code

Используйте файл `.mcp.json` в корне рабочей области (или пользовательский файл `~/.copilot/mcp-config.json`). Эти собственные файлы конфигурации Copilot используют объект верхнего уровня `mcpServers` и ссылки на переменные окружения вида `${NAME}` в значениях заголовков:

```json
{
  "mcpServers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${CACTI_MCP_TOKEN}"
      }
    }
  }
}
```

Экспортируйте `CACTI_MCP_TOKEN` в окружении, из которого запускается VS Code. Собственные файлы Copilot не поддерживают запросы ввода `inputs`. Пошаговая настройка VS Code отклоняет значения `${...}`, поэтому добавьте заголовок `Authorization`, отредактировав файл вручную, а не через мастер настройки. Пошаговая настройка предлагает файл в корне рабочей области только при включённом экспериментальном параметре `chat.mcp.workspaceRootConfig.enabled`. См. [справочник по настройке MCP в VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

**Устаревший вариант: `.vscode/mcp.json`.** Согласно документации VS Code, новые конфигурации Copilot не должны использовать `.vscode/mcp.json` или `mcp.json` профиля; они относятся к устаревшему механизму Local harness, который будет удалён в феврале 2027 года. Если вы всё ещё используете его, управляемый редактором формат принимает ключ верхнего уровня `servers` и может запрашивать токен интерактивно:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "cacti-mcp-token",
      "description": "Cacti MCP token",
      "password": true
    }
  ],
  "servers": {
    "cacti": {
      "type": "http",
      "url": "https://cacti.example.com/cacti/plugins/mcp/mcp.php",
      "headers": {
        "Authorization": "Bearer ${input:cacti-mcp-token}"
      }
    }
  }
}
```

### Клиенты, поддерживающие только stdio

[cacti-mcp](https://github.com/somethingwithproof/cacti-mcp) — это необязательный адаптер, который запускается как локальный stdio MCP-сервер и обращается к HTTP API плагина. Используйте его для клиентов, которые не могут подключаться к удалённому HTTP-серверу. Ему требуется тот же персональный токен, и он взаимодействует с `api.php`.

### Поведение MCP

Конечная точка предоставляет только инструменты: каждая открытая и разрешённая возможность представляет собой инструмент с именем, равным её идентификатору, со своими схемами ввода и вывода и аннотациями «только для чтения» (`openWorldHint` имеет значение `false`). Она обрабатывает методы `initialize`, `server/discover`, `ping`, `tools/list` и `tools/call`. Конечная точка не хранит сеансы, не отправляет заголовок `Mcp-Session-Id` (и игнорирует полученный) и не принимает пакеты JSON-RPC (batches). Сообщение без `id` является уведомлением и получает ответ HTTP 202 без тела. Разрешён только метод `POST`.

- **Ревизии протокола.** Запрос, содержащий `io.modelcontextprotocol/protocolVersion` в `params._meta`, должен указывать `2026-07-28`; любое другое значение возвращает ошибку `-32022`. Такие запросы также должны содержать соответствующие заголовки `Mcp-Protocol-Version`, `Mcp-Method` и (для `tools/call`) `Mcp-Name`, иначе возвращается ошибка `-32020`. Остальные запросы обрабатываются как `2025-11-25`: метод `initialize` отвечает этой ревизией, а для любого другого метода заголовок `Mcp-Protocol-Version`, если он передан, должен иметь значение `2025-11-25`, `2025-06-18` или `2025-03-26`.
- **Ошибки инструментов.** Ошибка возможности, включая несоответствие аргументов схеме или значение `arguments`, не являющееся объектом JSON, возвращается как результат инструмента с `isError: true` и ошибкой AIP-193 в `structuredContent`, а не как ошибка протокола.
- **Ошибки протокола.** Сбои, не являющиеся ошибками инструментов, возвращаются в виде объектов ошибок JSON-RPC (код `-32000` со статусом и причиной в `data` или стандартные коды): отсутствующий Public Cacti URL, отклонённый заголовок `Origin`, запрос при отключённом плагине или на удалённом поллере (remote poller), а также непредвиденные ошибки сервера (`-32603`, при этом подробности записываются в журнал Cacti, а не в ответ). Первичные проверки запроса (405, 413, 415) и сбои аутентификации (401 `INVALID_TOKEN`, 403 `REALM_REQUIRED`) сохраняют тело ответа в формате AIP-193, описанном в разделе HTTP API.

## HTTP API

Базовый URL: `https://cacti.example.com/cacti/plugins/mcp/api.php`. Контракт описан в файле [openapi.json](../../../openapi.json).

| Метод и путь | Назначение |
| --- | --- |
| `GET /v1/abilities` | Получить список разрешённых возможностей. Параметры запроса: `pageSize`, `pageToken` и `filter` вида `category = "inventory"`. |
| `GET /v1/abilities/{id}` | Получить описание одной возможности. |
| `POST /v1/abilities/{id}:execute` | Выполнить возможность. Тело запроса имеет вид `{"arguments": {...}}`. Ответ имеет вид `{"requestId": "...", "result": {...}}`. |

```console
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" \
  https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities
curl -sS -H "Authorization: Bearer $CACTI_MCP_TOKEN" -H 'Content-Type: application/json' \
  -d '{"arguments": {"filter": "state = \"DOWN\""}}' \
  'https://cacti.example.com/cacti/plugins/mcp/api.php/v1/abilities/cacti-list-devices:execute'
```

Ошибки соответствуют стандарту AIP-193: объект `error` содержит поля `code`, `message`, `status` и `details`, в котором передаётся `ErrorInfo` с доменом `cacti.net` и стабильным значением `reason`. При проблемах с аргументами добавляется элемент `BadRequest` с именем поля. Размер тела запроса ограничен 64 КБ, а результата — 1 МБ. Обе конечные точки отвечают только на основном поллере (main poller) и возвращают `UNAVAILABLE` (`PLUGIN_UNAVAILABLE`), если плагин отключён или сервер не является основным поллером.

| HTTP | Значения `reason` |
| --- | --- |
| 400 | `INVALID_ARGUMENTS`, `INVALID_FILTER`, `INVALID_PAGE_TOKEN` |
| 401 | `INVALID_TOKEN` (также отправляется `WWW-Authenticate: Bearer`) |
| 403 | `REALM_REQUIRED` |
| 404 | `ABILITY_NOT_FOUND`, `DEVICE_NOT_FOUND`, `UNKNOWN_PATH` |
| 405 | `METHOD_NOT_ALLOWED` (отправляется `Allow`) |
| 413 | `REQUEST_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR`, `INVALID_RESULT` |
| 503 | `AUDIT_UNAVAILABLE`, `PLUGIN_UNAVAILABLE`, `CACTI_UNAVAILABLE` |

## Создание возможности (для авторов плагинов)

Включённый плагин Cacti регистрирует возможности из функции, которую он привязывает к хуку `abilities_register`, обычно в своей функции `plugin_<slug>_install()`:

```php
api_plugin_register_hook('acme', 'abilities_register', 'acme_abilities_register', 'setup.php');
```

Функция получает объект `AbilitiesRegistrar`, ограниченный областью видимости этого плагина. Возвращаемое ею значение игнорируется.

```php
function acme_abilities_register(AbilitiesRegistrar $registrar) : void {
	$registrar->registerCategory('acme-widgets', 'Widgets');

	$registrar->register('acme-get-widget-count', [
		'label'         => 'Get widget count',
		'description'   => 'Count the widgets the caller may see.',
		'category'      => 'acme-widgets',
		'input_schema'  => ['type' => 'object', 'properties' => new stdClass(), 'additionalProperties' => false],
		'output_schema' => [
			'type'                 => 'object',
			'properties'           => ['count' => ['type' => 'integer', 'minimum' => 0]],
			'required'             => ['count'],
			'additionalProperties' => false
		],
		'annotations' => ['readOnly' => true, 'destructive' => false, 'idempotent' => true],
		'permission'  => fn (int $userId) => is_realm_allowed(ACME_REALM_ID, $userId),
		'execute'     => fn (int $userId, stdClass $args) => ['count' => acme_count_widgets($userId)]
	]);
}
```

Правила, проверяемые при регистрации:

- **Идентификаторы (ID).** Идентификатор соответствует регулярному выражению `^[a-z][a-z0-9]*(-[a-z0-9]+){1,7}$`, имеет длину не более 64 символов и должен начинаться со слага (slug) плагина и дефиса: `acme-` в примере выше. Слагом является имя каталога плагина, поэтому каталог вроде `my_plugin` не сможет ничего зарегистрировать. Каталог плагина с именем `cacti` отклоняется; это пространство имён принадлежит встроенным возможностям.
- **Определение.** Строго следующие ключи: `label`, `description` (до 4096 байт), `category`, `input_schema`, `output_schema`, `annotations`, `permission`, `execute`. Категория должна уже существовать: используйте встроенную (`inventory`, `system`) или зарегистрируйте собственную с помощью `registerCategory()`, идентификатор которой уникален среди всех плагинов и соответствует `^[a-z][a-z0-9-]{0,31}$`.
- **Только режим чтения.** Поле `annotations` должно содержать строго `readOnly: true`, `destructive: false`, `idempotent: true`. Любое другое значение вызывает исключение.
- **Схемы.** И `input_schema`, и `output_schema` должны иметь на верхнем уровне `type` со значением `object`. Диалект схем минималистичен и работает по принципу «отказ по умолчанию» (fail-closed). Объекты должны быть закрытыми (`additionalProperties: false` при наличии `properties`); другие поддерживаемые типы — `integer` и `number` (`minimum`, `maximum`), `string` (`minLength`, `maxLength`, `enum`, `pattern`), `boolean` и `array` (требует указания `items` и `maxItems`). Тип можно сделать допускающим `null`, указав `['string', 'null']`. Строки в аргументах по умолчанию ограничены 4096 символами; строки в результатах ограничены только объявленным `maxLength` и общим лимитом размера результата. Можно зарегистрировать не более 256 возможностей.
- **`permission(int $userId): bool`.** Для предоставления доступа функция должна возвращать строго `true`. Идентификатор пользователя принадлежит владельцу токена; никогда не читайте состояние сеанса.
- **`execute(int $userId, stdClass $args): array`.** Параметр `$args` уже проверен на соответствие `input_schema`. Проверку прав на уровне объектов реализуйте самостоятельно. Возвращайте ассоциативный массив, точно соответствующий `output_schema`; список, лишнее поле или JSON объёмом более 1 МБ приводят к ошибке `INVALID_RESULT`. Для ошибок, видимых клиенту (например, `NOT_FOUND`), выбрасывайте исключение `AbilitiesError`.
- **Пустые объекты.** PHP кодирует `[]` как массив JSON. Везде, где выходная схема объявляет `object` на любой глубине вложенности, реестр трактует `[]` как пустой объект и отправляет `{}`; `new stdClass()` также работает. Непустой список никогда не считается объектом и завершается ошибкой `INVALID_RESULT`. Пустая карта `properties` в схеме может быть задана как `[]` или `new stdClass()`; оба варианта публикуются как `{}`.
- **Изоляция сбоев.** Каждый плагин выполняет регистрацию во временную копию, которая сохраняется только при нормальном завершении вашей функции. Если она выбрасывает исключение, ни одна из ваших возможностей не регистрируется, а сбой записывается в журнал.

Возможности из плагинов изначально скрыты. Администратор открывает к ним доступ на вкладке «Abilities» в консоли, и в столбце «Required Realm» для них отображается «Set by the plugin».

## Модель безопасности

- **Только Bearer-токен.** `api.php` и `mcp.php` принимают персональный токен в заголовке `Authorization` и ничего больше. Они отбрасывают cookie, `$_POST` и `$_REQUEST` до загрузки Cacti и уничтожают запускаемую Cacti сессию, поэтому вход через браузер никогда не даёт доступа к API.
- **Обход защиты от CSRF.** Защита Cacti от CSRF отклоняет JSON POST-запросы без CSRF-токена Cacti, который не может отправить ни один MCP-клиент. Только для этих двух конечных точек плагин переименовывает метод запроса до загрузки Cacti и восстанавливает его после, чтобы проверка пропускала их. Это безопасно, поскольку CSRF-защита предназначена для запросов, аутентифицируемых браузером через cookie, а эти конечные точки не принимают аутентификацию по cookie: межсайтовая страница не сможет прикрепить bearer-токен. Страницы консоли сохраняют полную защиту от CSRF. Это временный обход до тех пор, пока в Cacti не появится поддерживаемое исключение; см. `lib/bootstrap.php`.
- **Проверка Origin.** В `mcp.php`, если в запросе присутствует заголовок `Origin`, его схема, хост и порт должны в точности совпадать с Public Cacti URL, иначе запрос отклоняется с ошибкой `ORIGIN_NOT_ALLOWED`. Запросы без заголовка `Origin` (именно так подключаются небраузерные клиенты) разрешены. Это не даёт веб-странице обращаться к конечной точке из браузера посетителя. `api.php` эту проверку не применяет.
- **Только чтение.** Регистрация отклоняет любую возможность (ability), которая не является доступной только для чтения, недеструктивной и идемпотентной.
- **Применяются и видимость, и права доступа (realms).** Возможность должна быть открыта (exposed), а владелец токена должен обладать соответствующим правом доступа (realm). Если таблицу видимости не удаётся прочитать, все возможности скрываются, а не возвращаются к значениям по умолчанию.
- **Скрытые, неизвестные и запрещённые возможности выглядят одинаково.** Клиент не может отличить несуществующую возможность от скрытой или недоступной его пользователю: обнаружение (discovery) исключает её из списка, а выполнение возвращает `NOT_FOUND` (`ABILITY_NOT_FOUND`).
- **Токены.** Хранятся в виде хешей SHA-256, показываются один раз, всегда имеют срок действия, могут быть отозваны и отклоняются, если владелец отключён или теряет право доступа (realm).
- **Аудит.** Таблица `plugin_mcp_audit` записывает идентификатор запроса, идентификатор токена, идентификатор пользователя, возможность, результат (`started`, `succeeded`, `failed`, `denied`, `rejected`) и временные метки. Она никогда не сохраняет аргументы, результаты выполнения или значения токенов. Возможность выполняется только после записи строки `started`; если таблица аудита недоступна, вызов завершается с ошибкой `UNAVAILABLE` и не выполняется. Отклонённый до выполнения вызов записывается одной строкой: `denied` для неизвестной, скрытой или запрещённой возможности, `rejected` для аргументов, не прошедших проверку схемы. Создание и отзыв токенов из консоли, страницы «My MCP Tokens» и CLI записываются как `mcp-token-create` и `mcp-token-revoke` с результатом `succeeded`, причём отзыв фиксируется только для активного на тот момент токена. Обнаружение (discovery) и вызовы, в которых `arguments` не является JSON-объектом, не журналируются.
- **Журнал сбоев.** Непредвиденный сбой, `INVALID_RESULT` или недоступность таблицы аудита записывает одну строку в журнал Cacti с источником (facility) `MCP`: идентификатор возможности, фиксированную причину и класс исключения. Сообщения, аргументы и токены никогда не записываются в журнал.
- **Только главный поллер.** Обе конечные точки, обе страницы консоли и `tokens.php` отказываются работать где-либо ещё.

## Жизненный цикл

Отключение плагина блокирует обе конечные точки. Удаление плагина отзывает все токены и сохраняет три таблицы (`plugin_mcp_token`, `plugin_mcp_audit`, `plugin_mcp_ability`) для хранения истории; повторная установка не активирует отозванные токены. Делайте резервные копии этих таблиц вместе с базой данных Cacti и применяйте политику хранения записей аудита за пределами плагина.

## Разработка и тестирование

Тесты представляют собой обычные PHP-скрипты, которые выполняются без Cacti:

```console
for t in tests/*.php; do php "$t" || break; done
git archive --format=tar.gz --prefix=mcp/ HEAD > mcp.tar.gz
```

CI выполняет статическую проверку (lint) PHP и запускает скрипты из `tests/` (каждый из них перечислен в `.github/workflows/ci.yml`) на версиях PHP с 8.2 по 8.5, а затем собирает устанавливаемый архив `mcp/` и его контрольную сумму. Тесты, затрагивающие Cacti, используют фикстуры на границе вспомогательных функций Cacti и не проверяют полноценную установку Cacti.

### Интеграционные тесты

Команда `tests/integration/run.sh 1.2.31` или `tests/integration/run.sh develop` устанавливает плагин в реальный экземпляр Cacti в контейнерах и выполняет против него живые проверки. Для запуска требуются Docker с Compose версии 2.23.1 или новее, git и openssl. Переменная `KEEP=1` оставляет стек запущенным для отладки. CI запускает их еженощно и по запросу, но не при каждом pull request.

## Локализация

Cacti MCP поставляется со скомпилированными каталогами GNU gettext в `locales/po/` и `locales/LC_MESSAGES/`, а также с локализованными README-файлами в `docs/i18n/` для английского и ещё 44 локалей (19 основных локалей уровня Tier 1, 15 африканских и 10 азиатских локалей), используя текстовый домен `mcp` (`locales/po/mcp.pot`). Cacti загружает соответствующий каталог автоматически, когда включена поддержка языков.

## Участие в разработке

Pull request'ы направляются в ветку `develop`. Поддерживайте совместимость рабочего кода с PHP 8.2 и придерживайтесь стиля кода Cacti: табуляция для отступов, одинарные кавычки для строк и использование вспомогательных функций Cacti для работы с базой данных и правами доступа. Добавляйте тесты при изменении логики валидации, авторизации или протокола и подписывайте коммиты с помощью `git commit -s`. Изменения HTTP API согласовывайте с [cacti-mcp](https://github.com/somethingwithproof/cacti-mcp).
